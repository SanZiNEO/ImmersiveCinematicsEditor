## 一、摘要

本轮把只读图升级为项目入口：按文件夹分类，悬停摘要、点击打开；图本身维护文件夹归属、真实触发依赖和布局位置。删除旧最左常驻脚本/源码列。依赖维护是受限项目操作，不是把完整脚本编辑器搬到图上。

现状已有只读图（`MOD:webui/ScriptGraphService.java` + `ED:components/ScriptGraph.vue` + `ED:graphLayout.ts`），但**没有**文件夹维护、没有布局持久化、没有移动/重命名、没有引用事务，也没有删除常驻列表。本轮全部为计划，尚未实现。

## 二、为什么做

### 2.1 问题

- 脚本一多，作者只能靠左侧列表按文件名找；列表按路径字典序排，看不出故事线，也看不出谁依赖谁。
- 依赖只存在于脚本文件内部的 `meta.triggers[].requires`，必须逐个打开对照。
- 打开某个脚本要先在列表里按路径定位，再从列表点开，跳转成本高。
- 最左常驻一列脚本列表 + 一列 JSON 文本，占掉宽度，却不承担导航以外的工作；同一份导航能力在图上重复一遍会更糟。
- 脚本改名（`meta.id`）之后，其它脚本里的 `requires` 引用会静默悬空；现有图只能事后提示（`dangling`），不能事先改写。

### 2.2 目标

- 打开编辑器即看到整包脚本、文件夹分区与依赖方向，无需先打开任何文档。
- 悬停一个节点，能看到它是什么（名称/脚本 id/时长/轨道构成/触发器类型清单/前置依赖/维度/校验状态）。
- 点击节点进入该脚本文档；返回入口一次点击即可。
- 文件夹可新建/重命名/删除（空文件夹），脚本可在文件夹之间移动；移动不改变脚本身份。
- 脚本 id 重命名时，编辑器能列出全部受影响引用并在一次事务里改写。
- 图上可新增、删除或修改受支持的真实前置依赖；必须选择来源触发器/具体条目并确认，不自由捏造边。复杂未知关系只读保留。
- 作者手动摆过的位置重开不丢。

### 2.3 非目标

- 不做轨道/关键帧/片段编辑。图上不出现任何轨道控件。
- 不做拖线即自动写脚本；可选拖线只打开受控依赖表单。依赖唯一真源仍是标准脚本条件，04.11当轮完成写合同。
- 不做多人协作、版本对比、Git 集成。
- 不做运行时事实/触发状态可视化（服务端 `FactLedger` 不在编辑器进程，见 `../11-triggers-rules-events/07-continuity-and-facts.md`）。
- 不复制一套「脚本列表」到图视图侧栏；找脚本只有图这一个入口。

## 三、方案

**入口**：编辑器启动后的默认视图就是关系图（或上一次停留的视图）。顶部标题栏只有一个「视图」切换（关系图 / 文档），不再有独立的脚本列表面板。

**分区**：每个文件夹是一条横向泳道，带标题与外框；`scripts` 根目录排在最前。空文件夹也画出来（带「空」标记），否则作者无法把脚本拖进去。嵌套文件夹按路径展平为泳道，泳道标题显示完整相对路径。

**节点**：一个脚本一张卡片，显示名称、脚本 id（与文件名不同时两者都显示）、时长（无限显示 ∞）、轨道构成缩略。写坏的脚本仍然上图，标红并显示错误摘要。

**悬停**：浮层给出关键信息——名称/作者/维度/优先级、时长、每条轨道的类型与片段数、触发器类型清单（含 repeatable 标记）、前置依赖目标、图数据提示（悬空/自引用/重复 id）。浮层不提供编辑控件。

**点击**：单击选中并高亮上下游链（上游绿、下游蓝、其余压暗）；再次单击取消。双击（或浮层上的「打开」）进入文档视图并加载该脚本。

**文件夹维护**：分区标题上的菜单提供「新建子文件夹」「重命名」「删除（仅空）」。普通卡片拖动仅调整布局；卡片菜单「移动到…」或明确进入的文件移动手势才执行移动到目标泳道。移动只改文件路径，不改 `meta.id`，不能把拖动越过泳道边界当作隐式文件操作。

**重命名脚本 id**：在卡片菜单「重命名脚本 id」中执行。编辑器先扫描全包引用，列出将被改写的条目（哪个脚本、哪个触发器、哪种前置条件），确认后一次性写盘；任一文件写入失败则整体回滚并保留原文件。

**依赖边**：显示来源触发器/前置类型/目标，菜单提供受控新增、修改、移除及跳转文档。写操作见[04.11](11-GraphDependencyMutationController.md)，必须定位真实requires并校验回滚；不能只交只读跳转。

**布局**：自动布局（文件夹泳道 + 拓扑分层 + 环缩点）作为缺省；作者拖动节点后位置写入编辑器布局元数据，重开时优先使用保存的位置，缺失的节点回落到自动布局。

## 四、技术细节

### 4.1 核心模型

| 模型 | 承载 | 职责 |
|---|---|---|
| 项目索引 | 提案 `MOD:webui/ScriptIndexService.java` | 扫描 `scripts/`，给出路径、`meta.id`、文件夹、mtime、尺寸、可解析性；是图与引用事务的唯一事实源 |
| 图数据 | 现有 `MOD:webui/ScriptGraphService.java`（改造） | 由索引 + 解析结果组装 nodes/edges/folders/warnings |
| 文件夹 | 图数据内的分区 + 目录本身 | 分区是目录的投影；空文件夹由目录扫描补充，不由节点反推 |
| 依赖边 | `meta.triggers[].requires` 的投影 | 有向：被依赖脚本 → 依赖方脚本；边携带触发器类型与前置条件类型 |
| 布局文档 | 提案 `MOD:webui/GraphLayoutStore.java` + `ED:graphLayout.ts` | 位置/折叠/视图状态；编辑器元数据，不写回脚本 |
| 引用事务 | 提案 `MOD:webui/ScriptRefactorService.java` | 扫描并改写 `requires` 与组合器内 `script_*` 引用 |

### 4.2 契约

- 图数据由模组提供容错扫描；布局不改脚本。文件/身份重构与依赖维护则通过分别定义的受控写事务，不能前端直接写文件或只改图数据。
- 布局归编辑器；写入位置是 `immersive_cinematics/editor/graph-layout.json`（与 `scripts/` 平级、独立目录），不写进脚本文件。
- 节点身份分两层：**节点 id = 相对路径**（图内唯一、可重复性最好），**脚本身份 = `meta.id`**（依赖解析与播放注册的键）。布局记录两者，加载时先按路径、再按 id 匹配。
- 文件夹移动只改路径：不触碰 `meta.id`，因此不需要改写任何引用。
- 身份重命名需全包引用事务；依赖维护需精确条目级标准脚本事务。两者都要指纹检查、真实校验和失败恢复，不能混作一次拖动。
- 04图内依赖维护与11文档完整requires面板共用命令合同；04的基本维护不依赖11先完成。

### 4.3 数据形态

- `nodes[]`：`id`(路径) / `path` / `folder` / `scriptId` / `name` / `author` / `description` / `dimension` / `priority` / `duration` / `infinite` / `tracks[{type,clips}]` / `triggers[{type,repeatable,requires[]}]` / `requires[]` / `valid` / `error?`（现有形态，见 `MOD:webui/ScriptGraphService.java:367-390`）。
- `edges[]`：`from` / `to`（节点 id）+ `fromScript` / `toScript` / `trigger` / `requirement`（现有，`ScriptGraphService.java:108-140`）。
- `folders[]`：现为 `{path,count}`，由节点反推（`ScriptGraphService.java:142-158`）；本轮改为由目录扫描给出，增加 `empty` 与 `parent`。
- `warnings[]`：`kind` ∈ `dangling` / `self_reference` / `duplicate_id` / `invalid`，上限 200（`ScriptGraphService.java:41`、`:302-310`）。
- 布局文档：`{version, projectKey, nodes:{<path>:{x,y,scriptId}}, view:{scale,tx,ty}}`。

### 4.4 边界

- 图不读 `ScriptParser`（容错口径：写坏的脚本也要上图），因此图中「时长/轨道/触发器」是 JSON 直读结果，可能与运行时解析结果不同；差异只通过 `valid`/`error` 与校验诊断呈现，图不假装自己是权威。
- 图不碰时间轴、不碰片段属性、不碰规则。
- 布局元数据不参与播放，不进脚本文件，不进服务端。
- 引用事务不处理 `rules[]` / `rule_bindings[]`（它们只引用同脚本内的片段/绑定，不跨脚本）。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 保留常驻脚本列表 | 左栏列表 + 图并存 | 两套导航、两套选中状态、宽度被吃掉 | 导航只能有一个真源 |
| 拖拽即自动写依赖 | 无需选触发器/类型就写requires | 同一对脚本可有多条不同来源，自动猜测会改变含义 | 拖拽最多打开04.11受控表单 |
| 两个面板各自定义requires写规则 | 图与文档分别改原始JSON | 校验/身份/冲突规则分叉 | 共用同一标准文档命令和受控宿主写入口 |
| 布局存进脚本文件 | 节点写 `graph_x/graph_y` | 污染脚本格式、影响 diff、进服务端解析 | 布局是编辑器元数据 |
| 布局只存 localStorage | 浏览器本地 | 换机器/换入口丢失；Electron 与浏览器不一致 | 作者会跨入口使用 |
| 移动脚本时改写 `meta.id` 跟随路径 | 路径即身份 | 破坏「改 id = 换触发器身份」的事实语义（旧事实失效） | 身份必须稳定 |
| 重命名 id 时逐文件即时写 | 边扫边写 | 中途失败会留下半改状态 | 需要原子提交 |

**本方案的缺点**：

- 路径与 `meta.id` 双主键意味着两者都变时布局会丢一次（降级为自动布局），需要在 UI 上明确提示。
- 引用事务要读全包脚本，脚本数量大时（>200）会有一次可感知的停顿。
- 图只开放受控依赖维护；完整触发器/规则参数仍要进入文档，两个入口复用同一命令合同而非各写一份。
- 空文件夹必须画出来，会让图在早期显得稀疏。
