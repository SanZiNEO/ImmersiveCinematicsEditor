# 对象与节点诊断

> 状态：已实现（偏差见 §六）
> 范围：本地校验与服务端校验的结果如何落到行、节点与组头；诊断条；按面板归属的定位；必填缺失与未知路径
> 关联：06-02 行、06-06 烘焙提示、06-09 属性面板；校验合同见 03-06

## 一、摘要

校验结果只有在"能被点过去"时才有用。本文定义 issue 如何从校验层落到属性面板的行、效果面板的节点、以及两个面板的组头，并规定定位规则：静态问题去属性面板，动画问题去效果面板。必填字段缺失不再通过"添加属性"弹层处理，而是作为未设置行出现在属性面板里，等着被填。

## 二、为什么做

### 2.1 问题

校验最容易变成一份"错误列表"：作者看到三十条消息，不知道每一条对应哪个属性、哪个时刻，只能自己去翻。如果定位规则含糊，点一条动画节点的错误却被送到属性面板，作者会更困惑。另一个常见退化是把缺失必填字段做成弹窗，打断编辑流程，而且弹窗关掉之后问题依然存在。

### 2.2 目标

- 每条 issue 都能定位到具体的行或节点，定位后视野里立刻能看到它。
- 定位遵循归属：静态与缺失去属性面板，动画与节点去效果面板。
- 必填缺失在行内呈现并可聚焦，不用弹窗。
- 服务端超时或失败不被当成通过。
- 修复后 issue 自动消失，撤销后自动重现。

### 2.3 非目标

- 不在诊断条里直接修数据，诊断只负责呈现与定位。
- 不合并本地与服务端的不同代码，只合并同代码。
- 不为未知路径创建对象或补字段。
- 不在这一层处理缓动未烘焙提示（那属于 06-06，诊断条可并列显示但不合并级别）。

## 三、方案

每条 issue 有稳定身份、代码、级别、所属片段、可选对象路径、可选节点时间、消息、来源与目标面板。身份由代码加片段加路径加时间生成，重算不会重复。级别分四档：阻止、错误、警告、提示，样式上逐级减弱，但每处都带图标或文字说明，不只靠颜色区分。

issue 落在三个位置。行上：最高级别的边框或圆点，悬停给出消息摘要，点击打开诊断条。节点上：环形标记加 tooltip，多条时显示"还有若干条"。组头上：最高级别圆点加计数；组内行即使因为归属被隐藏到另一个面板，组头仍保留计数，折叠也不丢。

诊断条在属性面板与效果面板底部各有一条，可折叠。折叠时只显示最高级别与计数；展开后列出当前片段的 issue，默认只看当前片段，可切换成全局但定位仍按片段。每条给"定位"动作，没有 issue 时显示"无问题"，不摆一条空白栏。

定位规则是这套设计的核心。动画行或节点的问题：确保效果面板可见（若被抽屉收起先恢复），选择对应片段但不改变主时间轴的选择，展开组与行，若有节点时间则把局部播放头移到该时间并选中节点，最后滚动到位置并显示行内错误或 tooltip。静态、未设置或必填缺失的问题：确保属性面板可见，展开组并滚到行，未设置行聚焦值控件；若该问题同时关联效果面板（例如动画节点校验失败但属性面板也要给摘要），属性面板只显示摘要并给"在效果面板查看"的二次入口。定位不写文档、不新增选择、不展开主时间轴的对象行。片段键失效时说明原因并给撤销入口，不跳到相邻片段。

必填缺失的呈现是"行内可见、可聚焦、不打断"：属性面板对应行显示"必填未设置"与错误边框，定位只展开并聚焦，不自动创建对象；作者输入值后创建对象，issue 重算，若还有其他缺失则保留计数。必填缺失不进入效果面板，效果面板不显示该叶子。服务端与本地同代码的必填问题合并，保留服务端来源与消息。

未知路径分两种：没有关键帧的在属性面板未知组只读，issue 定位到属性面板；有关键帧的在效果面板未知组只读，issue 定位到效果面板。两种都不提供"删除字段"，只给复制路径与复制原始数据。模式或类型无法解析时行标未知，不猜控件。

服务端校验的边界：打开片段、保存、推送后调用 `script.validate`，结果写入状态而不写文档。服务端 issue 覆盖同代码的本地 issue，本地只保留未被覆盖的即时提示。阻止级阻止保存与推送，错误级阻止推送但允许本地保存草稿，警告与提示只显示。服务端返回未知路径时进未知组只读，不创建对象。服务端超时或失败时诊断条显示"服务端校验未完成"，本地 issue 仍然可见，绝不把超时当通过。保存前未烘焙缓动的提示由缓动模块负责，诊断条可以并列显示但不合并级别。

交互上，行内错误不阻挡其他行编辑：阻止级的行控件禁用，错误级的行可编辑但带提示；节点错误不阻止拖动其他节点，当前节点被阻止时禁止提交它的修改。修复后 issue 自动消失，不需要手动清除；撤销与重做后按文档修订号重算，不保留过期 issue。诊断条的展开状态属于会话，不写文档。

## 四、技术细节

### 4.1 核心模型

- 对象 issue：身份、代码、级别、片段键、可选路径、可选节点时间、消息、来源（本地/服务端）、目标面板、可选修复指向。
- 面板归属：由归属策略派生，不写死；动画行与节点归效果面板，静态、未设置与必填缺失归属性面板。
- 诊断条状态：是否展开、是否只看当前片段。

issue 只读，不携带可执行动作，只有"定位到哪里"的指向。

### 4.2 契约

- 本地校验在文档变化后即时产生；服务端校验在打开、保存、推送后触发，结果进状态服务。
- 同代码的服务端 issue 覆盖本地；不同代码并存。
- 同一路径的多个 issue 聚合到行，节点 issue 聚合到节点，组头取组内最高级别。
- 定位只改可见性、展开、滚动、播放头与选择，不改文档。

### 4.3 数据形态

级别决定样式与是否阻止操作，是唯一的语义分层。身份稳定性保证重算时不会重复插入或闪烁。修复指向只是"路径 + 可选时间"，因此撤销后重新计算仍能定位到同一位置。

issue 与行、节点不是一对一：一条行 issue 可能覆盖多个节点，一个节点可能有多条 issue。聚合方向是单向的——从 issue 聚合到行与节点，不反向存储。

### 4.4 边界

- 诊断不修改文档，也不创建对象。
- 诊断不改变 schema，不把未知字段变成已知。
- 诊断不合并不同代码的 issue，不吞掉本地即时提示。
- 诊断条不占文档高度，不参与序列化。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 只给一份错误列表 | 侧栏列出全部 issue 文本 | 无法定位；作者要自己找 | 落到行、节点、组头才可操作 |
| 全部定位到属性面板 | 所有 issue 都去属性面板 | 动画节点错误无处高亮 | 按归属分流 |
| 缺失必填用弹窗 | 选中片段就弹添加对话框 | 打断编辑；关掉后问题仍在 | 行内未设置 + 可聚焦 |
| 服务端超时视为通过 | 无结果就不报错 | 脏数据被发布 | 明确显示"未完成"，本地提示仍在 |

**本方案的缺点**：

- 两个面板各有一条诊断条，同一片段的问题要分两处看。
- 组头计数可能指向另一个面板里的行，点击只开诊断条而不跳转。
- 级别与样式强绑定，主题更换时需要重新核对对比度。

## 六、实现结果

状态：已实现

聚合在 `src/features/effects/diagnostics.ts`（`buildDiagnosticIndex` / `resolvePanel` /
`mergeServerIssues` / `withServerIncomplete`），诊断条是**一份**参数化组件
`src/features/effects/panels/DiagnosticsBar.vue`，`scope` 决定显示哪一侧。

| 原设计 | 实际实现 | 偏离原因 |
|---|---|---|
| 两个面板各一条诊断条 | 一份组件 + `scope` prop | 两份逻辑同源、只差 `scope` 与文案；参数化避免漂移 |
| 服务端超时显示"未完成"，绝不当通过 | `server_incomplete` 的 info 诊断 | 与设计一致 |
| 定位：动画行→效果面板，静态/缺失→属性面板 | `resolvePanel` 按行有无帧分流 | 与设计一致 |
| 定位后滚动到该行 | 属性面板按 `rowLayout` 定位；效果面板依赖浏览器默认滚动 | 效果面板缺精确 `scrollIntoView`（见 §九 已知局限 2） |
| 同代码服务端覆盖本地，不同代码并存 | `mergeServerIssues` | 与设计一致 |

### 验收要点

- 必填属性缺失时属性面板行显示必填未设置与错误边框，效果面板不出现该行，定位聚焦属性行。
- 输入值后创建对象、issue 消失，一次撤销恢复未设置与 issue。
- 服务端节点错误在效果面板显示节点环，诊断条列出，定位选中节点并移动播放头。
- 同一路径多条 issue 时行只显示最高级别，悬停列出全部，诊断条计数正确。
- 组折叠时组头仍保留 issue 标记，展开后行仍标记。
- 未知路径无帧时属性面板只读，定位不打开效果面板。
- 未知路径有帧时效果面板未知组只读，定位不打开属性面板。
- 服务端超时时诊断条显示未完成，本地警告仍显示，保存不被误判通过。
- 阻止级行控件禁用，其他行仍可编辑，保存按钮给出阻止原因。
- 撤销修复后 issue 重新出现，不需要刷新整页。
- 两个面板同时打开时，定位只改目标面板的展开与滚动，不关闭另一个面板。
