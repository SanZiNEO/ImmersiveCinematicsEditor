# 事件记录编辑

> 状态：已实现（偏差见 §六）
> 范围：EVENT / MOD_EVENT 叶子的记录列表、字段编辑、非空约束、白名单与类型校验、面板归属
> 关联：06-02 行、06-04 记录条、06-05 编辑操作、06-10 诊断

## 一、摘要

事件叶子不存"值随时间变化"，而存一条条记录：每条记录有时间和一个由 schema 描述的记录体。本文定义这些记录怎么创建、怎么编辑字段、为什么记录数组不能为空、以及记录从空到非空时事件叶子如何从属性面板迁入效果面板并永远留在那里。

## 二、为什么做

### 2.1 问题

把事件当成普通关键帧处理会立刻出问题：事件没有插值、没有段、不参与值采样，用菱形节点和段线表达会误导作者以为中间过程有过渡。另一个问题是非空约束：如果允许事件叶子存在零条记录，那么它在效果面板里就是一个没有记录条的空行，在属性面板里又显示"无记录"，两处都说不清这个属性到底存在不存在。

### 2.2 目标

- 事件记录在视觉上与值节点区分：区间事件是条，瞬时事件是竖菱形。
- 记录字段按 schema 渲染，必填、白名单、类型都在提交前拦截。
- 记录永远非空：删到只剩一条时拒绝，事件叶子始终留在效果面板。
- 记录体里的未知字段原样保留，不被 UI 顺手清理。

### 2.3 非目标

- 不做事件插值、不做事件段缓动。
- 不把事件记录混进普通关键帧的复制粘贴与框选。
- 不在效果面板提供"添加属性"式的事件创建入口（首条记录在属性面板创建）。
- 不删除 schema 不认识的记录字段。

## 三、方案

事件叶子的记录数组就是它的关键帧数组，但语义不同：每条记录有时间和记录体，没有插值、没有前后段。记录体按 schema 的字段声明渲染，字段可以是文本、数字、开关、枚举或引用；必填为空阻止提交，名称类字段若 schema 给了白名单则只接受白名单值。

面板归属上，事件叶子分两种状态。空记录时它只在属性面板，显示"暂无记录"和"添加首条记录"；点后者在播放头创建一条记录，记录体按 schema 默认或字段默认生成，若必填字段无法补齐则先打开编辑器让人填，不写半成品。有记录时它只在效果面板，属性面板改为显示"N 条记录"与"在效果面板编辑"的入口。EVENT 不允许空数组：删除最后一条记录被拒绝，因此事件叶子不会回到空态。

效果面板里事件行画记录条：区间事件是起止端点加横条，起点是记录时间，终点来自记录体里 schema 约定的字段；瞬时事件是竖菱形。记录条有最小宽度，零时长也看得见。点击记录条选中并打开编辑器；双击只打开编辑器，不新增记录。事件行没有段线，播放头只显示位置，不做节点命中样式。

编辑器顶部显示路径、事件名与记录数，字段按 schema 顺序排列，错误内联显示。未知字段折叠进"原始记录"只读区，不提供删除未知键的按钮。时间可以改，改时间走移动命令，与已有记录同刻冲突时拒绝。删除记录走删除命令，删最后一条被拒绝。复制记录会带一个小的相对偏移以避免同刻冲突，粘贴后打开新记录。

记录体的修改只替换 schema 声明的字段，未知键原样保留；类型不匹配拒绝，不做数字转字符串、布尔转零一这类隐式转换。同一字段短时间内的连续编辑合并为一个撤销项，切换记录或失焦结束合并。批量删除同路径原子提交，跨路径分批提交、任一失败整批回滚。

事件记录的校验分本地与服务端两层：本地给出即时提示（`event_requires_record`、`event_name_invalid`、`event_field_required`、`event_field_type`、`duplicate_time`、`negative_time`），服务端校验为权威，同代码时保留服务端来源与消息。行角标显示最高级别并可定位到诊断条。未知事件路径只读：不能添加记录、不能改字段、不能删除，只能复制原始 JSON。

## 四、技术细节

### 4.1 核心模型

- 事件记录：时间 + 记录体。记录体的字段集合由 schema 视图描述。
- 事件定义视图：路径、标签、事件种类（瞬时/区间）、字段定义列表、可选名称白名单、是否未知。
- 字段定义：键、标签、类型、是否必填、可选枚举值、是否只读。

事件行与动画行共用行模型，但模式为事件，节点组标记为有（因为要画记录条），插值为无。

### 4.2 契约

- 首条记录由属性面板发起，走新增记录命令；成功后事件叶子自动进入效果面板。
- 后续记录的增删改在效果面板内发起，仍走同一套命令。
- 记录不参与缓动、不写作者态数据、不进序列化的 UI 部分。
- 面板归属由"记录是否非空"决定；因为不允许空，事件叶子一旦有记录就永久留在效果面板，除非整条事件被移除。

### 4.3 数据形态

记录时间精度与关键帧一致，同路径同刻重复被拒绝。区间事件的终点从记录体字段读取，不由 UI 另存。记录体保持原始 JSON 形态：声明字段被编辑，未知键保留，序列化时顺序不重要但不做重排。

事件种类决定记录条形态，不决定数据形态：两种种类都只是"时间 + 记录体"。

### 4.4 边界

- 事件记录不进入普通关键帧剪贴板，反之亦然。
- 事件行不画段线、不参与段缓动、不参与值采样。
- 属性面板只负责空事件的首次记录入口与概览，不做字段编辑。
- 未知事件路径只读，且不因只读而从诊断中消失。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 事件当普通关键帧 | 用菱形节点 + 插值表达 | 误导作者以为有过渡；段线无意义 | 记录条语义更准确 |
| 允许空事件数组 | 删完记录后叶子留空 | 两个面板都说不清它存在与否 | 非空约束让状态唯一 |
| 事件记录自由 JSON | 不做字段声明，直接编辑原文 | 无校验、无必填、易写坏数据 | 按 schema 渲染字段，未知键仍保留 |
| 事件与关键帧共用剪贴板 | 统一复制粘贴 | 类型与语义冲突，粘过去没有意义 | 两套剪贴板各自清晰 |

**本方案的缺点**：

- 记录字段多的区间事件，编辑器较长，需要滚动。
- 非空约束意味着"清空这个事件"必须先移除整个动画对象，路径不够直接。
- 白名单只校验名称字段，其他字段的语义约束仍靠 schema。

## 六、实现结果

状态：已实现

记录体字段表与校验在 `src/features/effects/eventRecords.ts`，编辑器在 `EventRecordEditor.vue`。
非空约束由命令层拒绝（`object.removeKeyframe` / `removeKeyframes` 对 `mode=event` 抛错），
`object.disableAnimation` 也拒绝事件叶子。

| 原设计 | 实际实现 | 偏离原因 |
|---|---|---|
| 事件分瞬时/区间两种，区间事件画记录条 | **只有瞬时事件**（竖菱形） | **源码事实冲突**：`EventRecord` 只有 `time` + 记录体，无终点字段。`EventClipRuntime` 按单点触发 |
| 记录体字段按 schema 渲染 | 目录有 `FieldEntry` 时走 `checkValue`；缺失时按 `ObjectCodec.readEvent/readModEvent` 同口径白名单 | 与设计一致（不发明字段） |
| 未知字段折叠进"原始记录"只读区 | 已实现，无删除按钮 | 与设计一致 |
| 白名单校验名称字段 | 运行时只约束 `event_type` 为字符串；无枚举白名单 | 源码无该白名单，不凭空造 |

### 验收要点

- 属性面板空事件行点"添加首条记录"后播放头出现一条记录，事件行进入效果面板，一次撤销回到空态。
- 效果面板事件行显示记录条，点击打开编辑器，不显示菱形与段线。
- 名称改到白名单外被拒绝，原值保留。
- 必填字段清空阻止提交，记录体不变。
- 删除唯一记录被拒绝，事件行仍在效果面板。
- 添加第二条记录后出现两条记录条，同刻重复被拒绝。
- 把记录时间改到已有记录同刻被拒绝，不覆盖。
- 未知字段显示在原始记录只读区，保存后原样保留。
- 未知事件路径只读，没有添加入口，也不能删除。
- 上百条记录时记录条虚拟化，编辑器只渲染当前记录，滚动不卡死。
