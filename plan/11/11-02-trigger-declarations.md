# 触发器声明与身份

> 状态：未实现
> 范围：`meta.triggers` 的声明、身份规则、固定播放动作、列表摘要与脚本图悬停摘要
> 关联：11-04 条件树、11-05 前置、05 脚本图悬停

## 一、摘要

触发器是"整个脚本播不播"的服务端门控：`meta.triggers` 里每声明一条，游戏侧就多一个判断入口，命中后把本脚本播放给触发者本人。本文定义这些声明在行为页里怎么呈现、身份怎么算、为什么没有动作与目标选择器，以及 05 脚本图节点的悬停摘要如何显示全部触发器与全部条件。

## 二、为什么做

### 2.1 问题

`meta.triggers` 是数组，靠下标定位。作者在编辑器里看不到"这个脚本有几条触发器、各自什么类型、有没有前置没解析"，只能在 JSON 里数序号。更常见的是误解：以为触发器可以配动作、可以指定播放给谁。当前脚本格式里根本没有这些字段——解析后固定生成"把本脚本播放给触发者本人"，没有 `actions`，没有 `target`。编辑器若给一个动作下拉，作者写出的东西会被校验器拒绝。

身份问题同样隐蔽：不写 `id` 的触发器，运行时身份是"类型 + 声明下标"。一旦有人调整数组顺序，去重身份就变了，之前触发过的记录对不上新身份，触发器会二次触发。

### 2.2 目标

- 作者能一眼看出当前脚本有几条触发器、各是什么类型、条件与前置各有几条、最高问题级别是什么。
- 身份可见：有显式 `id` 就显示 id，没有就显示生成身份并标明它会随下标变化。
- "触发后做什么"以只读卡呈现，不给任何可编辑入口。
- 脚本图节点悬停能看到全部触发器、全部条件树与全部前置，不截断、不只显示前几条。

### 2.3 非目标

- 不新增触发器类型、动作数组、目标字段或 `all/all_except_trigger` 之类的分发模式。
- 不显示运行态"已触发 / 未触发"。
- 不新建脚本图页，不改 05 的节点、边、布局与图数据契约。
- 不定义条件字段与前置语义（分别见 11-04、11-05）。

## 三、方案

列表按声明顺序排列，不按片段、不按中文分类重排。每行固定给出：类型、身份（显式 id 或生成身份）、可重复或单次、条件叶子数、前置条数、最高问题级别。条件数只数叶子，不把组合器算进去；有 `delay` 加延迟徽标，有 `continuity` 加连续徽标。

身份规则只有两条：写了 `id` 就用 `id`，必须匹配字母数字下划线、1 到 64 位、脚本内唯一；没写就用"类型 + 声明下标"，界面明确标注"身份随声明下标"。改 `id` 会改变非重复触发器的去重身份，应用前提示"已触发记录不会迁移"。触发器排序会改数组下标，因此只要存在无 `id` 的触发器，排序前必须二次确认。重复 `id` 直接阻止保存与推送。

详情分四段：身份、触发后、条件与前置、诊断。身份区给 `id` 输入与类型下拉，下拉按代码顺序列全 27 种、可搜索、不按中文分组重排。切换类型时不静默丢旧条件：不适用于新类型的键进"旧字段"只读块，作者可以确认"清理不适用字段"或继续保留，但应用时必须通过新类型的校验。

"触发后"是一张只读卡，写明"播放本脚本给触发者本人"。不提供动作选择器、目标选择器、可编辑的 `play_script` 对象——这是当前脚本格式的固定行为，不是本轮的可配置项。

条件和前置在详情里是两个独立区域，`requires` 不能被渲染成 `conditions` 的子节点。诊断区列出：未知类型、重复 `id`、条件与前置都为空（info：只靠事件或轮询类型本身触发）、条件字段不适用、前置缺失或自引用或自定义只读、时序字段不适用。

脚本图悬停卡接在 05 的节点卡里，不新开图页。节点卡本身仍用 `script.graph` 的摘要；悬停片刻后按需通过现有只读通道读当前脚本的 `meta.triggers`，缓存摘要，按"路径 + 文件版本"失效，`script.graph.invalidated` 后丢弃。这是纯只读：不进入文档页、不建脏文档、不触发未保存保护。读取失败时退回节点已有摘要，条件区写"读取失败，条件暂不可用"，不编默认条件。

悬停内容要求：全部触发器都列出，每个都展开完整条件树，`all_of` 显示"全部满足"、`any` 显示"任一满足"，递归缩进；叶子条件用与 11-04 同一套中文摘要；每个触发器下面挂它的全部 `requires`，显示"类型 → 目标脚本"与解析状态（已解析、缺失、自引用、重复 id、自定义前置只读）。没有条件写"无场景条件"，没有前置写"无前置"，未知条件类型显示原文只读。内容多时卡片内部滚动，绝不折叠成"+N"，卡片里不出现输入框、下拉或删除按钮。

卡片底部提供两个入口：先在卡内选中一条触发器，再"定位到触发器"——打开脚本、切到文档页、行为页选中该触发器，不自动播放也不 seek；"打开脚本"沿用 05 既有的打开流程。

## 四、技术细节

### 4.1 核心模型

一条触发器由类型、可选显式身份、条件对象、前置列表、若干时序字段构成。类型决定条件对象的合法结构，也决定哪些时序字段可用。身份是"显式 id 优先，否则由类型与声明下标推导"的派生值，不存盘。

### 4.2 契约

- 列表与详情只消费 `meta.triggers`，不消费运行时状态。
- 悬停摘要的读取走既有只读脚本通道，与 05 的节点摘要互不依赖：读不到时节点摘要照常显示。
- 缓存键含文件版本或刷新版本，脚本图失效事件到达即丢弃缓存。
- 类型下拉的顺序与字段目录一致，界面不另立一份顺序表。

### 4.3 数据形态

`requires` 支持字符串与对象两种元素形态；字符串只可能是 `script_played` 的简写。条件对象的形状随类型变化，组合器用 `list` 承载子项。生成身份不写入文件——它只是"没写 `id` 时运行时会算出来的那个值"。

### 4.4 边界

- 编辑器不判断某条触发器在某个玩家身上是否成立。
- 编辑器不解释类型的判定细节，只保证字段合法。
- 悬停卡不做编辑，不提供"在这里改条件"。
- 诊断模式可以额外显示声明下标、条件叶子数、`requires` 下标，但不改变卡片布局，也不把内部细节铺到普通视图。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 给触发器配动作与目标 | 详情里加动作下拉与"播放给谁" | 写出的字段会被校验器拒绝；作者以为能力存在 | 当前脚本格式固定为"播放本脚本给触发者本人" |
| 身份全部自动生成 | 忽略显式 `id`，一律用下标 | 排序即改身份，已触发记录错位 | 显式 `id` 是稳定身份的唯一手段 |
| 悬停只显示数量 | 卡片写"3 个触发器" | 作者要逐个点进去才知道条件 | 悬停的价值就是"不用打开就能读全" |
| 悬停折叠长内容 | 超过 N 条折叠 | 跨脚本前置恰好是最容易漏看的部分 | 宁可内部滚动，不截断 |

**本方案的缺点**：

- 全部条件树展开后卡片很长，作者需要滚动才能读完，尤其是多层组合器。
- 类型切换时保留旧字段会让 JSON 里暂时存在不适用于当前类型的键，作者需要主动清理。
- 无 `id` 触发器的排序多一步确认。

### 验收要点

- 新建触发器默认 `login` 并生成可读 id；清空 id 后列表显示生成身份。
- 27 种类型都在下拉里，顺序与代码一致，不按中文分组重排。
- 两条触发器同 id：都标重复，应用被阻止。
- 详情里找不到动作或目标下拉，只有只读的"播放本脚本给触发者本人"。
- 改变类型后旧条件进只读块，出现清理入口，不静默丢失。
- 列表行给出类型、身份、可重复、条件数、前置数、最高问题级别。
- 悬停卡列出全部触发器，每个带完整条件树与全部前置，无截断。
- 嵌套组合器的缩进与叶子摘要可读，`all_of` 与 `any` 文案正确。
- 前置的缺失、自引用、自定义只读分别标注，不画假边。
- 读取脚本失败时悬停仍显示节点摘要，条件区写明读取失败。
- 点"定位到触发器"打开脚本并选中该触发器，不播放。
- 检查：05 图数据契约未新增字段，没有新增消息或脚本字段。
