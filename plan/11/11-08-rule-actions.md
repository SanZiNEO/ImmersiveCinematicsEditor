# 规则动作

> 状态：未实现
> 范围：`rules[].actions` 与 `policy.on_timeout` 的九种动作、各自字段约束、与触发器动作的分离
> 关联：11-06 规则定义、11-10 执行与出口、09/10 的片段字段

## 一、摘要

规则动作固定为九种：`camera_set`、`overlay_set`、`adjust_set`、`goto_clip`、`pause`、`resume`、`exit`、`play_sound`、`emit_command`。它们全部作用于"触发这条规则的播放实例"，没有动作级目标选择器。本文定义每种动作能写什么、不能写什么，以及为什么它们不写回片段字段。

## 二、为什么做

### 2.1 问题

九种动作的名字容易让人联想成"轨道操作"：`camera_set` 被当成改相机轨关键帧，`overlay_set` 被当成加 `OVERLAY` 轨的淡入关键帧，`adjust_set` 被当成往 `ADJUST` 轨写调色。实际上它们是运行时临时工件，作用到当前播放实例的覆盖链上，不落盘到轨道数据。作者若按"轨道操作"的直觉去用，会发现播完什么都没留下，于是反复加动作试图"保存效果"。

另一类问题是边界越界：`hold` 被当成第十种动作（其实是绑定的控制方式，无限等待由 `timeout=-1` 表达）；`emit_command` 被放进超时动作（服务端命令表只编译普通动作，超时里的命令解析不到）；`goto_clip` 写成旧形态的轨道加时间。

### 2.2 目标

- 九种动作全部可编辑，`hold` 不可选并给出替代说法。
- 每种动作的必填、范围、互斥关系在字段旁可见。
- 动作与轨道数据、与触发器动作彻底分开，不出现第二套字段面。
- 三类"退出/跳转"的区别在界面上一直可见。

### 2.3 非目标

- 不新增动作类型，不提供动作级目标或轨道选择器。
- 不做"试执行"或实时预览，不连服务端命令表。
- 不把片段字段（`OVERLAY`、`ADJUST` 等）搬进行为页。

## 三、方案

动作列表至少一条，顺序即执行顺序，可上下移动。超时动作可以为空。所有动作的作用对象恒为触发实例，详情顶部写明这一点，没有"对谁执行"的选项。

**`camera_set`** 在覆盖链上叠加一条临时相机修改。六个通道：位置、yaw、pitch、roll、fov、zoom；位置整体算一位，三轴一起写。`channels` 非空不重复；选中哪个通道就必须给哪个通道的值；写了值但没进 `channels` 会报错——该通道不生效。合成模式可省，缺省按通道区分：位置与三个角度用加法，fov 与 zoom 用乘法，替换必须显式写；写了模式就统一作用于本次所有选中通道。优先级是整数，升序应用，缺省 0。工件持续到该动作作用域片段的活跃窗末，不是永久全局相机，也不写 `CAMERA` 轨。

**`overlay_set`** 建一层临时淡入覆盖层，归属当前实例，持续到片段结束移除。层类型当前只有 `fade`，不列 image 与 subtitle。颜色是六位十六进制，缺省黑；不透明度 0 到 1；`z_index` 是整数，缺省 10，越小越先绘制。这个 z 只在该覆盖层管线内排序，不与相机画面做全局合成表。它不是 `OVERLAY` 轨的关键帧。

**`adjust_set`** 写一层调色：十五个基础校色通道（曝光、对比、高光、阴影、白色、黑色、色相、饱和度、自然饱和度、亮度、色温、色调、红、绿、蓝），至少一个。未写的通道按不改变画面处理，界面用"启用"勾选决定写不写键，不把未启用通道写成 0。它不认 59 通道的 `ADJUST` 全集，不认曲线、LUT、混合模式与层级。名字和界面都用"调色层"，不叫画面合成。

**`goto_clip`** 在规则成立时开一条新分支，目标由片段 id 与入口局部时间指定。它不是片段内跳转，也不是调用栈；旧形态的轨道加时间字段一律不接受。目标片段必须存在；已在分支中或目标不可达时启动被拒绝，动作跳过而不中断播放。新分支的出口覆盖取触发这条动作的绑定的 `exit`，绑定没有 `exit` 时用片段默认。

**`pause` / `resume`** 都没有参数，出现其他键报错。前者给当前实例加一个暂停持有，后者释放该持有。它们走实例挂起账本，不冻结脚本字段也不暂停编辑器，允许跨规则配对，编辑器不强制在同一规则里成对出现。

**`exit`** 声明式结束当前播放实例，没有目标、没有退出类型选择、没有跳转参数。它不是绑定 `exit` 的替代——后者是分支完成后的出口策略。文案用"结束当前播放实例（渐出）"，不写"立即消失"。

**`play_sound`** 在本实例一次性发声，作用对象是触发者本人。音效 id 必填，音量与音高可省、缺省 1，都是有限数字。不改 `AUDIO` 轨，不建循环；未知音效 id 在运行期跳过，编辑器可提示"未在注册表确认"但不阻止保存；不填文件路径或资源 URL。

**`emit_command`** 让服务端执行命令。命令原文必填、不能空白、不带前导斜杠，多条用 `&&` 分隔。客户端只发动作引用（绑定 id 加动作下标），命令原文由服务端按脚本命令表解析，命令表只存服务端内存。只有该播放实例的观看者可触发，服务端按权限等级执行。`&&` 分段不在编辑器拆分，整串交给服务端。超时动作里禁用这个动作：服务端命令表只编译普通动作，超时里的命令没有表项。动作移动后序号变化，服务端动作下标随之变化，保存后重新编译。

三处"退出/跳转"的区别在 `goto_clip` 与绑定详情里固定显示：动作 `goto_clip` 是规则成立时立刻开新分支；绑定 `exit.goto` 是分支完成后的去向；动作 `exit` 是结束当前播放实例。

动作详情通用规则：类型只能从九种选，未知类型只读报错；旧字段与未登记字段进只读块，不静默删除；每行显示序号，移动后序号更新；不提供"实时预览"或"试执行"。

## 四、技术细节

### 4.1 核心模型

每个动作是"类型 + 该类型字段"的对象。动作列表是一个有序数组，序号既是执行顺序也是服务端动作身份的一部分。超时动作是同一套动作对象的另一个数组。

### 4.2 契约

- 动作不引用轨道，也不写关键帧；所有画面类动作都是运行时临时工件。
- 动作字段约束由字段目录给出，界面不另存一份。
- 动作的执行结果不可在编辑器内观测，因此界面不承诺"成功"。

### 4.3 数据形态

`camera_set` 的通道声明与通道值是两处数据，必须对齐；`overlay_set` 的颜色与不透明度是独立可选字段；`adjust_set` 的键即通道名；`goto_clip` 只有目标与入口时间；三个无参动作只有一个类型键；`play_sound` 三个字段；`emit_command` 一个字符串。

### 4.4 边界

- 动作不改变片段字段，也不产生可回放的数据。
- 动作不指定目标玩家，作用域恒为触发实例。
- `emit_command` 的信任边界在服务端，编辑器只保证格式。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 把 `hold` 当动作 | 动作列表里加"持有" | 格式里没有这个动作；等待上限在策略里 | 无限等待由 `timeout=-1` 表达，控制方式归绑定 |
| 动作写回轨道 | `camera_set` 生成相机关键帧 | 播完留下数据，语义从"运行时"变成"持久" | 动作是临时工件，不该改片段 |
| `overlay_set` 支持多层类型 | 加 image、subtitle | 格式当前只有 fade，其他会被拒绝 | 只列真实支持的类型 |
| `emit_command` 提供目标选择 | 选"对谁执行" | 服务端只按观看者集合执行 | 目标由播放实例决定，不可配 |

**本方案的缺点**：

- 九种动作字段差异大，详情区无法统一成一张表。
- 画面类动作是临时的，作者想"保存效果"时必须改用片段字段，需要理解两条路径。
- `emit_command` 的下标随位置变化，移动动作会影响服务端编译结果。

### 验收要点

- 动作列表能加九种，找不到 `hold`。
- `camera_set` 选位置与 yaw：必须填三轴与 yaw；填未选通道的值报"该通道不生效"。
- `camera_set` 不写模式：显示"逐通道缺省"；写替换则明确覆盖。
- `camera_set` 说明"持续到片段活跃窗末"，不写"永久"。
- `overlay_set` 只有 fade，颜色、透明度、z 值可编辑，不出现 image 或 subtitle。
- `overlay_set` 的 z 说明只在该覆盖层管线内排序，不画全局合成表。
- `adjust_set` 只列十五个通道，不出现 59 通道、曲线、LUT。
- `adjust_set` 只写类型：报"至少一个通道"。
- `goto_clip` 用片段 id 加入口时间；旧轨道/时间字段报错；详情显示三种跳转的区别。
- `pause`、`resume`、`exit` 没有参数输入。
- `play_sound` 三个字段可编辑，不出现文件路径。
- `emit_command` 空白报错、前导斜杠警告、`&&` 原样保留。
- `emit_command` 放进超时动作：block，提示命令表不编译超时动作。
- 动作移动后序号更新，命令动作的下标随之变化。
- 保存重开：九种动作的字段、顺序、旧字段只读块原样恢复。
