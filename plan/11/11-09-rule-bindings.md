# 规则绑定

> 状态：已实现
> 范围：`rule_bindings[]` 的字段面、时间门、控制方式、五种调度、五种出口覆盖与引用保护
> 关联：11-06 规则定义、11-08 动作、11-10 执行与出口、11-07 的 `rule_fact`

## 一、摘要

绑定是"规则 × 片段"的入口：同一条规则定义可以被多条绑定复用，每条绑定有自己的时间门、控制方式、动作调度和出口覆盖，彼此独立运行。本文定义这四组字段的语义与约束，并说明为什么绑定 `exit` 不是"本绑定片段完成时的出口"。

## 二、为什么做

### 2.1 问题

规则定义不指向片段，绑定才指向片段，这个两层结构最容易被压平：作者以为改规则的时间就会改所有片段的行为，实际每条绑定各有自己的 `gate.at`。反过来，如果按片段复制规则定义，同一条规则在多个片段里就会变成多份定义，改一处忘一处。

`gate.at` 的单位是目标片段执行内部的局部秒，不是全局时间轴时间——这一点若不说清，作者会按主时间轴上的位置填，导致规则在错误的时刻判定。

最隐蔽的是绑定 `exit`：它看起来像"本绑定片段播完后的出口"，实际是"本绑定的动作 `goto_clip` 启动的那条分支，完成后的出口"。它不在本绑定自己的片段完成时生效，也不作用于 `goto` 链的下一跳。绑定没有 `goto_clip` 动作时，这个字段合法但不会被使用。

### 2.2 目标

- 每条绑定的四个维度（门、控制、调度、出口）独立可见、独立可编辑。
- 时间门的合法范围按目标片段时长给出，越界明确报错而不是夹取。
- 调度的依赖关系可见，成环能指出环。
- 三种"退出/跳转"的区别在详情里始终可见。

### 2.3 非目标

- 不在绑定里写条件或动作（属于规则定义）。
- 不新增绑定字段、不新增调度形态或出口类型。
- 不提供"拖动时间轴自动建绑定"的路径。
- 不预测某条绑定会被触发几次。

## 三、方案

绑定有四个必填键（id、规则、片段、时间门）和三个可省键（控制、调度、出口）。id 字符集与规则 id、片段 id 相同，脚本内唯一；规则与片段必须命中当前脚本内已存在的对象；未知键报错，尤其不接受 `condition` 与 `actions`。

**时间门**只有 `at` 一个键，有限数字、不小于 0，单位是目标片段执行内部的局部秒。有限片段要求 `at` 不超过片段时长；无限片段没有上界。条件只在"片段已开始且局部时间达到 `at`"之后参与，门之前既不判条件也不持有。片段时长变短导致越界时报错，不静默夹到时长。拖动时间轴改门时只写 `at`，不移动片段。

**控制方式**二选一，缺省"观察"：观察是非阻塞的，门后条件不成立也继续播放，成立才提交动作；持有会在门后条件未成立时挂起实例，直到条件成立、超时、门失效或执行切换。持有不是动作，不放在动作数组里；等待上限由规则的 `timeout` 表达，`-1` 是无限等待。详情里显示当前方式，持有时额外显示"无限等待"或"超时 N 秒"。

**调度**可省，省略表示判定成功后立即提交动作。五种形态：

- 片段开始：目标片段下一次执行开始时提交。
- 片段完成：目标片段执行完成时提交。
- 局部时间：目标片段执行到达指定局部时间时提交。
- 真实延迟：判定成功后经过真实秒数提交，挂起不冻结。
- 事实：另一条绑定的最近一次激活事实成立时提交。

前三种的目标片段可以是绑定自己的目标片段，也可以是别的片段，但必须已存在。局部时间的 `at` 不小于 0，不夹取。延迟按真实秒数而非片段本地时间。事实调度的绑定 id 允许前向引用，但成环报错；事实名只能是 `succeeded` 或 `action_completed`，与条件树里的事实叶子同一套词汇。调度只影响动作提交时点，不改变规则成功判定——成功事实在条件成立时就记录。

依赖关系在详情里以链路形式显示（如 b1 → b2 → b3），成环时标出环并报错。条件树里的 `rule_fact` 也会形成等待关系，但解析器只对调度做循环检测，因此编辑器对条件引用只给警告，不冒充解析器报错。

**出口覆盖**五种：`continue` 结束当前分支回主线、`goto` 转到目标片段、`return` 结束当前分支回主线、`end_execution` 结束当前执行、`end_script` 结束整个脚本。出口类型必填；只有 `goto` 允许目标片段与入口时间，其他类型带这两个键报错。目标片段必须存在，入口时间不小于 0、缺省 0。省略出口等于用片段默认出口，不写"继承"对象。

绑定 `exit` 的归属必须说清：它是入口出口覆盖，只在本绑定的动作 `goto_clip` 启动分支时作为该分支的出口策略；它不在本绑定自己的片段完成时自动生效，主线片段完成走片段默认出口；它不作用于 `goto` 链的下一跳，下一跳用目标片段自身默认出口。绑定没有 `goto_clip` 动作时，详情显示"未被本绑定 goto 使用"。

详情分区：身份、时间门、控制、调度、出口、运行摘要、诊断。身份区可重命名 id，重命名是事务性的：所有 `schedule.fact.binding` 与条件树里的 `rule_fact.binding` 一起更新，任一处无法重写则整体不应用。被引用时删除默认禁用并列出引用位置（调度、条件树）。目标片段被删除时绑定红框"片段不存在"，不能应用；规则 id 的增删改由 11-06 的事务处理，本页只读展示。

列表里绑定挂在规则下面，同时可在片段详情看到"该片段的绑定"。行内容给出 id、规则、片段与时间门、控制方式、调度与出口。同一规则的多条绑定按声明顺序分别显示，不合并。

## 四、技术细节

### 4.1 核心模型

绑定是规则定义到片段的一次实例化，携带四个运行参数：从何时开始判定、判定期间是否阻塞播放、动作何时提交、分支完成后去哪。四者互不影响，各自独立配置。

### 4.2 契约

- 绑定的规则与片段引用必须在同一份文档内解析成功。
- 时间门的合法范围由目标片段时长决定，文档变化后需重算。
- 调度的事实引用与条件树的事实引用共用词汇表，但循环检测范围不同。

### 4.3 数据形态

时间门是只有一个键的对象；控制方式是枚举；调度是"形态 + 该形态参数"的对象；出口是"类型 + 可选的 goto 参数"的对象。四个都可省（除时间门），省略即缺省语义，不写占位对象。

### 4.4 边界

- 绑定不解释规则条件的求值细节。
- 不显示运行时状态：是否已持有、是否已提交、是否已超时。
- 不在绑定层改动作内容。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 规则定义直接带片段 | 取消绑定层 | 一条规则无法复用到多个片段，也无法给不同片段不同门 | 复用与差异化入口都靠绑定 |
| 时间门用全局时间 | `at` 填主时间轴秒 | 片段被移动后语义全变 | 门是片段执行内部的局部秒 |
| 绑定 `exit` 当片段完成出口 | 本片段播完就按它走 | 与运行时相反，主线片段完成不读绑定出口 | 它是 goto 分支的入口覆盖 |
| 调度省略时也给占位对象 | 写"立即"对象 | 无意义字段进入脚本，diff 噪声 | 省略即缺省，不写占位 |

**本方案的缺点**：

- 四个维度都挂在绑定上，详情区信息密度高。
- 时间门的合法性依赖片段时长，改片段会连带报错，作者需要回头修绑定。
- 绑定 `exit` 的归属需要反复解释，一句话说不清。

### 验收要点

- 绑定指向片段与门 0：列表显示"片段 @0s"。
- 有限片段门超过时长：红框越界，不自动夹到时长。
- 无限片段门写大数：允许，显示"无上界"。
- 控制省略：显示观察；持有显示"门后未成立才持有"。
- 调度省略：显示"立即提交"。
- 前三种调度的目标片段可以是别的片段；未知片段报错。
- 真实延迟标注"按真实秒，挂起不冻结"，负数报错。
- 事实调度前向引用允许；A 等 B 且 B 等 A 时显示循环依赖并 block。
- 出口省略：显示"继承片段"，不写空对象。
- `goto` 显示目标与入口时间；其他类型带目标报错。
- 重命名绑定 id：调度引用与条件引用同步更新，一处失败整体不应用。
- 删除被调度或条件引用的绑定：禁用并列出引用。
- 同一规则两条绑定：两条独立显示，各自的四组参数互不影响。
- 绑定详情与片段详情对同一绑定的说法一致。
