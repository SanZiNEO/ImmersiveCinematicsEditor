# EVENT 事件记录

> 状态：未实现
> 范围：`objects.event` 的离散记录、命令与位置字段、时间与触发语义、列表与摘要
> 关联：11-14 事件标记与 seek、11-15 校验、02/06 的对象结构

## 一、摘要

`EVENT` 轨的对象不是采样曲线，是离散事件记录：每条记录有片段局部时间、可选命令、可选移动目标。服务端按记录触发命令，客户端按带位置的记录组成玩家移动路径。编辑器只写记录，不执行命令、不驱动移动，也不建第二时间轴。

## 二、为什么做

### 2.1 问题

事件对象挂在轨道对象结构里，形态与关键帧相同（时间 + 值），因此最容易被当成"可以插值的曲线"来渲染：作者看到一排点，以为中间过程会被平滑处理，实际每条记录只在跨过它的那一刻触发一次，没有插值、没有中间状态。

字段语义也容易走偏。空 `command` 不是"没填"，而是合法占位——表示"这个时间点确实发生了事件，但不执行命令"。`event_type` 不是可扩展枚举，当前只接受一个值。`position` 只有水平两轴，且绝对与相对两种写法不能混；相对坐标的基准是脚本激活位置，不是片段起点。`id` 不参与运行时身份，运行时身份是"播放实例 + 片段 + 对象路径 + 事件下标"。

时间冲突的处理也不直观：格式不允许两条记录同一时刻，所以"同一时刻多条命令"必须合并成一条并用 `&&` 分隔，而不是拆成多条。

### 2.2 目标

- 每条记录的时间、命令、位置、占位状态一眼可见，不需要展开原文。
- 空命令、前导斜杠、超出时长这些情况有明确标注，不静默通过。
- 移动目标的两种写法互斥且各自字段清晰，不足两个航点时说明不会驱动移动。
- 触发与去重语义说清，作者不会期待"循环重播"。

### 2.3 非目标

- 不把事件渲染成曲线、不做插值。
- 不新建第二条事件轨，也不建第二时间轴。
- 不执行命令、不驱动玩家移动、不显示"已触发"。
- 不把 `data` 塞进事件记录（那是另一类记录的事）。

## 三、方案

事件对象必须有关键帧数组，每帧有时间与值；时间非负有限且严格递增。一个片段只能有一个事件对象；出现多条 `EVENT` 轨时只给"建议最多一条"的警告，不是硬错误，编辑器也不主动新建第二条。时间是片段局部秒，全局时间等于片段起点加局部时间。超出片段时长的记录在运行时编译期被丢弃，编辑器对新建记录限制在时长内，对旧记录标"超出时长，运行时丢弃"。

记录字段四个，都可省：

- 命令：原文，空串表示占位——已触发但不执行，界面写"占位：已触发，不执行"，不当作删除。命令不带前导斜杠，多条用 `&&` 分隔，服务端逐段执行，单段失败不影响后续段。
- 事件类型：当前只接受一个值，缺省取对象级，再缺省按命令类型。它不是扩展点，写其他值报错。
- 移动目标：绝对（世界 x/z）或相对（相对脚本激活位置的 dx/dz），必须恰好两个键，两套混写、缺一个、多键都报错。只有水平轴，纵向由玩家物理决定。
- 记录 id：运行时忽略，编辑器可作稳定键，保留原值不自动生成，也不要用它做去重。

未知成员直接拒绝，不能塞任意键。

多条带位置的记录构成折线航点，按全局时间排序，相邻两点直线行走；不足两个目标不驱动移动。相对坐标基准是脚本激活位置（触发点），不是片段起点。被方块挡住会停在挡住处；播完或停止停在最后目标；宏观循环回到起点会复位航点索引，但不清目标表。移动是客户端行为，命令是服务端行为，同一条记录可以两者都有。

触发语义：首次推进从负无穷开始，时间为 0 的记录在第一次推进时触发；触发区间是"上次推进到的局部时间"到"本次局部时间"的左开右闭区间，每条最多触发一次。片段循环、宏观循环、多入口都不重放服务端事件。乒乓模式在事件轨上被拒绝——事件没有反向时间语义。显式 seek 前跳不补触发，后跳回退可重新触发目标之后的事件，目标及更早的不补。片段循环回到 0 不会重新触发已触发的记录；要重新触发必须显式 seek 或新实例。命令按观看者集合执行，空命令只标记已触发。

行为页的事件详情按片段列出记录，每条显示时间、命令摘要或移动目标、占位标记。编辑项：时间（秒，片段局部，附全局换算）、命令（多行文本，空为占位，提示 `&&`，前导斜杠警告）、移动目标（无 / 绝对 / 相对三选一，只显示两个输入）、事件类型（只读展示当前唯一合法值，不给扩展下拉）、记录 id（可选高级字段，保留原值）。记录可删除、复制、上下移动；复制保留时间与字段，需手动改时间避免相同；排序按时间升序，插入时自动找空位或提示。时间超出片段时长时阻止新建，旧记录红框标注。

删除有一条硬约束：片段里唯一的那条记录不能被删，界面拒绝并说明原因。事件对象必须始终有记录，否则"这个片段有事件"这件事本身就没有载体了；要让片段不再有事件，得删除整个事件对象，而不是清空它的记录。

时间冲突时给提示"同一时刻多条命令请用 `&&` 合并"，不自动拆成多条。

时间轴只放事件标记，位置是片段起点加局部时间，标记不展开命令正文。点击标记选中行为页对应记录，不自动 seek 也不播放。标记不新增第二时间轴，不改时间轴数据契约；记录多时列表内部滚动，标记可重叠、悬停显示摘要。

摘要格式：纯命令写"时间 · 命令 …"；纯移动写"时间 · 移动到 …"；两者都有则并列；占位写"时间 · 占位"；超时长写"时间 · 超出时长（运行时丢弃）"；前导斜杠加警告标记。

## 四、技术细节

### 4.1 核心模型

一条事件记录是"局部时间 + 记录值"的离散点。记录值里的命令与位置互相独立，可以只有其一、可以都有、也可以都没有（此时是纯占位）。记录集合是片段内的有序列表，顺序即触发顺序。

### 4.2 契约

- 对象路径固定，对象类型与模式必须匹配，否则是结构错误。
- 时间是片段局部秒，编辑器负责显示全局换算，但不把全局时间写回文件。
- 位置字段的两套键互斥，校验层拒绝混写，运行时的宽容处理不作为编辑器依据。

### 4.3 数据形态

命令是字符串，空串合法；位置是两键对象；记录 id 是可选的字符串；事件类型是单值字符串。四条记录字段之外一律视为未知成员。

### 4.4 边界

- 编辑器不判断某条记录在某个玩家身上是否已触发。
- 不解释命令的服务端执行结果，也不显示成功或失败。
- 不把事件当转场，也不与片段间的转场混用。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 按曲线渲染 | 事件点之间插值画线 | 记录是离散触发，插值制造不存在的中间态 | 离散记录就该离散显示 |
| 空命令当删除 | 清空命令即删记录 | 占位语义丢失，触发时刻被抹掉 | 占位是合法状态，删除是另一回事 |
| 位置允许三轴 | 加 y 分量 | 格式只有水平两轴，纵向由物理决定 | 只写真实支持的字段 |
| 同一时刻拆多条记录 | 允许相同时间 | 格式要求严格递增，解析会拒绝 | 用 `&&` 合并命令 |

**本方案的缺点**：

- 同一时刻只能一条记录，作者要多写 `&&` 而不是分条列。
- 占位记录看起来"什么都没有"，容易被误删。
- 记录 id 不参与去重，作者若拿它当身份会踩坑。

### 验收要点

- 新建记录默认时间为 0、命令为空占位，摘要显示"占位"。
- 时间为 0 的记录在第一次推进时触发，不是等播放到某一帧。
- 时间超出片段时长：新建被阻止，旧记录标注"运行时丢弃"。
- 两条记录时间相同：阻止，提示用 `&&` 合并命令。
- 事件类型只显示一个合法值，写其他值报错。
- 空命令能保存并显示占位，不删除记录。
- 片段只有一条记录时删除被拒绝，记录仍在；删整个事件对象才让片段无事件。
- 命令带前导斜杠：警告，保存保留原文。
- 绝对位置显示为世界坐标，相对位置标注基准是激活位置。
- 位置键不成对、混写、多键：block。
- 只有一条位置记录：允许保存，但提示"不足两个航点，不驱动移动"。
- 多条位置记录按全局时间构成折线，时间轴标记可重叠。
- 片段循环回到 0：已触发的记录不重放，界面不承诺循环重播。
- 乒乓模式用在事件轨：block。
- 显式 seek 前跳不补触发；后跳回退时目标之后可再触发。
- 多条事件轨：警告，不自动合并也不新建第二轨。
- 保存重开：时间、命令、位置、记录 id 原样恢复。
