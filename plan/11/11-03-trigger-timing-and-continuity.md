# 触发器时序与连续语义

> 状态：已实现
> 范围：`delay`、`repeatable`、`on_enter`、`exit_buffer`、`poll_interval`、`continuity` 的适用性与呈现
> 关联：11-02 声明、11-04 条件树、06 脚本属性里的触发器缺省

## 一、摘要

六个时序字段决定触发器"什么时候触发"，不改变条件本身：延迟、可重复、进入边沿、离开外扩、轮询间隔、连续语义。本文定义它们各自在什么类型上有效、无效时怎么呈现、以及为什么编辑器只写字段和提示而不替作者推断运行时状态。

## 二、为什么做

### 2.1 问题

这六个字段最容易被当成"随便填都行"：作者在 `facing` 上填 `exit_buffer`，或在 `death` 上打开 `on_enter`，脚本能存盘，游戏侧却直接判为无效——有些是 error，脚本被拒；有些是"将被忽略"，作者以为生效了。另一类问题是语义误解：以为 `delay` 会让条件更晚求值，其实它只推迟动作执行；以为 `repeatable=false` 只在本次会话内生效，其实已触发事实随存档持久；以为 `exit_buffer` 是一个独立字段，其实运行时用原条件外扩出一份退出条件，脚本里并没有 `exit_conditions`。

轮询间隔还有一层继承：触发器级 → 脚本级缺省 → 类型默认。作者看不到生效值，只能靠猜。

### 2.2 目标

- 每个时序字段只在可适用的类型上可编辑，不可用时禁用并说明原因。
- 无效但已存在的值保留为只读，不静默清零。
- 轮询间隔显示生效值与来源，让作者知道当前继承到了哪一层。
- 连续性三个子语义各自说清适用范围，不把"忽略"当成生效。

### 2.3 非目标

- 不新增 `exit_conditions` 字段，也不在编辑器里另存一份退出条件。
- 不在行为页重复编辑脚本级 `trigger_poll_interval`（归 Script Properties 的"触发器缺省"卡）。
- 不画停留进度条、不预测挂起时长、不模拟延迟队列。

## 三、方案

**延迟**按秒写，0 表示立即执行；它只影响动作执行时点，不影响条件求值。同一触发器已有延迟项在排队时，再次命中只记录事实、不再排队，界面说明这一点。延迟期间若脚本被结束、实例被暂停或播放切换，队列按运行时处理，编辑器不承诺"必然执行"。

**可重复**决定去重身份是否只用一次。关闭时按"玩家 + 脚本 + 触发器"只触发一次，已触发事实持久，换会话不清；开启时允许再次触发，但仍受进入边沿复位与延迟排队去重的约束。改这个字段不迁移已触发记录，应用前提示"历史已触发记录不重置"。

**进入边沿**只在条件从 false 变 true 的瞬间触发，离开并复位后才能再次进入。事件驱动的触发器没有离开事件，进入态不会复位，所以写 `on_enter` 实际等价于只触发一次——对 `death` 这类类型，校验器直接报无效，界面不显示可编辑开关，只保留旧值只读块。轮询类可以用，与 `repeatable` 并存时以运行时为准，界面不擅自简化成单次。

**离开外扩**只在三个条件同时满足时可编辑：打开了 `on_enter`、是轮询类、条件根对象有可外扩的空间区域（球形用位置加半径，方体用两个角点）。不满足时控件禁用并给出原因，已有非零值进只读块。`facing`、组合器、`death` 明确不可用。

**轮询间隔**是 1 到 600 的 tick 值，只对轮询类有效；事件驱动类写了会被判"无效，将被忽略"。行为页只显示生效结果与来源（触发器 / 脚本 / 类型），要改脚本缺省得去 Script Properties。事件驱动类直接显示"事件驱动，不轮询"，不给输入框。组合器按子条件的轮询需求运行，界面只给生效值，不让作者手算。

**连续语义**是一个对象，三个子字段都可省：

- `sweep` 把相邻两次采样之间的运动近似成线段或最短弧，判断这段运动是否碰到条件区域。它只对 `location`、`structure`、`facing`、`observation` 这类有几何语义的类型有意义；其他类型显示"无几何语义，将被忽略"并禁用开关。打开它不改变点判定结果——点命中仍然优先为真。
- `dwell` 是停留门槛，单位 tick，0 表示无门槛，只对轮询类有效。界面同时显示秒数换算，落盘仍是整数 tick。条件中途断掉会清零累计；编辑器不画停留进度，只写字段。
- `window` 是事件类子条件的回看窗口，单位 tick，0 表示不启用，只对 `all_of` / `any` 生效。它只作用于组合器内的事件类子条件，不把普通轮询叶子变成窗口判定；界面在组合器节点上显示窗口，叶子不重复显示。

三个字段全为 0 或 false 等价于未声明，应用时可以整个省略 `continuity`，不写空对象。未知键保留在只读高级块，不静默删除。超过上限、非整数、非数字就地报错，不夹取。

时序区固定显示一条只读的求值顺序说明：前置全部满足 → 检查是否跳过（同脚本播放中、单次已触发）→ 条件求值 → 记录事实 → 延迟排队 → 执行动作。它提醒作者两件事：同脚本正在播放时本触发器跳过，跨脚本不阻塞；单条动作失败只跳过该动作，不中断后续动作。

## 四、技术细节

### 4.1 核心模型

时序字段分两类：一类改变触发时点（延迟、进入边沿、连续语义），一类改变是否还能再触发（可重复、离开外扩）。轮询间隔属于采样节拍，不参与条件语义。连续性是对"两次采样之间发生了什么"的补充判断，不是独立条件。

### 4.2 契约

- 适用性由"触发器类型 + 条件根对象的形状"共同决定，不由作者手选。
- 继承链只有三层：触发器 → 脚本 → 类型默认。界面展示生效值与命中层级，不展示中间计算。
- 未知 `continuity` 键原样保留，编辑器只读显示。

### 4.3 数据形态

延迟与驻留、窗口分别用秒与 tick 两种单位，界面显示换算但落盘不换算。`continuity` 是可选对象，省略与"全零"等价；界面避免写出全零对象。

### 4.4 边界

- 编辑器不判断"这次命中会不会真的执行"，因为队列、挂起、播放切换都在游戏侧。
- 不把"无效将被忽略"当 warning 轻描淡写——它是校验器的 error。
- 不在行为页写脚本级缺省值。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 六个字段一律可编辑 | 不判类型，全部给输入 | 作者写出必被拒绝的脚本，且不知道原因 | 适用性是格式事实，编辑器应当前置暴露 |
| 无效值自动清零 | 切类型时清掉不适用的时序字段 | 静默丢作者数据，撤销也救不回语义 | 只读保留 + 明确提示 |
| 提供独立退出条件字段 | 新增 `exit_conditions` | 新增脚本字段，游戏侧不认识 | 运行时是外扩原条件，编辑器不能造字段 |
| 行为页也能改脚本级缺省 | 两处都能编辑轮询缺省 | 同一值两个入口，容易打架 | 缺省归 Script Properties，行为页只显示继承结果 |

**本方案的缺点**：

- 六个字段的适用性规则分散在类型与条件形状两处，作者需要读提示才知道为什么禁用。
- 只读保留的旧值会让 JSON 暂时带有无效字段，需要作者主动清理。
- 连续语义三个子字段的适用范围互不相同，一次讲清的成本较高。

### 验收要点

- `delay=1.5`：按 1.5 秒语义保存；同触发器连续命中时提示已有待执行，不重复排队。
- `repeatable=false`：列表显示单次；改开后提示历史已触发记录不重置。
- 轮询类开 `on_enter`：显示进入边沿；离开并复位后可再次进入。
- `death` 配 `on_enter`：说明"事件驱动无进入/离开语义，等价只触发一次"，不提供开关。
- `location` 球形区域加 `on_enter`：`exit_buffer` 可编辑；`facing` 或组合器上则显示无效、值只读。
- 事件驱动写 `poll_interval`：显示"事件驱动，不轮询"，输入禁用。
- `continuity.sweep` 用在 `advancement`：显示无几何语义，不写新值。
- `continuity.dwell=20`：界面显示 1.0 秒，落盘仍是 20 tick。
- `continuity.window=40` 在 `all_of`：窗口显示在组合器节点上，叶子不重复。
- tick 值非整数或越界：就地报错，不夹取。
- 保存重开：六个字段原样恢复，未知 `continuity` 键保留。
