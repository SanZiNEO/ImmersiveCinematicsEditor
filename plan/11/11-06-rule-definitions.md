# 规则定义与策略

> 状态：已实现
> 范围：`rules[]` 的字段面、`policy` 六个字段、增删复制与 id 事务重命名、引用保护
> 关联：11-07 条件树、11-08 动作、11-09 绑定、11-10 执行

## 一、摘要

规则定义是"条件 + 动作集 + 策略"的三件套，本身不绑定片段：同一条规则可以被多条绑定复用，每条绑定各自独立运行。本文定义定义的字段面、策略各字段的含义与缺省、以及重命名和删除时的引用处理。条件树与动作的字段规则分见 11-07 与 11-08。

## 二、为什么做

### 2.1 问题

规则与绑定是最容易被当成一个东西的一对：作者以为"加一条规则"就会在某个片段里生效，实际上规则只是定义，必须有一条绑定指向某片段才会跑。于是常见现象是一堆未被绑定的规则躺在脚本里，作者找不到它们为什么不起作用。

策略字段的缺省也容易被误解。`once` 缺省为真，且它的作用域是"每次片段执行内一次"，不是"整个脚本永久一次"；`timeout=-1` 表示无限等待，不是零秒超时；`on_timeout` 在有超时前是禁用的，但已有内容要保留而不是删掉。

引用问题同样具体：规则 id 被绑定引用，重命名必须连带更新所有绑定；删除被引用的规则会制造悬空绑定，而悬空绑定在运行时是无效入口。

### 2.2 目标

- 一眼看出某条规则有没有被绑定，不被隐藏也不被自动删除。
- 策略六个字段的含义、缺省与互斥关系在字段旁可见。
- 改规则 id 时所有引用一起改，一次撤销回到改前。
- 删除被引用的规则前，先看到谁在用它。

### 2.3 非目标

- 不定义条件树结构（11-07）与动作字段（11-08）。
- 不新增 `policy` 字段或新的策略语义，编辑器不执行规则。
- 不在定义层编辑绑定，也不自动为规则创建绑定。
- 不预测某条规则在运行时会被触发几次。
- 不把策略做成"运行参数调优面板"。

## 三、方案

规则定义有四个键：`id` 必填且脚本内唯一，字符集与片段 id 相同；`condition` 必填对象；`actions` 必填非空数组；`policy` 可省。`policy` 是键白名单，未知键报错。

详情自上而下：身份、条件、动作、策略、绑定、诊断。身份显示规则 id、被多少条绑定引用、是否未绑定。条件必须是对象，空对象按"永不满足"处理并报错，不自动改成恒真。动作至少一条，顺序即执行顺序，可上下移动；空数组时"应用"禁用。绑定区列出该规则下的全部绑定，只读展示，编辑在 11-09。

策略六个字段：

- `once` 缺省为真，成功后本次激活不再触发。与 `cooldown` 并存时，`once` 成功即终态，`cooldown` 只对未成功的重复触发有意义；界面给提示但不删字段。关掉它规则可重复触发，仍受冷却与条件边沿或驻留约束。
- `cooldown` 单位秒、不小于 0，是触发后的静默时长，不影响已经成功的 `once` 终态；0 表示不静默。
- `mode` 取 `enter` 或 `dwell`，缺省 `enter`。`enter` 在条件从不成立到成立的瞬间触发；`dwell` 要求条件连续成立达到驻留秒数。切到 `dwell` 时显示驻留输入；切回 `enter` 时保留 `dwell` 值但禁用，不静默清零。`dwell=0` 仍按驻留模式，实际等同立即，界面给提示而不自动改模式。
- `timeout` 大于 0 表示从过了时间门开始计时，到点仍未成功就执行一次超时动作；`-1` 表示无限等待，此时超时动作禁用但保留内容并提示"不会执行"。0 非法，不允许用它表示"立即超时"。
- `on_timeout` 是动作数组，可为空，动作类型与普通动作相同；没有超时时不可新增，已有内容只读。超时动作执行后规则进入终态，不重复执行。

列表每行给出规则 id、动作数、是否单次、模式、有无超时、绑定数与最高问题级别。未绑定的规则显示"未绑定"，不隐藏。规则按声明顺序排列，不按绑定数或名称排序。

新增时给默认 id 与默认策略（单次、冷却 0、进入模式、驻留 0、无限等待），条件与动作先留空，但空条件与空动作在应用时是错误，所以新增后先引导补条件与动作。新增不自动建绑定。

复制只复制定义，不复制绑定——绑定是"规则 × 片段"的关系，复制规则不等于复制入口；副本 id 加后缀，与原规则完全独立。

删除时若无绑定可直接删；有绑定时禁用并列出绑定，支持先把绑定迁移到另一条规则再删。删除规则不动片段字段。

改 id 是事务性重命名：新 id 必须合法且唯一，所有绑定的 `rule` 引用同步更新，一次撤销回到旧 id 与旧引用，任一绑定更新失败则整体不应用。

## 四、技术细节

### 4.1 核心模型

规则定义只描述"什么条件下做什么"，不含目标片段、不含时间门、不含出口。策略描述"这条定义在一次激活里能被触发几次、等待多久、超时怎么办"。

### 4.2 契约

- 定义被绑定按 id 引用，因此 id 重命名必须覆盖全部引用点。
- 策略是白名单对象，未知键视为错误而非忽略。
- 条件与动作的深层校验由 11-07、11-08 与 11-15 负责，定义层只保证容器存在且非空。

### 4.3 数据形态

`actions` 与 `on_timeout` 是同一套动作对象的两个数组，前者非空、后者可空。`mode` 与 `dwell` 是两个独立字段，切换模式不改另一个的值。

### 4.4 边界

- 定义层不解释条件求值顺序，也不解释动作执行结果。
- 不显示"这条规则被触发过几次"。
- 不在定义里写片段、时间门或出口——那是绑定的字段。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 规则自带片段 | 定义里写目标片段与时间门 | 一条规则无法复用到多个片段 | 复用是规则定义存在的理由 |
| 删除时级联删绑定 | 删规则顺手删它的绑定 | 静默丢作者配置，且无法撤销语义 | 引用保护优先 |
| 重命名只改定义 | 绑定的 `rule` 保持旧值 | 立即产生悬空绑定 | 引用必须一起改，且要原子 |
| `dwell=0` 自动转 `enter` | 归零时改模式 | 作者的模式选择被静默改写 | 保留模式，只提示实际效果等同 |

**本方案的缺点**：

- 定义与绑定分离，作者要理解两个层级才能让规则真正跑起来。
- 策略字段之间有语义交叠（`once` 与 `cooldown`、`mode` 与 `dwell`），提示文案偏多。
- 重命名的事务性意味着一次失败就整体不应用，作者需要先修好冲突。

### 验收要点

- 新建规则：默认 id 与默认策略正确；动作数组为空时不能应用。
- 条件为空对象：显示错误，不自动变成恒真。
- 改规则 id：所有绑定的 `rule` 同步更新；一次撤销恢复旧 id 与引用。
- 规则 id 重复：阻止应用，两条规则都标。
- 删除被两条绑定引用的规则：默认禁用并列出两条绑定。
- 关掉 `once`：显示"可重复"，与冷却同时可见且不合并。
- `mode=dwell` 且驻留 2 秒：显示驻留 2 秒；切回 `enter` 保留值但禁用。
- `timeout=-1`：显示无限等待，超时动作禁用且已有内容只读。
- `timeout=3` 配超时动作：说明"过时间门后 3 秒执行一次"。
- 空动作禁止应用，空超时动作允许。
- 未绑定规则可见，不自动删除也不自动建绑定。
- 保存重开：定义字段与绑定引用原样恢复。
