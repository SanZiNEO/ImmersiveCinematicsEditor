# 规则执行与出口

> 状态：未实现
> 范围：单条绑定从时间门到动作提交的顺序、`enter`/`dwell`、`once`/`cooldown`、调度释放、超时、持有与五种出口
> 关联：11-06 策略、11-08 动作、11-09 绑定、11-11 事实

## 一、摘要

本文说清一条绑定在一次片段执行里经历什么：什么时候开始判定、条件成立之后事实怎么记、动作什么时候真正提交、等待超时怎么算、实例什么时候被挂起，以及分支完成后的五种出口各是什么。编辑器不运行规则，只展示字段与诊断；这里的语义用于判断"编辑器该提示什么"。

## 二、为什么做

### 2.1 问题

规则的时序是这套系统里最难凭直觉猜对的部分。作者常见的误解有：以为时间门只判一次；以为 `once` 是整个脚本永久一次（其实是每次片段执行一次）；以为 `succeeded` 等于动作全部成功；以为超时从片段开始算（其实从时间门首次满足算）；以为 `hold` 挂起能阻止超时（真实时钟照走）；以为 `continue`、`return`、`end_execution` 是三种不同结果（当前行为一致）。

调度与冷却的单位也常混：调度里的延迟按真实时钟走，挂起不冻结；冷却按播放时钟走，挂起时冻结。

三个"退出/跳转"更是反复被混用：动作 `goto_clip` 是开新分支，绑定 `exit` 是分支完成后的去向，动作 `exit` 是结束当前播放实例。

### 2.2 目标

- 单条绑定在一帧内的判定顺序可被作者复述：先门后条件、先成功事实后动作、超时与成功互斥。
- 每个时间相关字段用"哪种时钟"标注清楚，不让作者自己推断。
- 五种出口的实际行为说明白，尤其三种同义写法不假装成三种结果。
- 诊断能指出"这个等待在冻结状态下永远等不到"这类结构性问题。

### 2.3 非目标

- 不在编辑器内实现规则执行器或第二套运行时。
- 不预测具体触发次数、不显示运行时状态。
- 不把 `continue`、`return`、`end_execution` 改写成统一写法（保留作者原文）。

## 三、方案

单条绑定在一次片段执行里的顺序是固定的：片段尚未开始时既不建激活、也不持有、不判条件；执行身份变化时释放旧持有、建新激活、清空本次激活的事实；目标片段完成时记录完成事实；时间门满足（局部时间不小于门值）才进入判定，不满足则释放本绑定的持有并跳过；门首次满足时记下真实时刻作为超时起算点；随后求值条件树；再检查单次与冷却；触发时记录成功事实、释放持有、提交动作；无调度则立即执行动作并记录动作完成，有调度则入队等待释放、暂不记录完成；门后未成功且真实时钟到点则执行一次超时动作并标记终态；控制方式为持有时，门后未成立就挂起实例。

这个顺序不能颠倒：门在条件之前，成功事实在动作之前，超时与成功互斥。

**时间门**是外层门，条件树是内层判断。局部时间是目标片段执行内部秒，不是全局时间轴时间。片段尚未开始时局部时间可能显示为 0，但不能因此误判门已满足——运行时用执行窗口起点挡掉这种情况。门值为 0 表示片段一开始就参与判定，不是"到 0 秒瞬间只判一次"。门不满足时释放本绑定的持有，不会让实例一直挂着等门。

**两种模式**：`enter` 在条件从 false 到 true 的上升沿触发一次，条件持续为真不重复触发，必须先回 false；每次片段执行重置边沿状态。`dwell` 要求条件连续成立累计播放时间达到驻留秒数才触发，中途断掉清零；挂起期间驻留时间不推进，这是持有状态下可能永远等不到驻留的原因之一；首帧或时钟回退时增量按 0 处理，不倒退累计。

**单次与冷却**：`once` 是"每次片段执行内成功后不再触发"，换一次执行会重置，不是整个脚本永久一次。冷却在成功后按播放时钟设一个静默截止点，跨片段执行保留，挂起时播放时钟冻结。触发前同时检查单次已成功与冷却是否到期。超时后本次执行标记完成，不再触发，下一次执行重新开始。编辑器只显示"单次 / 可重复 / 冷却 N 秒"，不推算次数。

**成功与动作完成**是两个事实：条件成立即记录成功，这是规则成功而非动作完成；无调度时动作按声明顺序执行后记录动作完成；有调度时动作入队，释放并提交后才记录。动作完成表示"这批动作已提交"，不表示每个动作都成功——动作失败只跳过该动作。队列按承诺顺序提交，本帧释放的动作对同帧后续判定可见；待执行队列不冻结内容，但会作为脚本自然完成的依赖。

**调度释放**各有判据：片段开始在目标片段记录开始事实之后释放；片段完成在目标片段完成事实晚于承诺时释放；局部时间在目标片段活跃且局部时间达到指定值、并已离开承诺帧后释放；延迟按真实时钟经过指定秒数释放；事实在另一条绑定的事实晚于承诺时释放。不可满足的等待（目标片段不在账本等）会被丢弃并告警，不阻塞自然完成；已经过去的局部时间不补触发。

**超时**只对正值生效，`-1` 是无限等待。起算点是时间门首次满足的真实时刻，不是片段开始，也不是条件首次成立。门后已成功则不再超时；超时后执行一次超时动作并标记终态，超时动作为空也照样标记。真实时钟在挂起期间照走，所以持有也不能阻止超时。超时动作里禁用命令动作，因为服务端命令表只编译普通动作。

**持有**在门后条件未成立且未成功、未超时、未终态时挂起实例；成功、超时、门不满足、执行切换都会释放。多个来源可以同时持有，全部释放才恢复推进。冻结期间局部时间与驻留时间都不推进，因此时间条件与驻留条件可能永远不满足，诊断区会提示"持有等待未来局部时间或其他片段"。暂停与恢复动作走同一本挂起账本：暂停加一个持有，恢复释放全部暂停持有，不影响判定持有；若本次执行内已经没有仍可触发的恢复动作，运行时会告警并自动释放，防止卡死，编辑器不强制成对也不预测自动释放。

**五种出口**：`continue` 与 `return`、`end_execution` 当前行为一致——分支目标完成时结束分支回主线，主线片段则继续；`end_script` 结束分支并请求脚本整体结束；`goto` 结束分支并以目标片段加入口时间链式启动新分支。三种同义写法在界面上一并说明，保留作者原文不自动改写。`goto` 链式启动没有调用栈，新目标使用自身默认出口，不继承入口覆盖。

**绑定的出口归属**：绑定 `exit` 是入口出口覆盖，只在本绑定的动作 `goto_clip` 启动分支时作为该分支的出口；它不在本绑定自己的片段完成时生效，也不作用于 `goto` 链的下一跳。绑定没有出口时，分支入口用目标片段默认出口。动作 `goto_clip` 只读触发它的那条绑定的出口，不读目标片段自己的绑定出口。

**动作 `exit`** 结束当前播放实例：设置完成原因、开始渐出、标记停止中，渐出完成后真正停用。它不经过"播完驻留"的拒绝门，作者显式退出不会被挡住；只作用于触发实例，不影响其他并行实例。文案写"结束当前播放实例（渐出）"。

**分支启动**：目标由片段与入口时间指定；同一实例同一时刻只允许一条分支，已在分支中或目标不在执行账本时启动被拒绝，动作跳过而不改现有分支，也不执行出口策略。分支目标完成才走出口；分支失败恢复启动快照并回到原播放头。新分支不是嵌套调用，没有返回栈。

诊断区按级别列出：门越界、调度等待未知片段、调度事实成环、超时里出现命令动作、持有等待未来时间、持有等待不会开始的片段、暂停没有释放者、三种同义出口混用。

## 四、技术细节

### 4.1 核心模型

一条绑定的一次执行是一个"激活"，激活持有自己的边沿状态、驻留累计、成功与超时标记、动作队列。片段执行切换会重建激活并清空事实。所有这些都在游戏侧，编辑器只描述规则。

### 4.2 契约

- 时间相关字段分两类时钟：局部时间与播放时钟用于条件、驻留、冷却；真实时钟用于延迟调度与超时。
- 成功事实与动作完成事实分开记录，条件树分别读。
- 出口策略归属"启动分支的那条绑定"，不随分支传递。

### 4.3 数据形态

编辑器只写字段：门值、控制方式、调度对象、出口对象、策略值。激活状态、队列、边沿标记都不在脚本里。

### 4.4 边界

- 不显示运行时的激活状态、队列长度、剩余冷却。
- 不预测某次执行会不会触发。
- 不改写作者选择的出口写法，即使三种当前同义。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 超时从片段开始算 | 简化起算点 | 门后很晚才开始判定时，超时会提前触发 | 起算点是门首次满足，与"等待多久"的直觉一致 |
| 把三种同义出口合并 | 界面上只留 `continue` | 改写作者原文，破坏格式兼容 | 保留写法，只在提示里说明当前同义 |
| 持有冻结真实时钟 | 挂起时暂停超时 | 死锁无法自愈 | 超时按真实时钟走，持有不能阻止 |
| 绑定出口作用于本片段完成 | 直觉化语义 | 与运行时相反，主线片段完成不读它 | 它是 goto 分支的入口覆盖 |

**本方案的缺点**：

- 时钟有两套（播放时钟、真实时钟），每个字段都要标注，界面文案负担重。
- 三种同义出口保留原文会让作者以为它们不同。
- 持有的诊断（等待未来时间）无法在编辑器里彻底判定，只能提示。

### 验收要点

- 门值 2、局部时间 1：不判条件、不持有；到 2 之后才判。
- `enter` 模式：条件持续为真只触发一次，回 false 再 true 才再触发。
- `dwell` 驻留 2 秒：连续成立 2 秒才触发，中途断掉清零，挂起时不推进。
- 单次模式：本次执行成功一次后不再触发，换一次执行可再触发。
- 冷却 3 秒：成功后播放时钟 3 秒内不再触发，跨执行保留，挂起时不推进。
- 无调度：动作执行后记录动作完成，条件树能读到。
- 有真实延迟调度：先记录成功，延迟到点后才提交并记录动作完成。
- 持有时门后未成立：实例挂起；成功、超时、门不满足、执行切换后释放。
- 超时 2 秒：门首次满足后 2 真实秒未成功则执行一次超时动作，挂起也照走。
- 无限等待：不超时，超时动作禁用。
- 三种同义出口：分支完成都结束分支回主线，界面说明当前同义。
- 结束脚本：分支完成请求脚本结束，与动作 `exit` 区分。
- `goto` 链：第一跳用触发绑定的出口，第二跳用目标片段默认出口。
- 已有分支在跑时再启动：被拒绝，动作跳过，不中断播放。
- 动作 `exit`：进入渐出，不是立即消失，不受播完驻留阻挡。
- 超时动作里写命令：block，提示命令表不编译超时动作。
- 持有等待未来时间：诊断提示"冻结时不会到达"，不自动解除。
- 保存重开：绑定的门、控制、调度、出口与规则策略原样恢复。
