# 11-05 触发器前置与跨脚本依赖

## 目标

把 `meta.triggers[].requires` 做成结构化的 AND 前置列表，并覆盖跨脚本前置。前置是整条触发器之前的门，不是条件树里的普通叶子；但组合器内部也可以放脚本前置子条件，两者要分清。

编辑器只写 `requires` 和组合器子项，不查询运行态“某玩家是否播放过”。

## 存储形态

`requires` 是数组，元素两种形态：

```text
"chapter1"
```

等价于：

```text
{ "type": "script_played", "script": "chapter1" }
```

对象形态：

```text
{ "type": "script_started", "script": "chapter2" }
```

- 元素是字符串：只可能是 `script_played` 简写；
- 元素是对象：必须有非空字符串 `type`；其余键是该前置的数据；
- `script_played` / `script_started` / `script_completed` 用 `script` 字段指向目标脚本 id；
- 自定义类型只保留 type 与原始数据，编辑器不猜字段。

## 内置三种

| type | 语义 | 判定源 |
|---|---|---|
| `script_played` | 目标脚本有开始事实且有结束事实（任何退出原因都算） | 服务端事实账本 |
| `script_started` | 目标脚本有开始事实 | 服务端事实账本 |
| `script_completed` | 目标脚本有结束事实；不要求先开始过 | 服务端事实账本 |

- 三种都是“玩家 + 脚本”维度，与播放实例、退出原因无关。
- `script_completed` 只看结束事实，不等价于“完整播完”。
- `requires` 是 AND：全部满足才允许触发；空数组 = 无前置。
- 前置先于跳过检查：前置不满足时，触发器不求值、不写 `TRIGGER_FIRED`。

## 与组合器内前置的区别

| | `requires` | 组合器子项 |
|---|---|---|
| 位置 | 触发器外层 | `all_of` / `any` 的 `conditions.list` 内 |
| 语义 | 整条触发器的 AND 门 | 条件树内部子条件，可参与 OR |
| 字符串简写 | 允许，等价 `script_played` | 不允许，必须写对象 |
| 锁存 | 每次求值都先检查 | 前置子条件解锁后持续为真 |
| 用途 | “必须已经播过某章” | “前置满足 **或** 位置满足” |

- 组合器内前置子项写成 `{type:"script_played", conditions:{script:"chapter1"}}`，不是 `script` 顶层字段。
- `requires` 里的对象写成 `{type:"script_played", script:"chapter1"}`。
- 两处不自动互转。

## 行为页编辑

### 列表

```text
前置（AND）
├ script_played → chapter1      已解析
├ script_started → chapter2     缺失
├ weather → rain                自定义前置，只读
└ script_completed → chapter1   重复
```

每行显示：

- `type`
- 目标脚本 id（内置三种）或“自定义前置”
- 解析状态：已解析 / 缺失 / 自引用 / 重复 id / 自定义只读
- 目标脚本路径（能解析时）
- 删除、上下移动

顺序只用于阅读；AND 语义与顺序无关，但保留原数组顺序，保存时不重排。

### 新增

1. 选择类型：`script_played` / `script_started` / `script_completed`。
2. 选择目标脚本：
   - 从当前项目图索引的脚本 id 列表选择；
   - 也可手动输入脚本 id；
   - 不选文件路径，`requires` 认的是 `meta.id`。
3. 应用时写对象形态；如果作者选择“使用简写”，只有 `script_played` 可写成字符串。
4. 目标为空、类型为空：不允许应用。

### 编辑已有

- 字符串简写：显示为 `script_played`，但保留字符串形态；改目标仍写字符串。
- 对象形态：改 type 时保留原 `script`；切到自定义类型时 `script` 变为只读旧字段，不静默删。
- 自定义类型：只显示 type + 原始数据只读块，不提供目标选择器，不把它伪装成脚本前置。
- 删除前置后，如果触发器没有其他前置，显示“无前置”。

### 目标选择器

- 数据来自当前项目图索引：`scriptId`、`path`、`name`、`valid`、`duplicate`。
- 目标脚本缺失：允许手动写 id，显示“缺失”，不自动创建脚本。
- 目标 id 重复：显示“重复 id，无法确定”，不自动选先扫到的那个。
- 目标等于当前脚本：显示“自引用”，不阻止保存但给警告。
- 目标脚本未打开：仍可引用；不要求先打开文档。

## 跨脚本依赖视图

行为页“依赖”页签与脚本图边使用同一套关系：

- 每个 `requires` 条目对应一条潜在边；
- 字符串简写按 `script_played` 建边；
- 自定义类型没有脚本 id，不建边，只读；
- 同一目标重复出现：保留多条 `requires`，图上只画一条边，但依赖页显示重复；
- 目标缺失：画悬空桩，不创建假节点；
- 自引用：不画完整边，标“自引用”；
- 环：标“环内前置”，提示“可能只能由外部启动打破”。

### `requiresFingerprint`

- 图数据里的 `requiresFingerprint` 只用于依赖维护并发检测，不是作者字段，不在行为页显示。
- 行为页改 `requires` 后由保存流程重算；不手写指纹。

## 校验

| 检查 | 级别 | 处理 |
|---|---|---|
| `requires` 不是数组 | block | 前置区红框 |
| 元素既不是字符串也不是对象 | block | 行红框 |
| 字符串为空 | block | 行红框 |
| 对象 `type` 缺失/空 | block | 行红框 |
| 内置三种 `script` 缺失/空 | block | 目标行红框 |
| 目标脚本不存在 | warn | “缺失” |
| 目标 id 重复 | warn | “重复 id，无法确定” |
| 目标等于当前脚本 | warn | “自引用” |
| 重复 `requires` 条目 | info | “重复前置”；保留，不自动去重 |
| 环内依赖 | warn | “环内前置，可能只能由外部启动” |
| 自定义前置被写成可编辑脚本 | info | 只读块；不提供目标选择器 |
| `requires` 与组合器子项混写 | block | 不把字符串子项写进组合器 `list` |

## 脚本图悬停

- 每个触发器下面列出全部 `requires`。
- 状态与行为页一致：已解析 / 缺失 / 自引用 / 重复 id / 自定义只读。
- 不把 `requires` 合并成一个“前置 N 个”的计数。
- 长列表在悬停卡内滚动，不截断。
- 目标脚本可点“定位”到图节点；缺失目标不创建假节点。

## 验收标准

1. `requires:["chapter1"]` 显示 `script_played → chapter1`；保存仍是字符串简写。
2. `requires:[{"type":"script_started","script":"chapter2"}]` 显示开始前置；不改写成 played。
3. `requires` 两条不同目标：两条都显示，AND 语义说明正确。
4. `requires` 两条相同目标：两条都保留；图只一条边；依赖页显示重复。
5. 目标缺失：显示“缺失”，保存允许，推送给校验器 warning。
6. 目标自引用：显示“自引用”，不画完整边。
7. 目标 id 重复：显示“重复 id，无法确定”，不自动选。
8. 自定义 `weather` 前置：只读块，没有目标选择器，不建边。
9. `requires` 目标为脚本路径而不是 id：显示“应为脚本 id”，不自动解析路径。
10. 组合器内加 `script_played`：写成 `{type, conditions:{script}}`，不是字符串，也不是顶层 `script`。
11. 组合器内前置在 `any` 中：说明“锁存，解锁后持续为真”，不按一次性事件处理。
12. 脚本图悬停：全部前置可见，状态与行为页一致，不截断。
