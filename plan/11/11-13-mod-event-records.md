# MOD_EVENT 事件记录

> 状态：已实现
> 范围：`objects.mod_event` 的离散记录、事件名与数据树、对象级缺省、与内置播放器的关系
> 关联：11-12 事件记录、11-14 时间轴语义、11-15 校验

## 一、摘要

`MOD_EVENT` 是给模组消费者的扩展事件通道：每条记录有片段局部时间、事件名和任意对象数据。它不执行命令、不驱动玩家移动，也不进规则动作。当前内置播放器不消费它——编辑器只保证格式、校验和落盘，不伪造"已触发效果"。

## 二、为什么做

### 2.1 问题

`MOD_EVENT` 与 `EVENT` 形态相似，但字段集几乎不重叠：前者有事件名与自由数据，没有命令、位置、记录 id。作者若照事件记录的习惯写，会写出被校验器拒绝的键。反过来，如果编辑器把它做成"命令通道的另一种写法"，作者会期待事件名触发某种内置效果——而内置播放器根本不读这个轨道。

数据字段的边界也容易越过：`data` 顶层必须是 JSON 对象，内部可以任意嵌套；数字必须是有限数；空对象与省略不同（前者是显式空对象，后者回退到对象级）。这些差别直接决定消费方拿到的结构。

### 2.2 目标

- 记录的事件名、数据形态、继承关系一眼可见。
- 数据既能结构化编辑，也能切原始 JSON 视图，两种视图结果一致。
- 明确标注"内置播放器不消费"，不显示任何"生效 / 未生效"。
- 对象级缺省与记录级覆盖的关系清楚，不批量改写已有记录。

### 2.3 非目标

- 不定义事件名的枚举（它没有固定取值）。
- 不把事件名映射到命令或内置效果。
- 不提供"绑定到规则或触发器"的入口。
- 不建第二时间轴，不改变事件标记的呈现规则。

## 三、方案

对象必须是事件模式且有关键帧数组；每帧有时间与记录值，时间非负有限、严格递增。一个片段只能有一个该对象，不新建第二条轨。超出片段时长的记录在运行时被丢弃，编辑器新建时限制在时长内，旧记录标"超出时长，运行时丢弃"。对象级值可以提供事件名与数据的缺省，记录级可覆盖；记录值必须是对象，不能直接写数组或字符串。

记录两个字段：

- 事件名：记录级可省，但最终必须有值。记录级缺省时取对象级显式写出的值；对象级也没写就报"缺少事件名"。它没有固定枚举，任何非空字符串都合法（如天气变化、章节名、带命名空间的自定义名）。空串非法。
- 数据：任意嵌套数据，顶层必须是对象；缺省取对象级数据。内部可以是对象、数组、字符串、数字、布尔、null 任意嵌套；数字必须是有限数。未知成员不拒绝，因为数据本身是自由结构。

记录里出现命令、位置、记录 id 一律报错——这些属于另一类事件。

数据编辑给两个视图：默认结构化键值编辑（每行一个键，值类型可选对象、数组、字符串、数字、布尔、null），以及原始 JSON 视图。应用前校验顶层是对象而不是数组或标量。嵌套的数组与对象允许，不展开成脚本字段，也不建 schema。数字保持数字、布尔保持布尔，不强制转字符串。空对象合法；省略数据与写空对象不同：前者回退到对象级或空，后者是显式空对象。

对象级缺省区显示当前的事件名与数据。改对象级缺省不批量改已有记录，只在记录未写该字段时生效。对象级事件名为空串是 block，不能让记录悄悄落回默认值。

时间与消费语义与事件记录一致：离散不插值，时间为 0 的记录在第一次推进时触发，区间左开右闭；片段循环与宏观循环不重放已触发的记录；显式 seek 前跳不补，后跳可重新触发目标之后；乒乓模式被拒绝。当前内置播放器不消费这个轨道，记录由第三方消费者自行编译读取。因此界面不显示"已触发 / 未触发"或"生效 / 未生效"，只显示格式与时间。事件名不映射到命令，不要写斜杠命令语法。

行为页详情按片段列出记录，顶部显示对象级缺省，下面是各条记录：时间（秒，片段局部，附全局换算）、事件名（文本输入，空串报错，显示"继承对象缺省"状态）、数据（双视图）、删除、复制、上下移动。复制需改时间避免相同；排序按时间升序，不允许相同时间；超出时长时阻止新建，旧记录红框。

摘要格式：有时间、事件名与数据键数，如"时间 · 事件名 · 数据 N 键"；继承对象缺省时写"继承 某名"；数据为空对象时直接显示空对象；超时长写"超出时长（运行时丢弃）"；事件名为空写"缺少事件名"。

删除同样受"至少留一条"约束：片段里唯一的记录不能删，要让片段不再有这个通道就得删除整个对象。事件对象不允许变成空记录列表。

## 四、技术细节

### 4.1 核心模型

一条记录是"局部时间 + 记录值"，记录值是"事件名 + 数据"两项，两项都可以从对象级缺省继承。对象级缺省是整条轨道共享的兜底值，不是模板——修改它不会回填到已写字段的记录。

### 4.2 契约

- 对象路径固定，模式与类型必须匹配，否则是结构错误。
- 事件名的最终值由"记录级 → 对象级"逐级回退，两级都没有即错误。
- 数据只校验顶层形态与数字有限性，内部结构交给消费方解释。

### 4.3 数据形态

事件名是字符串；数据是任意 JSON 对象。数据里不出现脚本字段引用、不出现类型标注、不建 schema。记录级写空对象与省略是两种不同的落盘结果。

### 4.4 边界

- 不解释数据含义，也不校验消费方 schema。
- 不显示消费结果，因为内置播放器不消费。
- 不把事件名当命令，也不提供命令语法提示。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 与 EVENT 共用一套字段 | 记录里都放命令、位置、事件名、数据 | 两套校验互斥，写出的记录必有一半非法 | 两类记录字段集不重叠 |
| 给事件名做枚举 | 下拉里列已知事件名 | 格式允许任意非空名，枚举会挡住扩展 | 事件名是自由字符串 |
| 提供内置效果预览 | 事件名映射到画面效果 | 内置播放器不消费，预览是假的 | 只保证格式与落盘 |
| 省略数据等同空对象 | 统一按 `{}` 处理 | 丢失"继承对象级"的语义 | 两者落盘结果不同 |

**本方案的缺点**：

- 内置不消费，作者写完看不到任何反馈，容易怀疑是否写对。
- 数据是自由结构，编辑器无法给出有意义的校验，只能保证顶层形态。
- 对象级缺省与记录级覆盖的两级回退需要作者理解继承顺序。

### 验收要点

- 新建对象：对象级事件名有默认值，一条时间为 0 的记录，记录可继承。
- 记录级不写事件名、对象级写了：显示"继承"，保存合法。
- 两级都不写：block"缺少事件名"。
- 事件名为空串：block，不落回默认。
- 数据顶层是数组、字符串或数字：block，提示"顶层必须是对象"。
- 数据内嵌对象、数组、布尔、null：原样保存，不转字符串。
- 记录级写空对象：显示显式空对象，不继承对象级数据。
- 记录省略数据：显示继承对象级数据；对象级也没有则显示空。
- 记录里写命令、位置、记录 id：block。
- 时间为 0 首次推进触发；超时长显示丢弃。
- 两条记录时间相同：阻止，提示改时间。
- 片段循环不重放；seek 后跳可重新触发目标之后。
- 乒乓模式用在该轨：block。
- 内置播放器不消费：详情不显示"已生效"，只写"数据记录"。
- 保存重开：对象级缺省、记录的事件名与数据、时间原样恢复。
