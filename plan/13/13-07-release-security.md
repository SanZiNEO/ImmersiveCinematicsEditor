# 发布基线与安全

> 状态：未实现
> 范围：版本显示名、构建与打包、包内容、进程边界与 token、兼容性、已知限制、发布清单与阻断条件
> 关联：13-01 总账、13-04 真游戏冒烟、13-06 关闭幂等、14 的 AUI 版本格式

## 一、摘要

这一份把"能跑"收成"能发布"：版本号固定且各处一致，构建与打包可重复，发布包里没有本机绝对路径、token 与调试文件，安装、首启、连接、卸载可验收，已知限制写清楚。它不改业务语义，只产出发布包、发布说明和验收记录。有一件事必须写在最前面：13 不发布 AUI，AUI 的加载器版本、进程内端点、GPU 帧源与游戏内输入都归 14；13 只冻结 AUI 的版本格式，不产出它的包。

## 二、为什么做

### 2.1 问题

能跑的版本和能发布的版本之间差着几件具体的事。版本名可能在三处各写一套——状态栏、关于页、发布说明——用户看到的和清单里记的不是一个东西。打包配置里可能留着构建机的绝对路径，于是别人拿源码打不出同样的包，日志里还会泄露目录结构。包里可能混进开发夹具、日志、截图甚至 token。安全边界上，渲染进程可能被放开到能直接读盘，preload 可能暴露了不该暴露的通道。

还有一件更隐蔽的事：发布说明写得太好听。把未实现的能力写成已支持，把 AUI 的能力混进 WebUI 的说明，把"没测过"写成"兼容"。用户装完发现不成立，信任成本比功能缺失高得多。

### 2.2 目标

- 版本显示名只有一个来源，状态栏、关于页、发布说明、产物文件名一致。
- 构建、打包、安装、首启、连接五个环节都有证据，且证据能被人复跑。
- 发布包内容干净：没有本机绝对路径、token、日志、开发夹具与旧产物。
- 进程边界成立：渲染进程无 Node 集成，preload 只暴露白名单，文件对话框走主进程。
- 已知限制完整且如实，未实现的能力不写成已支持。
- 任一发布阻断条件成立时不产出发布包。

### 2.3 非目标

- 不发布 AUI，不在本包内含游戏内编辑、进程内 GPU 帧源、游戏内输入。
- 不新增自动化测试工程；当前没有测试脚本，13 不虚构一个 CI 门禁。
- 不引入自动更新与遥测。
- 不承诺 macOS 与 Linux 支持——未验证就不写"支持"。
- 不改业务语义，缺陷回原轮修。

## 三、方案

**版本显示名**——发布用的不是 npm 的版本字段，而是显示名。WebUI 的默认显示名形如"编辑器版本 for IC 模组版本"，其中 IC 是模组名的缩写；全称在关于页与宽布局下可用。AUI 的显示名另加加载器段，14 才产出，13 只冻结格式。规则是：同一个发布物只用一个显示名，不在标题、状态栏、关于页各写一套；显示名不塞进 npm 版本字段，npm 版本仍是独立的一串；产物文件名不含空格，用连字符连接各段。

**构建与打包**——只用现有脚本入口，不新增脚本。前端产物、Electron 开发运行、Windows 打包三步都要跑；安装与卸载手动执行并留证据。必须明确：前端构建通过不等于发布通过，打包通过也不等于游戏通过，两者都只是真游戏冒烟的前置。

打包配置里有一处必须清掉：当前指向构建机 electron 目录的绝对路径。它不能作为发布基线——要么删除改用依赖解析，要么改成环境变量或本机覆盖文件，且该覆盖文件不入包。默认走依赖解析之后，打包日志里不应再出现本机私有路径。其余打包项按现状保留即可。

**包内容**——只应包含前端产物、Electron 主进程与 preload、包清单、必要的图标与许可与关于文件。不应包含计划文档、设计文档、测试夹具、版本库目录、依赖源码目录、本机 token、日志、截图、旧产物、绝对路径配置、开发用环境文件与私有证书。

**安全**——进程边界上，渲染进程不开 Node 集成；preload 只暴露白名单（窗口控制、token 读取），不暴露文件系统、子进程或任意 IPC；文件选择与保存走主进程对话框，不由渲染进程直接拼路径；外部链接不在应用内任意导航，必要时交给系统浏览器；没有远程调试端口，没有开发服务器暴露到对外地址。

token 由服务端生成、客户端只读；路径可由环境变量覆盖，否则落在用户主目录下的固定位置；不写进日志、不写进发布包、不写进脚本；关闭或世界退出后不残留；轮换后重连能重新读取；没有 token 时不发起无意义连接；文件权限尽力收紧，失败不阻断但记录。

WebSocket 只监听回环地址与固定路径，Origin 走白名单，多客户端不选举不互踢，单会话关闭只释放本会话，关键文本不静默丢，错误在状态栏可见。

脚本与资源路径上，保存要求 `.json` 扩展名；资源只接受资源根下的相对路径，拒绝绝对路径、盘符、网络共享路径与向上逃逸；列举与应用内打开共用同一份根；不把本地绝对路径或 token 或用户目录写进脚本。

**兼容性与已知限制**——兼容范围写清楚：模组版本冻结、两条加载器、游戏版本以模组构建为准、Windows 优先、macOS 与 Linux 未验证即不宣称支持、预览固定规格、H.264 需要 ffmpeg 否则回退 RGBA、外部音频格式需要 ffmpeg 否则只保证 ogg 与 wav。

发布说明必须如实列出：AUI 未发布及其包含的能力不在本包；没有自动化门禁，验收是真机手工执行；JPEG、WebP、MOV 当前不支持；视频播放依赖运行时与 ffmpeg 能力；不本地合成画面、不本地混音，最终画面与声音由游戏完成；不做纯数据模板与模板 DSL；不做字幕样式批处理、拆分合并、ASS 样式映射；不做全局 z 表、第二套字幕 JSON、字幕 sidecar；预览只有固定规格，不提供其它档位；macOS 与 Linux 未验证；发布包不含自动更新与遥测。

已知限制不是失败借口：P0 与 P1 项不能靠一句"已知限制"放行，只有 P2 或用户明确接受的降级才能进这一段。

## 四、技术细节

### 4.1 核心模型

发布判定 = 版本一致 × 构建链有证据 × 包内容干净 × 安全边界成立 × 已知限制如实 × 总账无阻断。六项是全与关系，任何一项不成立就不产出发布包。

"证据"的定义在这里比 13-01 更具体：构建日志、安装截图、首启截图、连接截图、脚本哈希，五样都要有，缺一样等于该项未执行。

### 4.2 契约

发布清单的必备项：显示名、npm 版本、模组版本、前端构建成功、打包成功、安装成功、首启真窗口无白屏无崩溃、游戏按 F6 后能连接、至少最小脚本与全量展示脚本能打开推送播放、关闭幂等通过、已知限制已写入发布说明、证据齐全。

发布阻断条件：打包配置里仍有构建机绝对路径；包内出现 token、本机绝对路径或开发日志；安装后首启崩溃或白屏；连接不上或连接后没有预览；关闭幂等未通过；发布说明把 AUI 或未实现能力写成已支持；13-01 仍有 P0 或 P1 的失败或阻塞。

### 4.3 数据形态

版本信息集中在一处，状态栏与关于页读同一份，不硬编码多处。产物文件名由显示名派生：各段用连字符连接，加载器与模组版本段按固定格式排列。AUI 的文件名格式在这一份里冻结，但 14 才产出。

### 4.4 边界

这一份不判定功能是否正确——功能由 13-01 至 13-06 判定，它只判定"能不能发"。反过来，功能全绿也不能绕过这里：包不干净、边界不成立、说明不实，一样不发。

AUI 的一切实现不在本份范围内，包括它的版本号取值、加载器段命名以外的任何内容。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 直接沿用 npm 版本号做显示名 | 显示名就等于版本字段 | 无需维护第二处 | 显示名需要带模组版本与加载器信息，语义不同，硬塞会把版本字段变成复合串 |
| 保留构建机路径，出包前手改 | 每次打包临时改配置 | 改动最小 | 一旦忘记就打出不可复现的包，且日志泄露目录结构 |
| 包内带开发夹具与文档 | 让用户能看示例 | 用户上手快 | 增加体积、泄露内部计划、且夹具本身不是发布物 |
| 已知限制只在发布说明口头提及 | 不上清单，靠沟通 | 省事 | 用户无法核对，事后争议没有依据 |

**本方案的缺点**：

- 五个环节都要手工留证，发布一轮的时间成本高。
- 显示名与 npm 版本分离，需要两处同步维护，容易忘记更新其中一处。
- 只承诺 Windows，用户在其他平台上的期望需要额外沟通。

### 验收要点

- 状态栏、关于页、发布说明、产物文件名使用同一个显示名；npm 版本保持独立。
- 打包配置中不存在构建机绝对路径；打包日志不出现本机私有目录。
- 包内不含计划与设计文档、测试夹具、版本库目录、token、日志、截图、旧产物。
- 渲染进程无 Node 集成；preload 只暴露白名单；文件对话框经主进程；无对外监听与远程调试端口。
- token 不入日志、不入包、不入脚本；关闭或世界退出后不残留；轮换后能重连读取。
- 脚本保存要求 `.json`；资源路径拒绝绝对路径、盘符、网络共享与向上逃逸。
- 安装、首启、连接、关闭幂等四项都有截图或录屏证据。
- 发布说明如实列出全部已知限制，未把 AUI 或未实现能力写成已支持。
- 任一发布阻断条件成立时未产出发布包。
