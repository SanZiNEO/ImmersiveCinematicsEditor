# WebUI 到 Forge/Fabric 真游戏冒烟

> 状态：未实现
> 范围：编辑器编辑脚本到游戏播放再到预览回传的完整链路，在 Forge 与 Fabric 两条加载器上各跑一遍
> 关联：13-01 总账、13-02 黄金脚本、13-05 字幕端到端、13-06 传输与预览硬化

## 一、摘要

这一份要证明一条完整链路真实成立：编辑器里编辑脚本，保存或推送，模组解析并校验，游戏播放，预览帧回传，编辑器里看到真实画面。它既不是"前端能构建"，也不是"菜单能打开"——必须在一个真实 Forge 客户端和一个真实 Fabric 客户端里各跑一遍。两条加载器都通过，这一份才算通过。

## 二、为什么做

### 2.1 问题

编辑器与模组各自都能跑，合起来仍然可能不通。真实项目里最先暴露的是这些：构建通过但客户端一启动就报注册错误；连接显示"已连接"却没有一帧画面；脚本能被编辑器保存，却被模组的解析器拒绝；画面出来了，但那是编辑器本地合成的假预览；游戏退出了，端口和捕获消费者还挂着，下一次启动连不上。

这些问题没有一个能在编辑器内部发现，也没有一个能用构建日志证明。它们只在一个真实客户端、一个真实世界、一次真实播放里现形。

### 2.2 目标

- 证明从编辑器到游戏到回传的六段链路在 Forge 与 Fabric 上都成立。
- 证明预览是游戏真实回传的帧，不是本地合成或旧帧。
- 证明编辑器不写 `version` / `total_duration` 这类不属于目标文档形状的字段。
- 证明断连、重连、世界退出后没有残留（端口、捕获消费者、token、按键）。
- 证明错误路径都有明确提示，不出现"看起来正常其实没工作"的假状态。

### 2.3 非目标

- 不用构建成功代替真游戏；不用本地预览图代替游戏回传帧。
- 不验界面布局与面板行为，那在 13-03。
- 不验协议细节与帧消费实现，那在 13-06；这一份只按结果判定。
- 不引入 AUI 的进程内路径。13 不发布 AUI，AUI 归 14。

## 三、方案

冒烟分六个阶段，每个阶段都是一段可以连续执行的操作。

**启动与连接**——启动客户端进入世界，按 F6 打开 WebUI 服务与预览屏，启动编辑器，观察连接状态、token、Origin 与 schema。8765 只应在进入 WebUI 模式后监听；没有 token 时不应发起无意义的连接，状态栏要说明原因；连接成功后握手回执要带版本、能力与 schema 哈希；能取到当前 schema；状态栏显示固定预览规格；不能出现"已连接"但实际没有预览帧的假状态。

**打开与推送**——打开最小脚本与全量展示脚本，改一个安全字段（比如字幕文本或相机 fov），保存，推送，在游戏侧观察脚本加载。打开不应改写文档；保存产物要能被真实的解析器与校验接口接受；推送后游戏侧加载的是同一份脚本；编辑器不写 `version` 与 `total_duration`；保存失败不关闭窗口且提示可见；重开后脚本字段、轨道、路径、触发器、字幕逐字段不变（内部身份除外）。

**预览出帧**——观察首帧、十秒连续预览、播放暂停切换、seek 到开头中间末尾，以及状态栏里的宽高、帧率、编码器、丢帧与首帧状态。首帧应在合理时间内出现，超时要有明确提示而不是黑屏；有 ffmpeg 时走 H.264，没有时回退 RGBA 且不崩不静默；预览规格固定；暂停时不持续空转补帧，恢复后首帧可用；seek 后画面跟随，不出现长时间旧帧；长时间预览内存不持续增长；统计数字可解释。

**播放控制与真实画面**——播放完整展示脚本，暂停继续，seek 到转场交界前后，观察叠化、morph、字幕、覆盖层、调色、音频与事件，记录最终画面。播放状态要与编辑器显示一致；叠化是 A→B 交界的 crossfade 而不是片段里的字段；`fade` 不被误认为 crossfade；字幕固定白色且位置字号换行正确；覆盖层按 `z_index` 排序、LETTERBOX 在最底层；调色归属正确；音频能播放循环淡入淡出；事件与规则在游戏侧执行，编辑器不假装执行；最终画面不靠编辑器本地合成。

**保存、重开、断连、重连**——保存脚本，关闭编辑器，重开，重新连接，然后断开游戏或关闭服务，再恢复游戏重连，最后世界退出再进入。重开后文档、布局、最近项目、主题应恢复；重连要重新读取 token，旧 token 不残留；断连时未保存内容不清空且状态明确；重连不重复创建预览消费者；单窗口关闭不影响另一个窗口；世界退出后无残留端口、捕获消费者、token 与按键；重复按 F6 或重复关闭不误停游戏播放。

**错误路径**——逐一执行错误 token、无 token、端口占用、脚本语法错误、字段非法、资源缺失、ffmpeg 缺失、首帧超时、游戏崩溃退出。每一项都要有明确提示与可恢复路径：拒绝连接要说清原因，解析错误要定位到位置，字段问题要定位到对象与字段，资源缺失要指出相对路径，没有 ffmpeg 要说明回退与外部音频限制，游戏退出要进入断连态且不丢未保存文档。

## 四、技术细节

### 4.1 核心模型

一次冒烟记录 = 一个加载器 × 一组脚本 × 六个阶段 × 一份证据。加载器维度不可合并：Forge 与 Fabric 各是一份独立记录，一条不可用时整份验收是 `BLOCKED`，不是"另一条通过就算"。

判定规则是：两条加载器都通过，这一份才通过；加载器差异只允许出现在启动与注册层，脚本语义、预览协议、面板行为必须一致。如果某条加载器上出现了语义差异，那是缺陷，不是平台差异。

### 4.2 契约

前置条件：模组版本冻结（当前 0.3.6 或 13 冻结的实际版本）；编辑器版本与模组版本匹配；Forge 与 Fabric 各有一套可启动客户端；游戏版本为当前模组支持版本；优先本地单人世界，多人服务端单独记录；黄金脚本所需图片、视频、音频、LUT、语言表已放到资源目录；预览先在带 ffmpeg 的环境跑 H.264，再在无 ffmpeg 的环境跑 RGBA 回退；8765 未被占用；游戏侧已生成 token 文件且编辑器能读到。

禁止作为证据：构建成功、编辑器本地预览图、mock 的播放状态、一张静态截图假装连续播放、没有环境却写"应该可以"、把旧编辑器行为当目标合同、把 AUI 的进程内路径混进 WebUI 冒烟。

### 4.3 数据形态

每次执行记录：日期、加载器、游戏版本、模组版本、编辑器版本、ffmpeg 有无与路径、脚本文件名与 SHA-256、结果状态、证据路径（截图与录屏、日志片段、脚本 diff）、缺陷的期望与实际与回退轮次。

两条加载器跑同一组脚本：最小脚本与全量展示脚本。启动、F6、token、schema 必跑；打开保存推送必跑；预览至少一条跑 H.264，另一条可跑 RGBA；播放暂停 seek 必跑；叠化、morph、字幕、覆盖层必跑；断连、重连、世界退出必跑。

### 4.4 边界

这一份不判定协议字段与帧消费实现是否正确，只判定结果是否成立；协议层问题回 01 与 03。界面问题回 04～12。关闭幂等的问题在 13-06 硬化后回到本份复验关键路径。

预览规格固定，不提供档位选择；这一点在 13-06 一并收口。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 只跑 Forge | 用一条加载器代表两条 | 省一半时间 | 加载器入口与生命周期不同，Fabric 的问题会被完全漏掉 |
| 只跑最小脚本 | 验一条能加载的脚本就收 | 快 | 组合能力（叠化共存、调色归属、字幕换行）在最小脚本里根本不会触发 |
| 用编辑器本地预览代替游戏画面 | 直接看编辑器里的合成结果 | 不需要启动游戏 | 那是编辑器自己画的，证明不了游戏侧行为 |
| 先发布再补真机验证 | 靠用户反馈发现问题 | 省一轮 | 这条链路的失败模式是数据损坏与无法播放，属于 P0 |

**本方案的缺点**：

- 需要两套可启动客户端与真实世界，环境准备成本高。
- 每个阶段都要保存截图、录屏与日志，执行一轮时间很长。
- 首帧时间、内存增长这类判断依赖观察，没有硬阈值，不同执行者结论可能不同。

### 验收要点

- 8765 只在进入 WebUI 模式后监听；无 token 时不发起连接并说明原因。
- 握手回执带版本、能力与 schema 哈希；不存在"已连接但无帧"的假状态。
- 打开不改写文档；保存产物被真实解析器与校验接口接受；编辑器不写 `version` 与 `total_duration`。
- 有 ffmpeg 走 H.264、无 ffmpeg 回退 RGBA，两条路径都不崩不静默。
- 暂停不空转补帧；seek 后画面跟随；长时间预览内存不持续增长。
- 完整展示脚本连续播放不少于 60 秒（或脚本全长，取较短者），叠化、morph、字幕、覆盖层、调色、音频表现符合合同。
- 断连不清空未保存内容；重连重新读取 token；世界退出后无端口、捕获消费者、token、按键残留。
- 九类错误路径都有明确提示与可恢复路径。
- Forge 与 Fabric 各有一份完整记录；任一缺失时整体为 `BLOCKED`。
