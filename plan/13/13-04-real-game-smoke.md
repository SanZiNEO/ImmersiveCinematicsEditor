# 13-04 WebUI → Forge/Fabric 真游戏冒烟

## 目的

证明一条完整链路真实成立：

```text
编辑器编辑脚本 → 保存/推送 → 模组解析/校验 → 游戏播放 → 预览帧回传 → 编辑器看到真实画面
```

这不是“前端能 build”，也不是“菜单能打开”。它必须在真实 Forge 和真实 Fabric 客户端里各跑一遍。

## 前置

| 项 | 要求 |
|---|---|
| 模组版本 | `ImmersiveCinematics` 0.3.6（或 13 冻结的实际版本） |
| 编辑器版本 | `ImmersiveCinematicsEditor 0.1.0 for IC 0.3.6` |
| 加载器 | Forge 与 Fabric 各一套可启动客户端 |
| 游戏 | 当前模组支持的 Minecraft 版本 |
| 服务端 | 本地单人世界优先；多人服务端单独记录 |
| 资源 | 黄金脚本所需图片/视频/音频/LUT/语言表已放到 `immersive_cinematics/resource/` |
| 预览 | 先在有 ffmpeg 的环境跑 H.264；再在无 ffmpeg 的环境跑 RGBA 回退 |
| 端口 | 8765 未被其他程序占用 |
| token | 游戏侧已生成 token 文件，编辑器能读到 |

## 冒烟路径

### 阶段 1 · 启动与连接

1. 启动游戏客户端，进入世界；
2. 按 F6 打开 WebUI 服务/预览屏（统一入口；AUI 不存在时落到 WebUI）；
3. 启动 Electron 编辑器；
4. 观察连接状态、token、Origin、schema。

必须成立：

- 8765 只在进入 WebUI 模式后监听；
- 无 token 时不发起无意义连接，状态栏显示明确原因；
- 连接成功后 `hello_ack` 有版本、capabilities、schemaHash；
- `schema.get` 能取到当前 schema；
- 编辑器状态栏显示固定预览规格 `1920×1080@60`；
- 不出现“已连接”但实际没有预览帧的假状态。

### 阶段 2 · 打开与推送

1. 打开 `golden/01-minimal-meta-seven-tracks.json`；
2. 打开 `golden/09-full-showcase.json`；
3. 编辑一个安全字段（例如字幕文本、相机 fov）；
4. 保存；
5. 推送脚本；
6. 游戏侧观察脚本加载。

必须成立：

- 打开不改写文档；
- 保存产物能被真实 `ScriptParser` / `script.validate` 接受；
- 推送后游戏侧能加载同一脚本；
- 编辑器不写 `version` / `total_duration`；
- 保存失败不关闭窗口，状态栏/面板可见；
- 脚本字段、轨道、路径、触发器、字幕在重开后逐字段不变（`authoring` / 内部身份除外）。

### 阶段 3 · 预览出帧

1. 观察首帧；
2. 观察 10 秒连续预览；
3. 切换播放/暂停；
4. seek 到 0、1s、中间、末尾；
5. 观察状态栏的宽高/fps/编码器/丢帧/首帧。

必须成立：

- 首帧在合理时间内出现；超时有明确提示，不黑屏假装正常；
- H.264 路径能出帧（有 ffmpeg）；
- 无 ffmpeg 时回退 RGBA，不崩、不静默；
- 预览是 `1920×1080@60` 固定规格；
- 暂停时不持续空转补帧；恢复后首帧可用；
- seek 后画面跟随，不出现长时间旧帧；
- `VideoFrame` 每条路径都释放，长时间预览不持续增长内存；
- 预览统计的 `sent/dropped/inputDropped/encoderDropped` 可解释。

### 阶段 4 · 播放控制与真实画面

1. 播放完整 `09-full-showcase`；
2. 暂停、继续；
3. seek 到转场交界前后；
4. 观察叠化、morph、字幕、覆盖层、调色、音频、事件；
5. 记录最终画面。

必须成立：

- 播放/暂停/stop 与编辑器状态一致；
- 叠化是 A→B 交界的 crossfade，不是片段里加字段；
- `fade` 不被误认为 crossfade；
- 字幕固定白色，位置/字号/换行符合 09-05/12；
- 覆盖层按 `z_index` 排序，LETTERBOX 在最底层；
- ADJUST 与 CAMERA lane 调色归属正确；
- 音频能播放/循环/淡入淡出；
- 事件/规则在游戏侧执行，编辑器不假装执行；
- 最终画面不靠编辑器本地合成。

### 阶段 5 · 保存/重开/断连/重连

1. 保存脚本；
2. 关闭编辑器；
3. 重开编辑器；
4. 重新连接；
5. 断开游戏/关闭服务；
6. 恢复游戏，重连；
7. 世界退出，再进入。

必须成立：

- 重开后文档、布局、最近项目、主题恢复；
- 重新连接后 token 重新读取，旧 token 不残留；
- 断连时未保存内容不清空，状态明确；
- 重连后不重复创建预览消费者；
- 单窗口关闭不影响另一个窗口；
- 世界退出后无残留 8765、捕获消费者、token、按键；
- 重复 F6 / 重复关闭不误停游戏播放（13-06 硬化后复验）。

### 阶段 6 · 错误路径

至少执行：

| 错误 | 期望 |
|---|---|
| 错误 token | 明确拒绝，状态栏可见，不假装连接 |
| 无 token | 不连接；提示先启动 WebUI 服务 |
| 端口占用 | 启动失败明确提示，不静默 |
| 脚本 JSON 语法错误 | parser error，定位到位置 |
| 脚本字段非法 | `script.validate` issue，定位到对象/字段 |
| 资源路径缺失 | 资源检查/游戏日志明确，不白屏 |
| ffmpeg 缺失 | H.264 回退 RGBA；外部音频格式明确提示 |
| 预览首帧超时 | 明确提示；可重试；不显示假帧 |
| 游戏崩溃/退出 | 编辑器进入断连态，可重连；不丢未保存文档 |

## Forge / Fabric 双跑

两条加载器路径都要跑同一组最小 + 完整脚本：

| 项 | Forge | Fabric |
|---|---|---|
| 启动、F6、token、schema | 必跑 | 必跑 |
| 打开/保存/推送 | 必跑 | 必跑 |
| 预览 H.264 / RGBA | 至少一条跑 H.264；另一条可跑 RGBA | 同左 |
| 播放/暂停/seek | 必跑 | 必跑 |
| 叠化/morph/字幕/覆盖层 | 必跑 | 必跑 |
| 断连/重连/世界退出 | 必跑 | 必跑 |

判定：

- 两条加载器都 `PASS`，13-04 才 `PASS`；
- 一条不可用 => `BLOCKED`，不是“另一条通过就算”。
- 加载器差异只允许出现在启动/注册层；脚本语义、预览协议、面板行为必须一致。

## 禁止

- 用 `npm run build` 成功代替真游戏；
- 用编辑器本地预览图代替游戏回传帧；
- 用 mock 的 `playback.state` 假装播放；
- 用一张静态截图假装连续播放；
- 没有 Forge/Fabric 环境却写“应该可以”；
- 把旧编辑器行为当目标合同；
- 把 AUI 的进程内路径混进 WebUI 冒烟。

## 通过标准

- 阶段 1～6 在 Forge 与 Fabric 各跑通；
- 完整展示脚本能连续播放不少于 60 秒（或脚本全长，取较短者）；
- 预览无长时间黑屏/冻结/内存持续增长；
- 错误路径都有明确提示；
- 断连/重连/世界退出无残留；
- 所有证据进入 13-01 执行表。
