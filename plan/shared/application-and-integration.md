# 应用常见能力与元能力整合边界

## 一、摘要

本页把用户补充明确为必做：WebUI 具有正常桌面应用的主题、面板缩放/移动、布局恢复等能力；编辑器除字段编辑外，还整合模组元能力生成批量内容。字幕导入和批量管理是完整必做工作流，不是可选建议。

## 二、为什么做

仅给模组每个字段画表单，会把大量重复劳动留给作者；仅做固定布局，又不适合预览、关键帧、行为管理等不同任务。目标是提高制作效率而不扩大运行时格式。非目标是让模组解析字幕工程文件，或把编辑器变为通用音视频制作软件。

## 三、方案

### 必做 A：应用级工作台（05 轮）

- 深色/浅色/跟随系统主题；主题独立于脚本，与游戏画面无关。
- 面板边界拖动缩放、位置拖动重排、停靠/标签分组、显示隐藏和一键恢复默认。拖动不能丢失面板或把面板移出可恢复范围。
- 按工作流保存/切换布局（例如镜头、字幕、规则）；重启恢复尺寸、面板位置、可见性和选中标签；不同屏幕/DPI下做安全校正。
- 常规文件/编辑/视图/帮助命令入口、最近项目、明确的连接/离线状态、可查快捷键、中文/英文切换、确认式未保存退出、局部错误和恢复入口。已有保存/撤销/键盘规则必须整合，不做第二套。
- Electron 窗口最小化/最大化/恢复/关闭与窗口位置保存；AUI 宿主不展示不成立的系统窗口按钮，仍保留面板布局语义。
- 偏好与布局单独持久化；损坏时可恢复默认，不读写任意文件；自动恢复草稿不得覆盖模组脚本。
- 按[C17效果控件工作区](effect-controls-workspace.md)同时提供片段效果控件与独立快捷属性宿主；前者多对象/属性组共用局部标尺、独立节点，后者复用同值控件/命令。主轴只编排片段，不展开对象行。05完成宿主/布局，06完成内容、局部视口/行同步/节点交互，两轮各自完整闭环，不新增运行时效果层。

任务见 05 下 `20-ThemeService.md` 至 `23-PreferencesAndWindowState.md`，与该轮原任务共同验收。

### 必做 B：字幕整合（12 轮）

默认完整实现 SRT 与 WebVTT 的文本/时间导入子集；支持边界在导入器任务里明确。复杂 ASS 样式、视频烧录、自动语音识别不在本轮隐含加入。对不支持的格式/样式必须列诊断，不能静默丢信息后说完整支持。

工作流：选择文件 → 解析为编辑器 cue 中间模型 → 表格校对/筛选/多选 → 时间偏移/比例、样式预设、批量改文本与排序/分拆合并 → 显示生成差异 → 编译为标准 OVERLAY/subtitle 片段 → 主模组校验 → 一次提交 → 游戏原始画面验证。

每条字幕默认一个标准片段，时长为 end-start，text 是 value-only；位置信息、字号倍数、缩放、锚点、opacity 和层序只使用当前 schema 实际可用字段。重叠字幕按运行时单轨只激活一个片段的事实分配不同 OVERLAY 轨道，不能把重叠放同轨后祈祷都显示。导入来源/cue ID/批次/模板绑定是编辑器元数据，不写未知脚本键。

批量修改只作用所选 cue 或明确选定批次；重导入先预览差异和手工修改冲突，不重复插入同一批、也不覆盖非本批创建的内容。保存/关闭/重开后仍能从编辑器 sidecar 继续管理；sidecar 丢失时已有标准脚本仍可播放，导入为普通字幕片段后可重新编组，不能因管理元数据缺失就破坏脚本。

任务见 12 下 `20-SubtitleImportService.md` 至 `23-SubtitleBatchPanel.md`。

### 其他整合能力的边界例子（仅建议，不扩为必做）

| 效率工作流 | 编辑器可整合的元能力 | 必须保持的边界 |
|---|---|---|
| 对白/旁白段落生成字幕和音轨 | 文本、OVERLAY、AUDIO、时间参数 | 没有语音合成能力时不冒充生成真实配音 |
| 镜头组/环绕/推拉效果包 | CAMERA、路径、朝向、规则和对象动画 | 展开为标准字段；不新增运行时 orbit_template 字段 |
| 双语字幕/标题条/人物名牌 | 多条字幕片段、语言资源、几何与透明度 | 不支持的字体/描边/排版不能只在浏览器好看 |
| 批量转场与音量包络 | opacity/镜头连续性/音量对象 | 保留原片段内容与引用，不把全部轨道时间强行同步 |
| 调色预设/LUT对照 | ADJUST、LUT引用、真实捕获帧 | 不把编辑器主题当脚本调色，不承诺浏览器还原游戏光影 |
| 按触发链创建脚本包骨架 | 项目文件夹、触发条件与引用 | 受控事务、真实校验；不是任意图连线变成有效触发 |

## 四、技术细节

应用偏好/布局状态、字幕 cue/批次中间模型、最终运行脚本三者分层。运行时只认识最后一层。编译器根据 C01 schema 能力检查后，使用 C04 文档命令和 C11 模板展开事务；不直接触碰文件系统，不绕过校验保存。WebUI 外部文件由 Electron 最小权限端口选择读取；Forge 文件选择由宿主受控服务适配，同语义导入模型复用。

源码事实：App.vue（22–88、289–315）已有固定几列的拖动尺寸但不是完整停靠布局；electron/main.cjs（22–36、44–56）有基础窗口控制。TrackSchemas.overlayObjects（398–456）和 SubtitleLayer.render（55–100）决定实际字幕字段/渲染；OverlayTrackPlayer.findActiveClip（234–239）是重叠分轨的依据。

## 五、为什么不选别的

不让模组新增 SRT/ASS 播放器，不向脚本写字幕工程字段，不用前端 CSS 效果冒充游戏支持。也不把主题/可移动面板降为建议，因为用户已经明确要求。代价是编辑器需要维护安全的应用状态存储和可恢复的字幕中间模型；两者与脚本分离后不会增加播放器复杂度。
