# 宿主范围：WebUI 不受 Fabric AUI 故障影响

## 用户确认的精确边界

- **WebUI 分支**承载完整编辑器功能，完成标准脚本生成、元能力整合/模板、主题与可调整工作台、字幕导入与批量管理。它通过主模组既有服务通信；没有 ApricityUI 前置。
- WebUI 对接主模组的 **Forge 与 Fabric** 均属正常目标。不能因游戏内 AUI 的问题禁用 WebUI 的 Fabric 连接或少做其功能。主模组接口有真实加载器差异时按实际能力核对，不凭 AUI 故障推断不支持。
- **1.20.1 分支游戏内编辑器**需要 AUI 前置；当前是其中 **Fabric AUI 附属模组链路**有问题。因此游戏内先完成 Forge，暂不修 Fabric AUI 适配。
- 两分支共用同一份计划主体、标准文档、schema/消息和生成语义；宿主不同不代表各造一套字段模型。

## 对全部轮次的约束

本文细化所有任务里简称“Fabric 暂停／不做 Fabric／Fabric 不纳入验收”的措辞：它们**只准指游戏内 Fabric AUI 宿主适配**，不得扩为主模组 Fabric 或 WebUI 的 Fabric 通路。直接出现相反措辞时必须修正文档，不靠执行者猜测。

顺序见[implementation-order.md](implementation-order.md)：先01–12 WebUI，13 WebUI完整打磨验收；通过后才14 AUI迁移，先Forge。01–13不要求AUI界面、环境、进程内GPU接口或双宿主验证。14落实其真实前置，不能假接口通过；Fabric+AUI仅该迁移方向暂缓。

## 与应用/整合的关系

主题、窗口、面板位置/大小、布局恢复以及字幕导入/批次/编译首先完整落实在WebUI；游戏内Forge复用这些编辑语义，窗口控制等不适用项按宿主说明。不存在“WebUI只定义合同、等AUI完成再实现编辑器”的阶段。
