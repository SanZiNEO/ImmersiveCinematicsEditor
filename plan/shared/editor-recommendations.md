# 编辑器额外建议与元能力整合例子

> 本页均为非必做建议，不能降低已明确需求。状态：未实现、未排期。

## 一、摘要

在14轮必做之外列出可独立评估的效率增强。编辑器整合模组元能力，不扩展运行时脚本格式；每项实施前另建类级任务与验收，不顺手夹进主轮次。

## 二、为什么单列

**已是必做，不得放入建议延期**：深/浅/系统主题、面板移动缩放/停靠、布局预设保存恢复、最近项目/双语/IME/基础草稿恢复（05.20–23）；SRT/VTT导入、字幕批量与来源/重导入冲突、schema编译（12.20–23）；纯数据模板（12.12）；editor统一包/双模式总开关（独立editor-package-modes设计）。WebUI对接Forge/Fabric完整，只有游戏内Fabric+AUI适配暂缓。
统一片段效果控件、多个对象组同时可见、独立属性节点、局部标尺/轴外、独立快捷属性及主轴不画节点均已是[C17](effect-controls-workspace.md)必做，不是本页建议，也不能作为“高级编辑以后再加”延期。

以下建议不作为主轮未完成的借口，也不宣称当前不能实现的能力已存在。

## 三、建议清单

| 建议 | 价值 | 代价/风险 | 依赖与边界 |
|---|---|---|---|
| 可搜索命令面板 | 功能多时减少记忆成本 | 命令排序、焦点和快捷键冲突 | 复用05应用命令，不做第二套执行入口 |
| 最近项目收藏/分组 | 大包快速导航 | 状态持久化与失效路径 | 基础最近项目已必做；本项只增加收藏/组织 |
| 布局预设导入导出 | 分享镜头/字幕工作台 | 版本、panelId、尺寸兼容 | 基础布局/预设已必做；只导出受控布局，不带token/机器绝对路径 |
| 草稿多版本历史 | 对比不同创作尝试 | 存储上限、恢复与清理 | 基础防丢恢复已必做，不自动覆盖模组文件 |
| 多文档标签页 | 跨脚本对照 | 每文档历史/脏标记/连接状态 | 单独评审C03/C04，项目关系图仍独立 |
| 结构化变更审阅 | 审核批量生成或重命名 | 身份映射和diff语义 | 展示标准文档差异，不暗加协同/三方合并 |
| 高对比度/色弱专用主题 | 特定视觉需求 | 需要完整状态与轨道色复验 | 深浅主题已必做，本项是额外专门方案 |
| 英文术语审校/更多语言 | 更自然和广泛的界面 | 译名维护 | 基础en_us已必做，不能以审校未做省略英文UI |

### 元能力整合的进一步例子

| 编辑器工作流 | 可复用元能力 | 不越过的边界 |
|---|---|---|
| 对白/旁白时间表生成字幕与声音引用 | OVERLAY/subtitle、AUDIO、对象时间 | 没有配音文件不假造语音合成结果 |
| 双语字幕、标题条、人物名牌 | 多轨字幕、语言资源、位置/透明度 | 只输出当前schema与消费者支持的字形/参数；不把CSS样式当游戏能力 |
| 成组镜头/环绕/推拉效果包 | CAMERA、paths、朝向、数学模型 | 模板展开为标准对象/路径，不写orbit_template等新运行时字段 |
| 批量转场/音量包络 | 片段窗口、opacity/volume对象 | 保留原引用与异步时间，不强制同步所有属性 |
| 调色方案对照 | ADJUST、LUT引用、真实捕获帧 | 不承诺浏览器完全还原游戏光影，不把编辑器主题当脚本调色 |
| 按触发链搭脚本包 | 文件夹、真实前置条件和引用 | 通过受控事务/校验，不任意画线就生成有效触发 |

## 四、准入条件

1. 产物仍是主模组可解析播放的标准脚本，元信息放编辑器sidecar。
2. 新协议确有必要时先登记共享合同和责任类；不复制运行时、不给renderer任意文件/命令权限。
3. 正常/边界/失败、撤销与真实游戏结果都有验收；界面看起来有数据不算通过。
4. 需要波形/缩略图/实时多画面等数据源时先证明真实来源；不存在就明确能力缺口，不用随机折线/截图假装实现。
5. 两宿主差异可解释，不把未实证AUI能力当作永久缺失；新增增强不能挤掉WebUI完整功能。

## 五、为什么不选别的

不把完整剪辑软件的媒体转码、代理、烧录字幕、视频导出、云协作和插件平台隐含加入。它们改变产品边界或工程规模，不是“常见编辑器功能”四个字自动授权的范围。建议的代价是需要独立决策和任务书，但主轮次能有清楚出口。
