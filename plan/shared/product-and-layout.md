# 产品与分区主体

## 一、摘要

新版是把作者的镜头、画面、声音和触发意图翻译为固定格式脚本的工具。剪辑软件只提供时间轴、效果控件、资源组织的交互参照；输出不是视频，预览不是编辑器渲染。两宿主采用同一信息架构，游戏内受视口和 AUI 能力限制时允许折叠，不允许功能语义缩水。

## 二、为什么做

目标是让作者先找项目关系，再集中处理一个脚本；每个模组功能能找到唯一的主要面板。非目标是复刻 PR 的素材、渲染、编码导出或插件系统。旧左侧脚本列表/JSON 展示不再常驻。诊断需要源码时可以提供只读定位/复制，不得换个名字复活旧左栏。

## 三、方案

### 3.1 项目入口页

首次进入和返回项目时显示关系图：文件夹为分类容器，脚本为节点，边反映真实触发前置/后续关系。不是显示脚本 JSON 的旧树。

- 悬停或键盘聚焦节点，展示名称、ID、相对路径/文件夹、维度、轨道与时长摘要、触发条件摘要、入出关系、保存/校验状态；加载中的信息不能伪造为 0。
- 点击打开脚本进入文档工作区。未保存文档切换先执行明确的保存/放弃/取消选择；取消保持原文档。
- 节点拖动只改布局；移动到文件夹是脚本文件管理事务；维护依赖是脚本条件写事务。三者有不同命令、撤销和失败回执，不能同一拖拽隐式全做。
- 图上不提供轨道、片段、关键帧、效果参数的编辑器；依赖边的受控表单属于“关系维护”，不能顺便变成完整脚本表单。
- 环、缺失目标、无法解析文件和外部关系仍显示并可定位；不能因布局失败隐藏脚本。

### 3.2 文档工作区

| 区域 | 内容 | 不放什么 |
|---|---|---|
| 顶栏/文档命令 | 返回关系图、当前文档、脏标记、新建/保存/校验、连接状态 | 常驻全项目列表 |
| 主要预览区 | 游戏真实画面、播放状态、飞控/取景入口、画面源/传输状态 | JS 世界渲染或离线假游戏画面 |
| 主时间轴 | 七类及注册扩展轨道、片段编排/起止/时长、全局播放头、工作区标记/吸附、循环 | 属性行、关键帧/汇总节点、对象展开、属性曲线 |
| 片段效果控件clip.effects | 当前片段所有适用对象/功能组，左参数右独立节点，共用片段局部标尺，多个组可同时展开 | 单属性独占页、主轴子行、任意效果链、全项目浏览器 |
| 快捷属性selection.properties | 当前片段/组/叶子/节点的常用参数与效果控件定位；同一值组件/命令 | 第二套节点轴/可编辑副本，把效果控件缩回旧窄栏 |
| 曲线/路径页 | 数学模型、时间映射、路径几何、点源与方向辅助 | 另一套运行时采样真值 |
| 行为页 | 触发器、规则/绑定/动作/释放、事实诊断、分支/出口、事件内容 | 依赖关系的任意自由连线 |
| 资源/模板抽屉 | 游戏注册资源、文件引用、语言文本、LUT/音视频、模板参数/产物差异 | 通用素材剪辑库与视频成片导出 |
| 诊断抽屉 | parser/validator 返回的问题、路径跳转、不可编辑原因 | 静默吞掉未知对象 |
| 底部状态区 | 宿主/主模组能力、播放与预览分离状态、错误提示 | 持续覆盖游戏预览的调试信息 |

### 3.3 统一片段效果控件与独立快捷属性

完整定义见[效果控件工作区](effect-controls-workspace.md)。借用户截图的职责组织而非旧组件：效果控件可位于预览旁，右侧快捷属性独立，下方主时间轴只编排片段。两面板均可停靠且可同时可见；小窗用折叠/标签/受控滚动保证可达，不退回单属性独占页或主轴对象行。

- 一个片段的多个处理组与叶子可同时展开，左侧直接编辑适用值，右侧对齐各属性自己的关键帧组。选择yaw不隐藏position等已展开组。
- 一功能组一块，叶子成行；组仅UI，不写新运行时对象或组帧。mode/interp与可添加/移除/开关等能力仍由schema/parser决定，不复制PR效果链。
- 同一片段的属性共享局部标尺/播放头与行布局，但各自节点时间独立；主轴全局视口与06局部视口分开。06实际完成局部缩放、行命中、虚拟化、节点拖动及轴外可达，不反派给05。
- 秒表控制动画启停，菱形表示当前时刻节点，前后按钮只导航；VALUE无动画入口，事件按原记录组件。跨属性不同时间/同时间都不自动补帧或合并。
- 快捷属性仅复用同一Selection、目标解析与值/片段命令；动画已有帧时不能只改无效value后宣称动画已改变。两处草稿/回显不串写。
- 轴外节点保留并仅在效果控件扩展局部显示；不拉宽主轴片段或改脚本时长。标准保存不写组/折叠/视口/选区字段。

### 3.4 各功能归属

脚本meta的screen_layers/输入/并播/跳过/循环仍在脚本属性，不与快捷属性同名混用。CAMERA、OVERLAY、LETTERBOX、AUDIO、ADJUST和EVENT/MOD_EVENT按真实schema在片段效果控件中组成相应功能组；07位置/路径/数学、08转场/lane、09合成、10音频/LUT、11事件专用内容仍由原责任组件实现并与同一上下文连接，不一叶一个独占面板。脚本级clips/rules/rule_bindings/paths有原结构/行为/路径入口；独立片段可明确打开效果控件，但不伪造主轴片段。定制表见共享工作区§3.4。

### 3.5 可调整工作台与整合工作流

WebUI必须有dark/light/system主题、组件缩放/移动/停靠、布局保存/恢复默认、偏好/窗口与草稿恢复；见05.20–23。各面板位置可变，但信息职责不变，不恢复旧左侧常驻脚本列。

编辑器还把元能力整合成批量制作流程：字幕导入向导与可停靠批量面板位于资源/模板工作流，支持外部文件→cue校对→批量时间/文本/样式→schema编译→标准脚本，见12.20–23。模组只负责播放生成的OVERLAY/subtitle，不解析字幕工程；其他扩展示例及边界见 [application-and-integration.md](application-and-integration.md)。

## 四、技术细节

现有承载点：`EDITOR:src/App.vue`（顶层页面与快捷键）、`components/ScriptDock.vue`/`ScriptList.vue`/`ScriptContent.vue`（旧常驻导航与内容）、`ScriptGraph.vue`（图）、`Timeline.vue`（时间轴）、`PropertyPanel.vue`/`ClipPanel.vue`/`KeyframePanel.vue`（旧属性面板）。这里只界定职责，不宣称这些类已按新版模型实现。重构和删除必须迁移全部调用方，不能平行挂一份新版组件。

只有宿主层知道 Electron、WebSocket、AUI 和游戏线程；文档/命令/模板不知道网络或渲染纹理。只有主模组回答“脚本实际怎样播放”；前端曲线图是参数编辑辅助，动态世界结果要看游戏。

## 五、为什么不选别的

| 选择 | 未采用原因 |
|---|---|
| 最左栏继续列脚本 | 用户明确取消，且挤占预览与效果控件空间 |
| 图内直接编辑轨道/关键帧 | 破坏入口与文档工作区边界，关系图负担过重 |
| 所有字段自动塞进一张长表 | 无法表达异步时间、结构绑定、条件依赖与跨片段引用 |
| 完全复制 PR | PR 操作视频素材，本项目操作游戏固定脚本；不能照搬不成立的功能 |

代价是需要分离项目状态和文档状态，并为缩小的游戏窗口提供抽屉/单面板模式；这是布局适配，不是删功能。
