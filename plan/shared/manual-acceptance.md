# 人工使用验收规约

> 用户明确要求：无需自动化测试，测试验收由人工实际使用直接发现问题。适用于本计划全部轮次。

## 一、摘要

不为本计划建设单元测试、集成测试、端到端自动化、CI测试流水线或测试脚本。每个任务以真实界面和游戏中的人工操作验证正常、边界、错误、撤销/恢复及保存重载行为，发现问题回到责任类修复后再人工复验。

## 二、为什么做

用户希望先把WebUI做完整、通过实际使用打磨，再迁移AUI。自动化测试工程不是本任务的交付项，也不作为轮次完成门槛。人工验收必须具体，不能简化成“能运行”或“看起来正常”。

## 三、验收形式

每个任务给出：准备数据/环境、操作步骤、预期表现、异常操作、实际结果与问题位置。所谓正例/反例、黄金脚本、回归场景都指人工使用的场景和示例脚本，不要求写测试代码、断言框架或模拟环境。

| 项目 | 人工如何检查 |
|---|---|
| 脚本格式 | 在界面编辑、保存并重载，查看模组正常校验/解析反馈，实际播放 |
| 异步关键帧 | 在统一效果控件同时展开多个对象组，错开属性节点时间，单属性修改/撤销/轴外定位正确；换选属性不隐藏其他已展开组 |
| 项目关系 | 在图中移动文件夹/维护依赖，重开确认文件和真实触发关系一致 |
| 应用能力 | 实际切主题、拖动缩放停靠面板、重启恢复、IME输入与未保存退出 |
| 字幕 | 选择真实SRT/VTT、批量修改/生成/保存、游戏观看，手改后重导入检查冲突 |
| 错误与恢复 | 输入非法值、断连、缺资源、取消操作、保存失败，观察诊断/草稿/事务是否正确 |
| AUI迁移 | 仅13 WebUI完整通过后，在14实际操作Forge+AUI并与已稳定WebUI行为对照 |
| 主轴/效果/快捷属性分工 | 100+属性片段不增加主轴对象行/节点；效果控件左参数右独立节点，快捷属性独立同值回显；局部/全局视口分开、两面板可同时停靠 |

## 四、边界

模组现有script.validate、parser、资源解析和播放是产品运行路径，应当人工使用并观察其真实反馈；它们不是要新增的自动化测试。正常构建/启动用于人工使用，也不是测试框架。可以复制标准示例脚本作为人工场景，不为检查源码字符串、接线或模拟回声新增测试。

本次任务只交付计划文档，不改代码、不运行编辑器/游戏；文档链接/目录/来源的静态核对不代表产品行为已验收。未来执行者只能报告自己真正操作过的结果，没用过的不能填通过。

界面验收先读[效果控件工作区](effect-controls-workspace.md)§4.5并执行其中硬场景：主时间轴无任何关键帧/汇总点，效果控件多组同时可见，轴外节点仅扩展局部查看范围，快捷属性不另建节点轴。模组定制组、字段模式/权限和独立片段定位同样实际操作；不把截图模仿、单属性页或主轴子行当作通过。

## 五、为什么不选别的

不以测试数量、自动断言或CI变绿代替用户实际使用，也不把人工验收写成不明确的“自行测试”。代价是每轮需要真实操作与问题复验，但符合用户指定的打磨方式。
