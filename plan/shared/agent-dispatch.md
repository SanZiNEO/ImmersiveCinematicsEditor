# DeepSeek v4.1 Flash 主代理 → v4.1 Flash 子代理执行规约

## 一、摘要

主代理负责合同、分轮集成和验收；子代理一次接收一份自包含任务书，在一个会话里完成自己的闭环。不得靠主代理中途插入消息补需求、换目标或提醒还缺一半。本文是派单合同，不要求把整份模组代码塞进一个提示词。

## 二、为什么做

只说“按 Z 做编辑器”“完善异步关键帧”会让执行者沿旧模型工作。每单必须同时给目标、源码证据、明确写入集合、依赖产物、输入输出和验收；执行者无需记住主代理另一段聊天。非目标是让子代理自行重拆总体轮次、决定改变脚本格式或扩大到 Fabric 修复。

## 三、方案

### 3.1 主代理开始当前轮之前

1. 首先读shared/implementation-order.md：01–12仅WebUI完整建设、13仅WebUI打磨全验、通过后14才迁移Forge AUI。再读总纲/共享合同/应用与字幕/统一editor包/当前轮全部任务，不把未来AUI承载段当同步开发指令。
2. 确认前轮出口已通过。若缺公共接口、schema 或黄金脚本，当前轮保持阻塞；不要派 UI 工作假装前置已经存在。
3. 对任务建立读集合、写集合、合同 ID、依赖表。共享 types/store/operations 的修改先由一个集成所有者完成并冻结；多个子代理不得同时修改这些文件。
4. 为每份独立切片复制下列完整任务书，填具体文件，不留尖括号。派发前用文末检查表验完整性。
5. 同一轮只并行无共享写入、无未冻结合同依赖的任务；有依赖顺序的分批，不靠会话消息临时协调接口。

### 3.3 不插消息的会话纪律

- 派发之后主代理不在该会话追加需求、不改变目标、不用“顺便再做”补遗漏。主代理继续处理自己的独立切片。
- 子代理发现合同缺失或源码与计划冲突：先完成不依赖该缺口的可达部分，在回执中列具体类/符号/矛盾和所需决策；不得猜接口。
- 主代理收到回执后做集成判断。若需要新信息，结束该切片，形成新的完整修订单再开新会话；不得把多轮补丁聊天当成同一单。
- 真正安全风险可停止操作，但停止不等于允许扩写需求。

## 四、技术细节

### 4.1 推荐派发粒度

一单 = 一个明确类/组件或一组输入输出不可分的小模块，加自己的行为验收。不要一单包“整个镜头系统”；也不要把同一个原子编辑命令拆成三代理分别写类型/实现/调用者。文件相同即有写冲突，不因修改行不同就默认安全。

主代理保留：共享合同裁决、全调用方迁移整合、真实 parser/schema 对账、宿主能力门禁和轮次出口。子代理无权通过删验收场景、把必做标为建议或延期来关闭任务。

### 4.2 完成证据最小集合

| 内容 | 必须提供 | 不接受 |
|---|---|---|
| 行为 | 输入/操作/可观察结果 | “已实现全部功能” |
| 数据 | 前后结构、关键引用与时间单位 | 截图里看起来有节点 |
| 真值 | parser/validator 与游戏实际结果 | 编辑器自写校验器说通过 |
| 错误 | 回执、保留状态、资源/事务回滚 | catch 后什么都不做 |
| 验证 | 实际命令/日志或人工步骤观察 | 没跑却填通过 |
| 完成 | 本单每项约束均闭合 | TODO、后续再补、假 fallback |

### 4.3 轮次清零

每轮逐项清零；01–12的完成只验证WebUI与真实游戏，不依赖AUI。13全量验证WebUI→Forge/Fabric并打磨完成，之后才启动14迁移Forge+AUI。未来Fabric+AUI暂缓，不能影响WebUI当前功能。

## 五、为什么不选别的

不让一个子代理吞下整套计划，也不反复中途补充提示：前者容易丢约束，后者容易覆盖原目标。自包含任务书增加主代理派发前的准备，但让目标、证据和完成条件能在一个会话闭环。
