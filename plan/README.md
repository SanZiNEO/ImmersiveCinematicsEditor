## 编辑器原则

以下是编辑器的长期原则，不随轮次变化；每条都是实现与验收的判据。

### 1. 编辑器是什么

编辑器把作者的镜头、画面、声音和触发意图翻译成固定格式脚本。它的输出是脚本，不是视频；预览显示的是游戏产生的真实画面，不是编辑器自己的渲染。功能取舍以「是否让脚本更准确地表达作者意图」为准。

### 2. 规则以模组为权威，文件由编辑器自己读写

字段定义、schema 形状、校验规则与播放行为都由主模组回答：编辑器不定义脚本格式，不复制游戏渲染或播放算法。需要确认规则时，读主模组源码或调用它提供的接口；编辑器侧的目录与自检只用于提前暴露错误。

但**「规则问模组」不等于「文件经模组」**。工作区是游戏根目录下的 `immersive_cinematics/`（`scripts/` 放脚本、`resource/` 放资源），编辑器直接读写这里的文件：

- 读：一次目录扫描拿到路径清单，逐个解析 JSON，按需增量（只重读 mtime 变化的文件）；
- 写：直接写 `scripts/*.json`，原子写（tmp + rename）；
- 不经过模组的 WebSocket 通道，也不受游戏是否运行影响。

模组只在这些地方出现：**推送脚本给游戏播放、驱动预览画面、查询字段目录**。除此之外编辑器不需要模组。

### 3. 模组只提供元能力，编辑器负责组合与简化创造

模组提供字段、公式、播放控制这类元能力，模板展开、字幕批量、路径生成器等组合能力由编辑器实现。这些能力只写模组已声明的标准字段，不新增运行时字段，也不引入只有编辑器认识的脚本键。简化的是创作流程，不是脚本格式。

### 4. 编辑器只是固定格式的脚本生成器

写盘内容只有模组认识的 `objects` / `paths` / 四类脚本级集合。编辑器的布局、选区、视口、模板参数、导入来源等元数据保留在编辑器侧，不写进脚本。脚本文件因此能被模组与其他工具独立读取。

### 5. 先 WebUI 完整打磨并验收，再迁移 AUI

WebUI 是功能与交互的验收场：交互、预览、错误路径都在这里跑通并留下证据。AUI 只做迁移，不承担功能探索；两条线并行会让同一功能出现两套行为，因此不双线开发。

### 6. 项目入口是关系图

打开项目先看到脚本之间的关系图，从这里管理脚本与引用。打开具体脚本才进入文档工作区，时间轴与属性面板在这一层展开。主时间轴只编排片段，不展开属性行；属性编辑留在独立面板。

### 7. 统一片段效果控件 + 独立快捷属性

片段效果控件让多组效果同时可见，每组有独立的属性节点，共用一条局部标尺。快捷属性与完整属性使用同一套 Selection、命令与值控件，不维护第二套编辑通路。同一处修改因此只有一个撤销记录、一种校验路径。

### 8. 所有编辑走同一文档命令与撤销

界面上的每次修改都落到同一个文档命令层，并由同一套撤销栈记录。序列化保持无损，读入再写出不丢字段与顺序。保存前调用真实的 `script.validate`；外部改动不自动覆盖，冲突交由作者决定。

### 9. 只有宿主层知道 Electron / WebSocket / AUI / 游戏线程

文档、命令、模板只依赖抽象接口，不知道 Electron、WebSocket、AUI 或游戏线程的存在。网络重连、线程切换与渲染纹理由宿主层处理。同一套文档逻辑因此能在 WebUI、桌面壳与游戏内 AUI 复用。

### 10. 编辑器 UI 不进入捕获画面

预览只显示游戏产生的真实画面，编辑器面板、标尺、选中框都不进入捕获结果。捕获链路以游戏帧为准，避免把工具界面误当成作品内容。导出与预览因此看到的是同一份画面。

### 11. 完成定义

一项功能只有同时具备真实能力、消费者可见的错误路径和实际证据才算完成。类壳、空面板、占位待办、演示数据、假回执都不算完成。验收时按真实入口操作，用真实脚本与真实错误复现，留下可复查的记录。
