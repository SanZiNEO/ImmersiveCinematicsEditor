# 路径时间映射

> 状态：未实现
> 范围：每条路径条目的 `timing` 编辑与校验
> 关联：07-05 路径集合、07-06 几何表单、07-10 路径预览

## 一、摘要

一条路径声明了形状之后，还需要声明「时间怎么沿形状推进」。`timing` 就是这个映射：把路径区间内的局部时间归一化成 `t`，再映射成沿路径的弧长进度 `s`。线性表示匀速，关键帧表示作者手绘的节奏——中途暂停、突然加速、瞬时跳变都能表达。关键约束是：`timing` 只影响推进，绝不改变几何形状。当前状态：未实现。

## 二、为什么做

### 2.1 问题

- 匀速沿曲线走不一定好看。作者想要「起手慢、中段快、结尾停一下」，现在没有任何表达手段。
- 想在某一段让相机停住，只能靠加密关键帧实现，几何和节奏被绑在一起，改形状就得重调节奏。
- 手写 `timing.points` 容易犯三类错：首末点不是 `(0,0)` 和 `(1,1)`、`t` 或 `s` 递减、数值超出 `[0,1]`。这些错误在运行期表现为路径乱跳，很难定位。
- 作者不清楚「改 timing 会不会动形状」，于是不敢调。

### 2.2 目标

- 两种模式：线性（省略即线性）与关键帧；切换有明确语义，可撤销。
- 关键帧模式下首末点固定、中间点可增删改；`t`/`s` 的单调与范围在本地校验并定位到具体字段。
- 相等 `t` 允许（形成跳变），相等 `s` 允许（形成暂停），两者都不是错误。
- 明确表达「改 timing 不改几何」。

### 2.3 非目标

- 不改 `geometry` 的任何参数，也不改 `from/to`。
- 不在 `s(t)` 图上直接拖点改值（避免与路径预览的手势冲突）。
- 不支持 `linear`/`keyframes` 之外的 timing 类型。
- 不自动修复非法点表，不静默截断超限点数。

## 三、方案

时间映射区在路径条目编辑器内，两种模式二选一。线性是默认，`timing` 省略或写 `{type:'linear'}` 等价；界面显示「0→1 匀速弧长」，不显示点表。关键帧模式显示一张点表：首末两行固定、不可删除、不可改值；中间行可增删、可改 `t`/`s`、可上下移动；新增时默认取当前行与下一行的中点并线性插值 `t`/`s`。

点表按 `t` 稳定排序，相同 `t` 保持添加顺序、后值生效。删除中间点不重排首末。「按弧长复位」把中间点的 `s` 改成与 `t` 相同，恢复线性节奏但保留作者画的 `t`。数值输入显示三位小数但底层保存原值，步进按千分之一。

`s(t)` 预览是一张只读小图：横轴 `t`、纵轴 `s`，画折线与点；相等 `t` 画竖线，相等 `s` 画水平线。它只反映节奏，不画几何——几何预览是另一块。不在图上拖点，改动一律走点表输入。

模式切换的语义：从关键帧切线性要确认「删除中间点」，提交后 `points` 从文档移除，一次撤销可恢复；从线性切关键帧自动生成 `(0,0)` 和 `(1,1)` 两行，中间为空。切换几何类型不清 `timing`；改 `from/to` 也不清 `timing`，只是 `t` 重新归一化到新长度，`s(t)` 形状不变。

## 四、技术细节

### 4.1 核心模型

求值链是三步：先由路径条目自己的 `from/to` 把片段局部时间归一化成 `u`（不是整段脚本时间），再由 `timing` 把 `u` 映射成弧长进度 `s`，最后 `s` 交给几何做弧长反解得到点。线性时 `s` 就等于 `u`；关键帧时在相邻 `(t,s)` 之间线性插值，`t` 相等时按后一条的 `s` 跳变。

所以 `s` 不变表示路径暂停，`s` 跳变表示路径瞬移，`t` 相等是合法的跳变写法而不是数据错误。`FREE` 锚点路径仍按几何弧长算 `s`，端点只用于绑定。

### 4.2 契约

点表的结构约束：至少 2 项；首项 `(0,0)`、末项 `(1,1)`；`t` 与 `s` 都落在 `[0,1]`；两者都单调非减；不允许 `NaN` 或无穷；`type` 只能是 `linear` 或 `keyframes`。相等值合法，不报错。数量上限 256，超过时虚拟化并提示，不截断保存。

校验失败不写文档，草稿保留，切走再回来可以继续改。错误定位精确到 `points[i].t` 或 `points[i].s`。

### 4.3 数据形态

```json
{
  "timing": {
    "type": "keyframes",
    "points": [
      { "t": 0.0, "s": 0.0 },
      { "t": 0.3, "s": 0.1 },
      { "t": 0.7, "s": 0.6 },
      { "t": 1.0, "s": 1.0 }
    ]
  }
}
```

`timing` 可整体省略，等价于线性；线性时不写 `points`。数值按普通 JSON number 写，不做隐式四舍五入。

### 4.4 边界

- `timing` 错误在路径集合里计入 timing 非法这一类，行上显示问题数。
- 端点或节点变更不影响 `timing` 内容，只影响归一化长度。
- 路径生成器默认写线性，生成后可以改。
- 预览读 `timing.points` 画 `s(t)`，不调用运行时。
- 保存重开后线性仍是线性、关键帧点原样保留，相同 `t` 的顺序不变。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 只支持匀速 | 不提供 timing | 实现最简单 | 「中途停一下」是常见的镜头需求，只能靠加密关键帧实现，几何与节奏被绑死 |
| 用缓动函数枚举代替关键帧点表 | 提供 ease-in/out 等预设 | 概念简单 | 预设无法表达暂停与跳变；模组既有的 `timing` 就是点表 |
| 允许首末点任意 | 更自由 | 少一层校验 | 路径区间的两端必须对应 `s=0` 和 `s=1`，否则端点绑定失去意义 |
| 用容差容忍单调性错误 | 少报错 | 输入宽松 | 递减的点表在运行期会产生反向推进，容差只会掩盖问题 |
| 在 `s(t)` 图上直接拖点 | 交互直观 | 一个手势搞定 | 与路径预览的手势冲突；且图上拖点难以精确输入数值 |
| 自动把非法点表排序修复 | 少一次报错 | 操作更顺 | 排序会改变作者意图（尤其是相同 `t` 的跳变顺序），属于静默改数据 |
| 把 timing 折进 geometry | 一个对象表达形状与节奏 | 结构更紧凑 | 改节奏就要改几何，两者本该独立；模组也是分开的字段 |

**本方案的缺点**：

- 点表编辑需要理解 `t` 与 `s` 是两个不同的归一化量，初学成本不低。
- 相同 `t` 的跳变顺序依赖添加顺序，重排后行为会变，这个规则不直观。
- 256 点上限对极端精细的节奏不够用。
- `s(t)` 只读预览限制了「画一条曲线」式的直觉操作。

验收要点：

- 新路径省略 `timing` 时保存为线性，`s(t)` 为对角线；显式写线性等价。
- 切关键帧自动生成 `(0,0)` 与 `(1,1)` 两行；切回线性确认后点表移除，一次撤销恢复。
- 添加中间点默认取相邻中点，可改 `t`/`s`，保存后按 `t` 排序。
- 首项改 `t`、末项改 `s`、删除首末行都被拒；`t` 或 `s` 递减被拦下并定位到具体行与字段。
- 相同 `t` 允许并画竖线（运行时跳变）；相同 `s` 允许并画水平线（路径暂停）；中间点 `s` 为 0 或 1 允许。
- 数值超出 `[0,1]`、`NaN`、无穷被拦下。
- 点数超过上限时第 257 个添加被拒；已有点表可保存、可虚拟化滚动。
- 改 `from/to` 后 timing 点不变、`t` 重新归一化、`s(t)` 形状不变。
- 切几何类型时 timing 保留，`script.validate` 通过；几何参数不因 timing 改变。
- 保存重开后线性仍是线性、关键帧点原样保留、相同 `t` 的顺序不变。
