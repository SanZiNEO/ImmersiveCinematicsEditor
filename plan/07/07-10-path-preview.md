# 路径预览

> 状态：未实现
> 范围：11 种几何的编辑器内只读采样与画布呈现
> 关联：07-05 路径集合、07-06 几何表单、07-07 圆形生成器、07-08 时间映射

## 一、摘要

路径预览在编辑器内本地采样 11 种几何，把形状、控制多边形、端点、采样点、切线示意、`s(u)` 折线和锚点偏差画出来。它只用于画图和判断参数，不是运行时权威：弧长、速度、状态模型仍以模组为准。真游戏检查继续走现有的推送与定位能力，不新增运行时接口。当前状态：未实现。

## 二、为什么做

### 2.1 问题

- 作者填完几何参数只能靠想象，或者推送到游戏里看。一次往返几十秒，调一个半径要来回很多次。
- 控制点写错了方向、法向与参考轴搞反、`FREE` 锚点路径的端点与几何起终点不重合——这些错误在参数表上看不出来，只有画出来才明显。
- 十一种类型的形状差异很大，没有统一的可视化，作者无法建立「这个参数会怎样改变曲线」的直觉。
- 只覆盖部分轴的路径（`axes` 不含某轴）在视觉上应该与全轴路径有区别，否则作者会以为曲线真的只在平面上。

### 2.2 目标

- 11 种类型都能在编辑器里画出来，采样与模组同一参数定义对齐。
- 每种类型至少一组固定的期望采样向量，作为编辑器采样器的对照基准。
- `FREE` 与 `START` 锚点的端点偏差可见，并且明确「移动端点不改形状」。
- 预览与运行时权威的边界写清楚：预览不冒充游戏画面。

### 2.3 非目标

- 不实现运行时求值，不新增 `WebEditorApi` 消息，不读 Java 运行时对象。
- 不声称 2D 预览与游戏画面像素对齐。
- 不把预览采样结果写进文档。
- 不预览未选中的条目，也不做全列表批量预览。

## 三、方案

预览针对单个选中的路径条目，读它的几何、端点、`axes` 和 `timing`，产出一份只读模型：起终点位置（表达式空间）、锚点类别、采样点序列（每点带参数值与切线示意）、控制多边形、`s(t)` 折线、端点偏差、警告列表。

画布元素分工明确：路径线是当前几何的采样折线；控制多边形用虚线连控制点；端点用方块，`FREE` 锚点时用虚线连到几何真实的起终点；采样点与切线是可选项；`s(t)` 单独一张小图；锚点徽标常驻；警告区列出端点偏差、未知类型、无端点、法向退化。

采样按参数 `u` 均匀，不按弧长均匀——形状预览不需要弧长表。`arc`/`ellipse` 把 `u` 映射到起止角之间；`clothoid` 用数值积分。端点处理按锚点分三种：`ENDPOINTS` 的几何起点终点就是 `from`/`to`；`FREE` 的起终点由参数算出，`from`/`to` 只用于绑定和偏差；`START` 的起点是 `from`，终点由曲率与长度决定。周期 `fourier` 的 `u=0` 与 `u=1` 同点。

2D 投影按 `axes` 决定：三轴默认投影到 x/z，可切 x/y 或 y/z，标题标注「2D 投影，未显示 y」；`base` 空间下轴标签换成 `fwd/right`；单轴时改成「横轴参数、纵轴该轴值」的一维图；未覆盖的轴不画路径线。自动缩放按包围盒加边距，另提供「适配视图」与「1:1」。

生成器的向导预览不走这条路径——它直接用语义参数画理想曲线，不写临时 `paths[]`；生成之后路径面板再用实际写出的几何重画，两者应该一致（Bezier 允许千分之一半径的误差）。

真游戏检查是两个按钮：推送当前脚本、定位起点/终点，调用的都是既有能力。

## 四、技术细节

### 4.1 核心模型

每种类型的采样方式：

- `linear`/`line` 两端线性插值。
- `bezier` 三次贝塞尔，端点加两个内部控制点。
- `rational_bezier` 有理三次，按权重归一化。
- `arc` 由圆心、半径、平面基向量决定，角度线性采样。
- `ellipse` 由圆心、半轴、旋转、基向量决定，按参数角采样。
- `bspline` 用 de Boor，端点加内部控制点加节点向量。
- `nurbs` 有理 de Boor，权重归一化。
- `catmull_rom` 按三种参数化分别处理，端点按 mirror/clamp。
- `hermite` 三次 Hermite 基，端点加两个切线。
- `clothoid` Fresnel 积分数值采样，由起止曲率与长度决定。
- `fourier` 常数项加余弦正弦级数，周期与非周期分别处理。

控制多边形只对有多边形控制点的类型有值；端点偏差只对 `FREE`/`START` 计算，`ENDPOINTS` 恒为空。

### 4.2 契约

每种类型有一组 golden fixture：固定的几何参数、固定的端点、若干 `u` 上的期望坐标与容差。期望值来自模组的固定测试向量，不由编辑器采样器自己生成——否则就是循环验证。构建时跑 fixture，任一类型超出容差即失败并指出类型与采样点。fixture 是只读资产，运行时不加载。

未知类型或参数错误时不画曲线，显示错误卡片与字段路径。

### 4.3 数据形态

预览模型是纯派生数据，不写盘：

```json
{
  "u": 0.25,
  "point": [2.828427, 0.0, 2.828427],
  "tangent": [-0.707107, 0.0, 0.707107]
}
```

采样点数按画布宽度自适应；缓存键是几何 JSON 加起终点加 axes，参数一变就重算。同一时刻只预览一个选中条目。

### 4.4 边界

- 预览失败不影响文档，错误显示在画布下方。
- 拖动参数时保持交互可用；重算过慢时降采样，松手后恢复。
- `clothoid` 的数值积分节点按参数缓存，参数不变不重算。
- 「按几何重算端点」只对已提交条目开放，生成器草稿不显示。
- 游戏检查不叠加预览图形，不声称像素对齐。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 只靠推送到游戏里看 | 不做本地预览 | 零实现成本 | 一次往返几十秒，调一个参数要试很多次 |
| 把预览叠加到游戏画面上 | 半透明叠加 | 直观 | 需要新增运行时接口与消息，超出零改动边界；且坐标对不齐会误导 |
| 用第三方图库画曲线 | 引入依赖 | 省事 | 十一种几何的采样逻辑仍要自己写；引入依赖只为画线不划算 |
| 采样按弧长均匀 | 视觉上点距更均匀 | 更接近运行时 | 形状预览不需要弧长表；弧长均匀要额外做数值反解，成本高且容易与运行时口径混淆 |
| fixture 由编辑器采样器生成 | 省一次人工对齐 | 构建永远通过 | 循环验证，采样器错了 fixture 也错，起不到对照作用 |
| 全列表批量预览 | 一眼看全部 | 概览方便 | 100 条路径全量重算会卡死；列表只需要摘要，形状按需看 |
| 预览里直接拖控制点改参数 | 交互最直觉 | 一个手势改几何 | 与画布平移缩放、`s(t)` 拖点手势冲突；参数表单才是权威入口 |

**本方案的缺点**：

- 采样按参数而非弧长，画出来的点距不均匀，容易被误读为「速度变化」。
- 2D 投影必然丢失一个维度，三维曲线的自交在投影上可能看不出来。
- fixture 需要人工从模组测试向量里取数并对齐，维护成本不低。
- 预览与运行时权威的边界要靠文案反复强调，作者仍可能拿预览当最终依据。

| 原设计 | 实际实现 | 偏离原因 |
|---|---|---|

验收要点：

- 11 种类型都能画出形状；有控制多边形的类型画出虚线多边形与控制点；端点方块位置正确。
- `linear` 无控制多边形、`s(t)` 为对角线；`bezier` 端点等于起终点；`rational_bezier` 权重改变形状且数量匹配。
- `arc` 半圆采样点落在圆上，关键 `u` 与 fixture 一致；`ellipse` 半轴与旋转正确。
- `bspline`/`nurbs` 的 de Boor 采样与 fixture 一致，`nurbs` 权重影响形状。
- `catmull_rom` 三种参数化形状不同、tension 边界可画；`hermite` 两端切线方向正确。
- `clothoid` 曲率全零时退化为直线，非零时曲率渐变，fixture 偏差在容差内。
- 周期 `fourier` 的 `u=0` 与 `u=1` 同点；非周期时端点参与。
- 11 组 fixture 全部通过；任一类型超差时构建失败并指出类型与采样点。
- `FREE` 路径移动端点后形状不变、偏差数字更新、虚线连到几何起终点；`START` 路径终点只做绑定，移动不改形状。
- `axes` 部分覆盖时只画覆盖轴；单轴时切一维图；三轴时标题标注 2D 投影。
- 未知类型不画曲线并显示字段错误，修好后恢复。
- 100 条路径时只预览选中条目，参数拖动仍可用，无全量重算卡顿。
- 生成器 Bezier 圆预览闭合、误差在容差内；切精确模式显示单条弧。
- 游戏检查按钮调用既有推送与定位能力，`WebEditorApi` 消息清单无新增；模组 `.java` 零改动。
