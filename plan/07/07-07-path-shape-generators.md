# 圆形路径生成器

> 状态：未实现
> 范围：由圆心/半径/起止角生成圆、圆弧、椭圆，并写出位置关键帧与 `paths[]`
> 关联：07-05 路径集合、07-06 几何表单、07-08 时间映射、07-10 路径预览

## 一、摘要

作者要一条可播放的圆形路径，实际需要的是两样东西同时到位：位置关键帧（让相机真的在圆上）和 `paths[]` 条目（让曲线形状被声明）。手工做这件事要算三角函数、切控制点、对时间分段。圆形路径生成器把这步收进一个表单：给圆心、半径、起止角、方向、平面、模式，编辑器算出路径并一次提交。生成器只写 `objects` 和 `paths`，不新增曲线类型、不修改注册表或求值器。当前状态：未实现。

## 二、为什么做

### 2.1 问题

- 用 `bezier` 拼一个圆要手算每段控制点，段数不够会看出折角，段数过多则路径条目爆炸。
- 精确圆弧不需要控制点，但要求作者理解 `arc` 的圆心/法向/参考轴三件套，以及「端点是 `FREE` 锚点、只做绑定」这件事。
- 只写 `paths[]` 不写位置关键帧，运行期相机不一定会走到圆上；只写位置关键帧不写 `paths[]`，曲线形状又没有被声明。两件事必须同一次提交完成。
- 圆心坐标属于哪个空间取决于片段的 `position` 模式与空间。作者按世界坐标填，在 `base` 空间下会整体偏掉。
- 在已有位置节点的区间里生成，会与既有节点、既有路径端点冲突。静默覆盖是最差的结果。

### 2.2 目标

- 给圆心、半径、起止角、方向、平面，得到一条能通过 `script.validate` 的圆或圆弧。
- Bezier 模式的分段近似误差在可接受范围内，且段数可自动也可手调。
- 精确模式写一条（或按角度分段的几条）`arc`/`ellipse`，形状由几何参数决定，端点只做绑定。
- 生成前能看到会新增、替换、删除什么，以及会影响哪些其他路径。
- 生成后一次撤销可完全回退。

### 2.3 非目标

- 不新增曲线类型，不碰 `PathCurveRegistry`、`PathEvaluator` 或任何模组 `.java`。
- 不改 `WebEditorApi` 的消息清单，不新增运行时求值接口。
- 不生成非圆类形状（螺旋、贝塞尔自由曲线等），那些走 07-06 的手工参数。
- 不自动改作者已有但不在本次范围内的路径。

## 三、方案

表单输入是目标片段、时间区间、形状（圆/圆弧/椭圆）、圆心、半径或长短半轴与旋转、起止角、方向、平面（法向与参考轴）、模式（Bezier 分段 / 精确数学）、分段数、时间策略。

圆心坐标空间随片段位置模式变化，表单只读显示当前空间并切换轴标签：`absolute` 是世界坐标；`relative + world` 是相对原点偏移（原点是 `coordinate` 时允许切「世界坐标」输入，编辑器减去原点后写片段坐标）；`relative + base` 是局部坐标，轴标签是 `fwd/up/right`。原点是动态源（玩家、选择器、方块、结构）时只接受片段坐标，不猜世界原点。几何参数和位置关键帧写的是同一个表达式空间的分量，运行时由求值器统一加原点与参考系。

角度上，`delta = end - start`，方向开关把 `delta` 掰成正（逆时针）或负（顺时针）；`delta` 为 0 或绝对值超过 360 都拒绝。全圆就是 `0 → 360`，顺时针用方向开关把它变成 `-360`。平面由法向与参考轴张成，两者不能平行；默认水平面、从上方看逆时针。

两种模式的差别是本质的，不只是精度：

- Bezier 分段把圆弧切成不超过 90° 的段，每段一条 `bezier` 条目，控制点写成相对段起点的偏移。段数自动时按角度算，作者也可以手动指定。这种写法是近似，允许的采样偏差按半径的千分之一衡量，超出时提示分段不足。
- 精确数学对圆写一条 `arc`（或按 90° 分成几条），对椭圆写 `ellipse`；形状完全由几何参数决定，移动端点关键帧只改绑定、不改形状。圆心默认写相对段起点，避免依赖未知的世界原点。

时间策略有两种，决定「区间里已有的位置节点怎么办」：按现有节点保留作者的时间节奏，区间内每个已有节点都成为分段边界，生成器只重写这些时间点的位置值；替换区间节点则删掉区间内的位置关键帧，按分段数重建边界时间。删除区间内节点前会扫描引用这些节点的其他路径，有引用就列出来，让作者选「删除这些路径并继续」还是取消。

生成器一次写三类内容：分段边界上的 `position.x/y/z` 关键帧（每个时刻三条独立帧，同一数值，不建组、不写 `authoring`）、每条路径一个条目（`clip`/`from`/`to`/`axes`/`geometry`/`timing` 完整）、以及不写盘的诊断与预览草稿。生成后选中第一条路径，播放头跳到起点；路径面板和属性/效果面板同步显示新键。

重新生成时先出 diff：新增几条、替换几条、删除几条、影响其他路径几条。确认后一次提交，一次撤销恢复路径、关键帧、id 和选择。

## 四、技术细节

### 4.1 核心模型

平面基由法向 `n` 与参考轴投影出的 `u`、再叉乘得到的 `v` 组成；圆上的点是 `C + r * (cosθ·u + sinθ·v)`，切线是对 θ 的导数。投影后参考轴长度接近 0 时拒绝生成。`P(θ)` 的三个分量直接写 `position.x/y/z`；`base` 空间下这三个分量就是 `fwd/up/right`。

Bezier 分段用标准的圆弧三次逼近：每段的角度跨度为 `delta / n`，控制点沿切线方向外推，外推系数由 `tan(段角/4)` 决定——90° 段的系数就是常见的 0.5523。非 90° 段用通用公式，不硬编码单一常数。自动段数保证每段不超过 90°。

### 4.2 契约

- 半径与半轴在生成前校验为正，退化值拒绝。
- 全圆四段闭合时，最后一段终点必须与第一段起点相同，端点键首尾值相同。
- 精确模式下全圆的起止角落在同一点但时间不同，这是合法的。
- 生成的路径条目都是普通条目，之后可以手改几何、端点、axes、timing。
- 生成的 id 全局唯一；重新生成按 diff 替换，不复用已删除的 id。
- 生成器不 import 运行时 Java 代码，不调用运行时采样接口。

### 4.3 数据形态

精确模式的几何长这样：

```json
{
  "type": "arc",
  "center": { "dx": 0, "dy": 0, "dz": 0 },
  "radius": 4.0,
  "start_angle": 0.0,
  "end_angle": 360.0,
  "normal": { "x": 0, "y": 1, "z": 0 },
  "reference_axis": { "x": 1, "y": 0, "z": 0 }
}
```

Bezier 模式每段写 `{type:'bezier', control_points:[P1, P2]}`，控制点都是相对段起点的 `{dx,dy,dz}`。位置关键帧写成普通的 `AnimObject` 关键帧数组，`mode=animated`，不写 `authoring`。`position_mode`/`space`/`origin` 不因生成而改变。

### 4.4 边界

- 影响面只覆盖目标片段与本次时间区间；其他片段、其他区间不动。
- `impactedPaths` 非空时必须由作者决定删除还是取消，不静默改别人的路径。
- 应用后跑 `script.validate`；出现 block/error 时展开问题并提供「撤销本次生成」。
- 精确模式生成后移动端点关键帧，圆弧形状不变，偏差徽标出现；「按几何重算端点」只改位置帧。
- 模组仓库 `.java` 零改动，`WebEditorApi` 无新消息。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 只写 `paths[]`，不写位置关键帧 | 让运行时按几何驱动位置 | 一条路径就够 | 运行时按位置关键帧求值，只声明几何不会让相机移动 |
| 只写位置关键帧，不写 `paths[]` | 密集采样位置 | 不依赖路径系统 | 曲线形状没有被声明，`arc`/`ellipse` 的精确性与预览都无从谈起 |
| 一律用 Bezier 分段 | 只有一种模式 | 实现简单 | 分段是近似，段数再多也有误差；精确圆弧是既有能力，不该屏蔽 |
| 一律用精确几何 | 只写 `arc`/`ellipse` | 无近似误差 | 作者需要的是可手改的分段条目，或需要与既有 `bezier` 路径风格统一 |
| 在模组侧新增「圆」类型 | 参数化生成 | 表单最简 | 改 `.java`、改注册表，超出 07 的零改动边界 |
| 生成时自动清理冲突路径 | 少一次确认 | 操作更顺 | 会删掉作者手写的路径，且无法预知他要保留哪条 |
| 圆心一律按世界坐标输入 | 少一层空间判断 | 表单简单 | `base` 空间下必须写局部分量，混用会整体偏移 |

**本方案的缺点**：

- 两种模式并存，作者要理解「Bezier 是近似、精确是参数化」的差别才能选对。
- Bezier 分段在段数少时肉眼可见折角，段数多时路径条目数量膨胀。
- 精确模式的 `arc` 端点只做绑定，作者容易误以为「拖端点能改形状」。
- 时间策略的两选项覆盖不了所有需求，比如「只替换某几段」目前要生成后再手改。
- diff 确认步骤在反复调参时打断节奏。

验收要点：

- 半径 4、`0→90`、逆时针、Bezier：一条 `bezier` 条目，控制点长度符合标准圆弧逼近，端点落在圆上。
- `0→360` 自动分段：四条条目、闭合、径向采样误差在半径千分之一内、端点时间相邻。
- 同样参数走精确模式：一条 `arc`，圆心相对起点、`radius=4`、`0→360`，`script.validate` 通过。
- 顺时针 `0→360`：`delta` 为负、Bezier 控制点方向反向、精确弧按顺时针播放。
- 三维平面（法向非竖直）：生成的曲线落在指定平面内，垂直方向分量恒定。
- 两种时间策略分别成立：按现有节点时节点时间不变、分段角度对应；替换区间时旧键删除、边界时间重建。
- 区间内其他路径被引用时先列影响面；取消则文档不变，删除后生成继续。
- 重新生成按 diff 替换，旧 id 不再存在、新 id 唯一，一次撤销恢复路径、关键帧、id 与选择。
- 半径或半轴为零、起止角相等、跨度超 360、法向与参考轴平行：本地拦下且生成按钮禁用。
- `relative + world` 配 `coordinate` 原点时世界圆心减原点后写片段坐标；`relative + base` 时按局部三轴写分量。
- 应用后 `script.validate` 通过；模组 `.java` 零改动；`WebEditorApi` 无新消息。
