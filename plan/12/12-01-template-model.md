# 三层模板与装配

> 状态：未实现
> 范围：片段/轨道/脚本三层模板的定义口径、参数规则、展开产物、装配与事务边界、注册表
> 关联：12-02 嵌套传参、12-03 片段模板、12-04 轨道模板、12-05 脚本模板、12-11 生成校验

## 一、摘要

模板是编辑器侧的参数化生成器：填一组参数，产出一段标准脚本 JSON。三层分别是片段、轨道、脚本，只向下引用。模板本身不是脚本资产，产物里没有模板 id、参数或来源，运行时完全不认识"模板"这个概念。本轮只做内置模板，用户自定义数据模板留给后续层。

## 二、为什么做

### 2.1 问题

手写重复结构最容易出错的地方不是创意，而是机械字段：一段环绕要摆两个位置关键帧、一条贝塞尔路径、控制点系数、端点时间；一份开场骨架要记得七类轨道、遮幅、片头黑场、`meta` 里哪些字段能省。作者每次都要重抄一遍，漏一个字段就得到一份过不了校验的脚本，而错误信息指向字段路径，不指向"你想做的是环绕"。

另一个诱惑是把模板做进运行时：让脚本里带一个模板 id，播放时再展开。这会让脚本不再是唯一真相，模组要额外解析一套语义并承担版本兼容，而作者改了产物之后，模板与产物到底谁说了算就没有答案。

### 2.2 目标

- 作者按"我要做什么"选模板、填几个业务参数，就得到一段与手写同构的标准脚本。
- 产物能过现有脚本校验器，能被现有通道推送、被游戏播放，不带任何编辑器私有标记。
- 生成失败时文档、选择、路径集合全部保持原状，零残留；成功时一次撤销全部回退。
- 模板只排硬切，不替作者决定转场。

### 2.3 非目标

- 不做纯数据模板、模板包导入、模板 DSL 或解释器。
- 不新增运行时模板字段、模板轨道、模板转场。
- 不写片段级 `transition*`、不自动 crossfade、不改相邻片段。
- 不跨层横向引用：片段不引用轨道，轨道不引用脚本，同层之间也不互相引用。
- 不做"再生成/同步模板产物"这类保持关联的能力。

## 三、方案

作者在模板面板里先选层，再选模板，填参数，看一段结构摘要，然后生成。生成结果就是普通片段：可以继续改字段、改时长、加关键帧，也可以删掉重来。面板不会留下"这段是模板生成的"的标记，也没有"重新生成覆盖"的按钮——产物一旦落地，它与模板的关系就结束了。

三层各管一段范围。片段模板只管一个片段内部的对象字段，必要时附带一条路径；片段起点由装配器给，模板不写绝对开始时间。轨道模板只管一条轨道里的片段顺序、起点和时长，不碰其他轨道，也不复制片段级的数学。脚本模板只管整份骨架，不往已有文档里塞内容。

参数是模板的输入契约，不是第二套字段系统。参数声明复用文档字段元数据的形状（类型、默认值、必填、枚举候选、分组、单位、范围），但参数本身不写进脚本。除常规数值、开关、枚举、文本、选择器之外，还有两类编辑器侧参数：单个姿态和姿态列表，它们只是把位置、朝向、光学参数打包成一次输入，展开时拆回目标片段已有的位置、朝向、`fov`/`zoom` 字段。参数里的位置和姿态可以从九槽取，取槽发生在表单层，展开时只剩数值。

## 四、技术细节

### 4.1 核心模型

每个模板声明自己的层、目标轨道类型、标题与说明的文案键、参数声明列表、展开函数，以及可选的向下引用和跨参数校验。展开函数是纯函数：参数进，本层 JSON 片段出，不读文档、不读全局状态、不写文件、不缓存上一次结果。模板定义无状态，每次展开都新建对象。

三层只向下引用，方向本身就是模型的一部分：脚本 → 轨道 → 片段。这条约束保证了展开顺序可以静态推导，也保证任何一层都能独立被理解。

### 4.2 契约

展开产物按层固定形状：片段层给出片段对象与可选的路径条目；轨道层给出一条轨道、若干片段与可选路径；脚本层给出 `meta`、若干轨道、可选触发器骨架与可选路径。所有 `objects` 的键必须是目标轨道 schema 中真实存在的字段，值必须是该字段允许的 `{value}` 或 `{keyframes}` 形态；value-only 字段（如 `text`、`layer_type`、`position_mode`、`fov`）不生成关键帧；关键帧时间从 0 起、单位秒、严格递增。

模板不定义曲线类型、路径端点语义、规则执行和事件语义——这些字段照 07 与 11 的合同写。模板不写 `meta.version`、`timeline.total_duration` 或已废弃字段，`meta` 只写模板明确给出的非默认值。

装配器是模板与文档之间的唯一桥。片段级装配负责选目标轨道（必须与模板声明的轨道类型一致）、定插入点、算起点、检查区间重叠、分配片段 id 与路径 id；重叠时拒绝并提示改插入点或新建轨道，绝不静默挪动已有片段。轨道级装配可以新建轨道或追加到同类型轨道，追加时起点接在该轨道最后一个有限片段之后，任何片段重叠都整次拒绝，不生成半条轨道。脚本级装配只用于新建文档或明确的"从模板新建脚本"入口，当前文档有脏改动时先走未保存守卫。

一次应用就是一个文档事务：成功后可一次撤销，失败时文档、选择、路径集合保持应用前状态。成功后选择第一个生成的片段，选择用片段键而不是数组下标。

### 4.3 数据形态

产物只有标准脚本字段，形状与手写脚本一致：片段带 `id`、`start_time`、`duration`、`objects`、可选 `exit`，路径条目带 `id`、`clip`、`from`、`to`、`axes`、`geometry`、`timing`。轨道层与脚本层只是把这些片段按顺序装进 `timeline.tracks`。

模板 id、参数值、槽位 id、命名空间、生成时间都不出现在产物的任何字段里。当前会话可以显示"本次生成用了哪个模板、哪些参数"，只服务面板摘要，刷新或重开不保留，也不落盘。

### 4.4 边界

片段模板声明目标轨道类型，装配器不把 CAMERA 片段塞进 OVERLAY 轨。内置模板本轮只覆盖 CAMERA、OVERLAY、LETTERBOX：OVERLAY 模板只写覆盖层字段，CAMERA 模板只写相机字段，LETTERBOX 只写比例与透明度，AUDIO 与事件轨道本轮没有模板。模板不跨轨道复制字段，需要组合时由脚本级模板引用多条轨道模板。

注册表是只读列表，注册顺序即面板展示顺序，三层共用一个查找入口但 id 层内唯一。注册时检查层与引用方向、目标轨道类型是否存在、参数键是否重复、展开函数是否返回合法层；注册失败只让该模板不可用，不阻止编辑器启动。本轮不加载外部模板包、不扫描用户目录、不执行用户脚本。

模板不持有产物，也不保留再生成关系。模板升级只影响新生成的内容，不改已生成片段。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 模板进运行时 | 脚本里带模板 id 和参数，播放时展开 | 模组要新增解析、版本兼容与错误处理；脚本不再是唯一真相 | 作者改产物后语义二义，且运行时不该认识编辑器概念 |
| 模板持有产物并支持再生成 | 产物记住来源模板与参数，可"同步"回模板新版本 | 手改会被覆盖；冲突无法自动判定 | 产物即普通脚本是硬边界，关联必须断开 |
| 纯数据模板 | 模板本身是一份 JSON，用户可导入导出 | 需要 schema、校验器与沙箱；本轮没有需求驱动 | 先把内置模板与参数口径跑通 |
| 模板直接出像素预览 | 面板里画最终画面 | 编辑器无法复现运行时合成与字体测量 | 会变成假预览，误导作者 |

**本方案的缺点**：

- 内置模板覆盖有限，作者想要的结构若不在列表里，仍要手写。
- 参数类型比脚本字段多一层映射（姿态、姿态列表），读文档时要同时理解两边。
- 面板必须自己维护结构摘要与冲突预判，摘要逻辑与展开逻辑是两处实现，可能不一致。

### 验收要点

- 四个片段模板、两个轨道模板、三个脚本模板各生成一次，保存重开能过现有校验器。
- 产物与手写脚本同构：没有模板 id、参数、槽位 id、来源或生成时间。
- 目标区间重叠时拒绝装配，已有片段一动不动。
- 轨道类型不匹配时装配前拒绝，不产生跨类型字段。
- 一次生成一次撤销；失败后文档、选择、路径均无残留。
- 生成后作者能继续逐字段编辑，面板不提供"再生成"入口。
