# 模板嵌套与逐层传参

> 状态：未实现
> 范围：跨层引用声明、参数绑定、实例命名空间、深度/环/实例数上限、展开顺序与失败回滚
> 关联：12-01 三层模型与装配、12-03 片段模板、12-04 轨道模板、12-05 脚本模板、12-11 生成校验

## 一、摘要

嵌套让脚本模板引用轨道模板、轨道模板引用片段模板，从而不必重复实现下层已经写好的东西。嵌套只发生在编辑器展开期：保存后的脚本里没有模板 id、引用链、命名空间或参数，只有最终片段、路径、轨道和字段。参数逐层传递，每层只能看到自己声明的参数。

## 二、为什么做

### 2.1 问题

没有嵌套时，脚本模板要生成一圈环绕，就必须自己再写一遍角度分配、段时长和路径控制点；轨道模板要生成多机位，就要自己再写一遍固定机位片段的位置与朝向字段。同一份数学存在多份拷贝，改一处漏一处，作者看到的两个模板行为不一致，却查不出谁对。

但嵌套也是最容易失控的地方：如果允许任意深度的互相引用，就会出现环、参数穿越多层、命名冲突和无法定位的失败。所以真正要设计的是"嵌套能做什么、不能做什么"，而不是把引用做成图灵完备。

### 2.2 目标

- 上层模板能用常量或自己已声明的参数去填下层参数，不需要重复数学。
- 展开顺序可以静态推导，深度固定为三层，环在展开前就能被识别。
- 一次展开产生的所有实例 id 互不冲突，且不把中间命名泄漏到脚本里。
- 任何引用错误都整次失败，不生成半份内容。

### 2.3 非目标

- 不执行任意表达式：不做字符串模板、函数、正则、`eval`，也不读未声明变量。
- 不跨层跳取：只能引用当前层已声明的参数，不能引用上上层。
- 不做脚本嵌套脚本、轨道嵌套轨道、片段嵌套片段。
- 不把运行时状态、数组下标、片段 id 当参数。
- 不把槽位 id 写进参数：九槽取值必须在表单层先解析成数值。

## 三、方案

一条引用声明只回答四件事：引用哪个模板、参数怎么绑、重复几次、实例怎么放。参数绑定只有三种形态：常量、上层同名参数、引擎内置的封闭派生（如按序号切分角度）。派生是登记在册的固定算法，不是用户可写的表达式；本轮只登记实际模板需要的那几个。

逐层传参的规则很简单：上层把归一后的值传给下层，下层拿到的是数值而不是引用。下层没有声明同名参数时，绑定直接报错，不静默透传；上层的默认值只在上层解析一次，下层可以覆盖自己的默认值，但读不到上层没声明的东西。展开期参数对象只读，展开函数不得修改传入的参数。

每次引用展开都得到一个实例命名空间，用于在展开期分配最终 id。命名空间由模板短名和实例序号组成，只是中间产物：片段 id、轨道 id、路径 id 都按现有命名规则分配并在文档范围内去重，冲突时追加稳定后缀。命名空间字符串不允许出现在保存后的 JSON 任何字段里。

重复次数必须是整数并限制上限，单次展开的总实例数也有上限。每个实例的参数互相独立，不共享可变对象；实例顺序按引用声明顺序和重复索引递增，不按数组下标重排。

## 四、技术细节

### 4.1 核心模型

展开栈是理解嵌套的核心：栈里记录当前正在展开的模板 id。栈中出现重复 id 就是环，与深度上限无关——即使层数没超，重复也要报环；反过来，同一模板被多个不同父引用不算环，只有当前栈内重复才算。

深度上限就是层数本身：脚本 → 轨道 → 片段，超过三层不成立。方向约束比深度更根本：引用目标层必须严格低于当前层，同层与向上都直接拒绝。

### 4.2 契约

展开顺序固定：先校验当前模板参数，再展开本层自有内容，然后按引用声明顺序展开下层实例，为每个实例分配命名空间与最终 id，最后合并本层与下层内容并检查总实例数、id 冲突与目标轨道类型。返回的是扁平化后的片段、轨道或脚本片段；装配器只做放置，不再理解模板层级。

失败语义是"要么全成、要么全不成"：参数错误不开始展开；引用方向、深度、环、实例数错误整次失败；某个下层实例失败则整条引用链失败。已经生成的内存对象因为尚未写入文档，不需要回滚。装配阶段失败时文档不变，展开草稿丢弃。最终校验失败时整次应用回滚，诊断定位到模板 id、引用链、参数名或目标片段。

错误信息不吞掉下层原因，但也不重复刷屏：保留一条根因链即可。

### 4.3 数据形态

引用声明带被引用模板 id、参数绑定表、可选重复次数、可选实例索引变量名、可选放置方式。参数绑定的三种形态在数据上互斥，不允许组合。

产物形态与 12-01 一致：片段、路径、轨道、脚本片段。命名空间、实例序号、引用链都只存在于展开期。

### 4.4 边界

脚本模板可以引用多条轨道模板，也可以内联少量 `meta` 与触发器骨架。需要单轨起手式时可以用内部轨道组合器：它调用片段模板的展开函数，只负责轨道 id、片段起点、顺序与轨道类型，不复制片段数学；组合器不注册成用户可见模板，但仍属轨道级装配，同样只向下组合。

轨道模板按顺序引用片段模板，每个片段实例有独立参数；可以内联一个片段，但内联片段仍走同一装配校验。片段模板是最底层，没有引用，可以生成多条路径但都只属于本片段。

三层都不横向引用：需要组合时由更上一层引用多条下层模板。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 允许任意深度递归 | 模板可以引用任意层，深度由数据决定 | 需要运行时展开与通用环检测；失败定位困难 | 三层已经覆盖片段/轨道/脚本，更深只会增加不可读性 |
| 表达式式参数绑定 | 参数写成表达式串，支持运算与函数 | 需要解析器、沙箱与错误处理 | 本轮模板需要的是取值与角度切分，封闭派生足够 |
| 只允许常量传参 | 每层参数全部手填 | 上层无法把半径传给多个下层实例 | 会让轨道模板退化成一堆重复常量 |
| 允许横向引用 | 轨道模板引用另一个轨道模板 | 顺序与职责边界模糊，容易成环 | 组合应由脚本层表达 |

**本方案的缺点**：

- 派生种类是封闭的，新模板需要新的角度或数量分配时，要新增派生而不是写一行表达式。
- 三层固定，将来若需要"脚本套脚本"必须重新设计而不是放宽参数。
- 命名空间只服务展开期，调试时看不到中间名，定位问题要靠引用链。

### 验收要点

- 脚本模板引用轨道模板、轨道模板引用片段模板，逐层传参后产物正确，且产物里没有任何中间命名。
- 引用目标层高于或等于当前层时拒绝展开。
- 展开栈出现重复模板 id 时报环并给出闭环路径，即使层数未超。
- 重复次数非整数或越界、总实例数超限时拒绝展开。
- `from` 引用未声明参数时拒绝展开，不静默透传。
- 任一引用失败时整次展开失败，文档不变、无半份内容。
- 成功展开后命名空间与实例序号不出现在保存后的脚本里。
