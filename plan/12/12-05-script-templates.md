# 脚本级模板

> 状态：已实现
> 范围：`script.blank` / `script.camera_intro` / `script.follow_black` 三个内置脚本模板
> 关联：12-01 装配、12-02 嵌套、12-03 片段模板、12-04 轨道模板、07 位置契约、11 触发器声明

## 一、摘要

三个脚本模板各给一种起手式：一份空骨架、一个"相机 + 遮幅 + 可选片头黑场"的开场、一个"跟随目标 + 看向目标 + 结束黑场"的完整示例。产物是标准脚本：`meta`、轨道、片段、可选路径、可选触发器骨架。生成后作者继续在既有面板里编辑，模板不执行规则、不维护运行时状态、不写默认转场。

## 二、为什么做

### 2.1 问题

新建脚本最容易在骨架层出错：忘记某类内置轨道、给 `meta` 塞了不该写的版本或总时长、生成了一个空的触发器数组、把遮幅和片头黑场的时间轴对齐关系弄反。这些错误都不影响"脚本能打开"，但会影响播放和后续编辑——空触发器数组会让行为页出现一个没有内容的条目，片头黑场时长超过相机片段时长会让黑场一直盖着画面。

跟随类脚本还有另一层难点：相机用相对基准坐标跟随选择器时，位置三分量的语义是前向、上、右，不是世界三轴；写成世界坐标或把玩家基准当成片段原点，在游戏里就会跑偏，而编辑器静态检查看不出来。

### 2.2 目标

- 作者选一个起手式、填几个参数，就得到一份结构完整、能通过校验、能直接播放的标准脚本。
- 骨架里的每条轨道都合法：该空的空，该有内容的类型正确，不写废弃字段。
- 触发器只写声明骨架，动作与规则留给行为页。
- 生成后走现有保存与校验通道，不直接写游戏目录。

### 2.3 非目标

- 不写 `meta.version`、`timeline.total_duration`、空 `triggers` 数组、废弃的 HUD 或屏幕字段。
- 不写规则、规则绑定、执行状态、事实状态。
- 不写片段级 `transition*`、不做 crossfade、不自动改相邻片段。
- 不把脚本模板塞进已有非空文档。
- 不写 `target`：触发器固定为"触发后播放本脚本给触发者本人"。
- 不生成路径：脚本层的三个模板都不用路径。

## 三、方案

`script.blank` 给一份空骨架：`meta` 按 schema 默认值写并用参数覆盖身份字段，七类内置轨道各一条空轨，轨道 id 按类型与序号分配。它不写触发器、不写规则、不写路径，也不写总时长——时长由片段与播放器决定。

`script.camera_intro` 给一个开场：一条相机片段（固定机位、不呼吸），可选一条遮幅片段，可选一条片头黑场。遮幅比例为零时不生成遮幅片段；黑场时长为零时不生成黑场。三者首尾对齐，没有 A→B 交界操作。黑场用淡出模式（黑到画面），因为它是片头而不是收尾。

`script.follow_black` 给一个完整示例：相机用相对基准坐标跟随选择器并看向同一个选择器，位置三分量按前向/上/右给值，朝向与位置都是常量——跟随由运行时读取实体当前位置，不由关键帧表达。结束处可选一段淡入黑场。可选生成登录或生物群系触发器骨架，只写声明字段，不写动作。

三个模板都遵守同一条产物纪律：生成的是标准脚本，没有模板 id、参数、来源或生成记录；需要叠化时作者到 08 建立；需要规则时作者到 11 行为页添加。

## 四、技术细节

### 4.1 核心模型

脚本模板的输入是"一份脚本的起手状态"，输出是完整脚本骨架。它内部需要多条轨道时，可以用内部轨道组合器把片段模板的展开结果放进轨道——组合器调用片段模板的展开函数，只负责轨道 id、片段起点、顺序与轨道类型，不复制片段数学；它不注册成用户可见模板，但同样只向下组合。需要整圈或多机位时，脚本模板直接引用用户可见的轨道模板。

### 4.2 契约

`blank` 的契约：`meta` 身份字段由参数覆盖、作者字段写字符串；七类内置轨道各一条空轨；不写触发器、规则、路径、总时长、版本。

`camera_intro` 的契约：相机片段从零开始、时长由参数给；遮幅片段与相机同起同长、只写比例与透明度，方向由窗口比例自动决定；黑场片段从零开始、时长为参数值、模式为淡出、颜色为黑、层级明确；遮幅与黑场都只在参数大于零时生成。黑场时长不得超过相机时长。

`follow_black` 的契约：相机片段位置模式为相对、空间为基准、原点是选择器且不冻结；朝向来源与注视目标都是同一选择器；位置三分量按基准轴给常量（后退距离、高度偏移、横向零）；注视点高度单独给；位置与朝向都是常量，不生成关键帧，不写世界绝对位置。结束黑场从总时长减去黑场时长处开始、模式为淡入（画面到黑）。触发器只在选择登录或生物群系时写，字段限于声明骨架。

位置三分量在相对基准下读作前向、上、右，这条语义以 07 的位置组契约为准；模板只选值，不重新定义语义。无法忠实表达的位置字段按参数或生成错误处理，不把世界坐标冒充相对坐标。

### 4.3 数据形态

产物是标准脚本：`meta` 加 `timeline.tracks` 下的各类型轨道，每条轨道带片段数组；触发器可选，且只可能是 11 定义的声明形态。标准对象字段全部来自目标轨道 schema，没有模板私有字段。

### 4.4 边界

脚本模板只用于新建文档或明确的"从模板新建脚本"入口；当前文档有脏改动时先走未保存守卫，不静默覆盖。生成后仍走保存与校验通道。触发器骨架只写声明，不写动作、规则或绑定；需要规则时到行为页添加。`follow_black` 不使用路径，跟随由运行时读取实体位置实现。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 骨架里预置默认转场 | 开场或收尾自动加一段叠化 | 与 08 的交界模型冲突；作者不知道转场从哪来 | 转场必须由作者在 08 显式建立 |
| 跟随用关键帧表达 | 把跟随目标的轨迹烘成位置关键帧 | 目标移动路径不可预知，烘完就固定 | 跟随应由运行时读实体位置，常量字段足够 |
| 触发器连规则一起生成 | 骨架里带上规则与绑定 | 规则依赖行为页的字段与执行语义 | 模板只给声明骨架，规则归 11 |
| 骨架写 `total_duration` | 按最长片段填总时长 | 该字段已废弃，写它会让脚本与播放器口径不一致 | 时长由片段与播放器决定 |
| 空骨架只建相机轨 | 少写几条空轨，作者需要时再加 | 新建后要反复加轨道，且易漏类型 | 七类内置轨道各一条成本很低 |

**本方案的缺点**：

- `follow_black` 的位置语义依赖对基准轴的理解，作者读参数时容易按世界三轴理解。
- 三个模板都只是起手式，稍微不同的开场结构仍需手改。
- 骨架里的空轨在作者只用相机时显得冗余。

### 验收要点

- blank 产物：七类空轨、零片段零路径零触发器；`meta` 无 `version` / `total_duration`；id / name / author 不符规则被拒。
- camera_intro 默认：相机一片段 0~3s；遮幅同起同长仅比例与透明度；黑场 0~1s 透明度 1→0；比例或黑场时长填 0 时对应轨不生成。
- 黑场时长 > 相机时长被拒（`T_PARAM_CROSS`）。
- follow_black：相机相对基准、原点为选择器且不冻结，位置三轴为基准轴常量，朝向 / 注视同一选择器；结束黑场 0→1 淡入。
- 选 biome 触发器：条目只有类型与群系条件，无 target、规则、绑定；空群系被拒。
- 三个产物均无转场字段；过既有校验器；撤销后回到空文档。
- 未在本轮验证项：跟随在游戏内是否贴住目标实体、黑场 / 遮幅实际时序观感；证据缺失原因：仅有字段形态与端点时间静态证据。
