## 一、摘要

本轮把「一个脚本的编辑工作台」定下来：删掉旧最左 JSON 常驻列与脚本列表导航，把界面重排为**文档顶栏 / 左上片段效果控件 / 中央真实游戏预览 / 右侧快捷属性 / 下部主时间轴 / 按需资源模板抽屉**——这是**默认布局，不是唯一布局**：这些区域和区域内的面板都必须能拖动换位、缩放、停靠成标签组、隐藏与恢复，并可保存/切换布局预设。

0.3.6 的对象模型（片段 → 完整对象叶子路径 → 该属性自己的关键帧）仍是唯一数据模型，但**属性与节点只在效果控件中出现**：主时间轴只编排轨道与片段，不展开对象行、不画属性节点、曲线或关键帧汇总点；`clip.effects` 统一承载当前片段的全部适用组/叶子/节点，`selection.properties` 承载当前选中项的常用参数，两者可同时停靠，不会因为选中某个属性就切成单属性独占页。片段效果控件与快捷属性的**内容本体**由 06 实现，本轮只交付双宿主、选区身份、打开/关闭/空态/错误边界、焦点与停靠契约。

脚本关系图是**独立顶层入口**，不在文档里开 tab。应用级能力（深色/浅色/跟随系统主题、布局与停靠、偏好/窗口/草稿恢复）与上述工作区同时交付，见 05.20–05.23。所有写入都走 02 的文档命令，本轮不自己发明第二套事务。

**参考源码怎么用**：工作台、停靠、主题、偏好、窗口和焦点任务同读[Olive/LosslessCut工作台适配](../references/03-workspace-preferences-host.md)；按实际类/函数和人工操作检查落实05.20–23，不把Qt停靠库当作现成Vue/AUI能力，不采用参考软件的宽权限renderer或常驻素材树。系统主题跟随仍须真实实现。

## 二、为什么做

### 2.1 问题

- 旧布局三栏挤在一起：`EDITOR:src/App.vue`（319–393 模板）同时放最左 `ScriptDock`（331–332）、左面板 `ScriptList`（349）、预览、右面板四 tab（367–378）和时间轴（383–384）。脚本列表与 JSON 源码各占一列，预览被压到最窄，正好与「中央预览是主画面」相反。
- 旧时间轴的模型是错的：`EDITOR:src/components/Timeline.vue` 用 `clip.keyframes` 平铺渲染（模板 732–774），选择用 `{track, clip, keyframe}` 数组下标（`EDITOR:src/store.ts:38–90`），而 0.3.6 每个对象叶子路径各有自己的 `keyframes`（`MOD:docs/SCRIPT_FORMAT.md:106–117`），同时间可以有多条不同属性的节点。下标选择在插入/删除/排序后会指错对象。
- 旧时间轴的时长是伪造的：`Timeline.vue:130` 用 `totalDuration * 1.5 + 5` 造画布，`recalcDuration`（`EDITOR:src/operations.ts:610`）把 `total_duration` 写回脚本（`store.ts:142–150`），而新格式**没有** `timeline.total_duration`（`MOD:docs/SCRIPT_FORMAT.md:14–19`、`J:script/ScriptParser.java — timelineKeys（83–89）`）。无限片段也没有可显示的有限末端规则。
- 没有容器：曲线/路径、行为、资源、诊断、模板在旧代码里没有归属。模板塞在左面板第三 tab（`App.vue:29–33` + `PresetsPanel.vue`），诊断只有一个顶部横幅（`App.vue:323–327`），资源字段散落在 `fields/ResourceStringField.vue`。
- 选区契约不存在：`state.rightTab` 写死四个值（`store.ts:78`），面板之间靠 `selectKeyframe` 顺手改 tab（`store.ts:674–687`）。06 要做片段效果控件与快捷属性时没有可消费的稳定身份。
- 工作台能力缺失：`App.vue:23–26` 只有四列固定尺寸，`initSizes()`（50–67）按窗口比例一次性分配，`startDrag`（68–89）只拖四条分隔线；没有面板换位、停靠、标签组、布局预设，也没有主题切换与偏好存储。用户要求的是「正常桌面应用」级别的可调工作台，不是固定几列。

### 2.2 目标

1. 打开文档后，默认布局是顶栏、左上效果控件、中央预览、右侧快捷属性、下部主时间轴，外加按需抽屉；旧脚本列表、JSON 常驻列、`ScriptList`/`ScriptDock` 导航全部退役，调用方迁移完，不留第二套入口。
2. 主时间轴只编排片段：轨道行 → 片段块；不渲染对象/属性行、不显示轴外槽、不画属性节点或关键帧汇总标记，也不提供加帧菜单与节点命中/拖动/框选。选中 100+ 属性的片段也不改变轨道高度。
3. 选择消费02唯一Selection：稳定clipKey、完整objectPath和单属性keyframeTime定位；主轴只消费片段级定位与片段命令，属性/节点定位进入效果控件。移动节点通过命令映射同步，删除后不猜选最近节点，插入/重排不丢片段身份。
4. 显示范围由片段窗口派生；无限内容显式标记，不写 `Infinity`、不伪造固定长度。
5. 关系图入口在顶栏与项目页之间切换，**不占文档 tab**；从图打开脚本进入本工作区。
6. 抽屉有 5 个面板容器：曲线/路径、行为（触发/规则/事件）、资源、诊断、模板。本轮只交付容器与面板注册协议，内容由 07/11/12 与 10 填（诊断来自 02/03）。
7. 键盘可达：所有可点目标有可见焦点与键盘等价操作；主时间轴、效果控件与快捷属性分别给出非指针操作路径（详见 `05-10-KeyboardFocus.md`）。
8. 工作台可调：五个区域与区域内的面板能拖动换位、拖动边界缩放、停靠成标签组、隐藏与重新打开；布局按工作流保存为预设并可恢复默认；重启后恢复尺寸/位置/可见性/选中标签（`21`/`22`）。
9. 主题完整：深色、浅色、跟随系统三模式，覆盖面板、弹层、主时间轴/效果控件的图表、表单、图与标题栏；主题与脚本/游戏画面完全分离（`20`）。
10. 应用级常规功能：文件/编辑/视图/帮助命令面、最近项目、连接/离线状态、可查快捷键、中英文切换、确认式未保存退出、局部错误与恢复入口；Electron 窗口最小化/最大化/还原/关闭与窗口位置恢复；偏好/布局单独持久化，损坏可恢复默认；未保存草稿可恢复且不覆盖模组脚本（`23`）。
11. 上述 8–10 与 1–7 在同一轮验收；不得把主题、组件移动、布局恢复、窗口状态或草稿恢复降为「后续建议」。

### 2.3 非目标

- 不做媒体剪辑：没有素材箱、转码、成片导出、时间重映射（Z README §2.3 已定）。
- 不实现 06 的效果控件行/节点本体、属性表单与快捷属性内容，不实现 07 的路径与曲线编辑，不实现 11 的规则语义，不实现 12 的模板引擎与字幕批次。
- 不改主模组协议、不改运行时字段、不新增 `script.save` 之外的写入通道。
- 不做多文档标签页（属 `shared/editor-recommendations.md` 的建议项，不计入本轮必做）。
- 不保留旧格式兼容层：旧 `meta.version` / `timeline.total_duration` / 片段级 `keyframes` 的读取与写入随 02 迁移一次完成，本轮不写任何「旧格式也能开」的分支。
- 不做浏览器内独立运行版；文件选择、窗口控制与凭据通道按宿主裁剪（见 `23`），但 WebUI 连主模组 Forge/Fabric 的功能完整，不因游戏内 Fabric AUI 暂缓而缩减。

## 三、方案

### 3.1 用起来是什么样

**进入**：从项目关系图（04）点脚本 → 进入文档工作区。顶栏左侧是「← 项目」，中间是当前文档名 + 脏标记，右侧是保存/校验/预览源状态。没有脚本列表。首次启动进入默认布局；之后恢复上次布局与主题。

**看画面**：中央是游戏真实画面（03 的端口）。预览上方一行是播放控制与飞控入口（12 负责飞控语义，本轮只放按钮位与状态位）。预览下方没有任何「素材/滤镜缩略图」假画面。

**排时间**：下部是主时间轴，默认占窗口高度约 34%，可拖到 160–560px。

- 左列轨道头：类型色条、类型名、`clip.id` 或显示名、显隐/锁定/静音（AUDIO）/独奏（AUDIO）、上移下移、删除、添加片段。
- 画布：标尺 → 轨道行。每条轨道内只有片段块；主轴不展开对象行，不画属性节点、菱形或汇总点，也没有轴外槽和加帧菜单。
- 播放头贯穿标尺与轨道行；拖动标尺任意位置即拖动播放头（与游戏内/旧版一致）。
- 片段块内显示片段名与循环角标；无限片段用斜纹 + `∞` 角标，宽度到当前可视末端并标注「无限」。
- 选中片段不改变轨道高度：即使该片段有 100+ 属性，主轴仍是同样的一行片段块；属性与节点在效果控件中查看。

**改属性**：选中片段 → 左上效果控件（`clip.effects`）列出该片段全部适用对象/功能组、静态参数与各属性的独立节点；右侧快捷属性（`selection.properties`）显示当前选中片段/组/叶子/节点的常用参数和「定位到效果控件」入口。两者可同时可见、各自停靠与缩放，共用同一 Selection 与 02 命令；选中某个属性只改变高亮与编辑目标，不会把效果控件切成单属性独占页，也不会把节点送回主时间轴。内容本体由 06 实现，本轮只交付宿主与状态合同。

**开抽屉**：资源/模板是**按需抽屉**（默认关闭；打开时默认高 280px，可调 200–420px），tab 为曲线/路径、行为、资源、诊断、模板。抽屉与主轴可同时存在；同一时刻只有一个抽屉 tab 打开。资源/模板用于按需浏览与插入，不是常驻素材栏，绝不恢复旧常驻脚本/源码栏。抽屉内容异步加载，加载中显示骨架行，不显示假数据。

**调工作台**（与上面同时可用，不是另一套界面）：

- 拖面板标题可把面板移到另一个区域、与已有面板组成标签组、或拆成新组；拖区域边界改比例；隐藏的面板从「视图 → 面板」重新打开；「视图 → 恢复默认布局」一键回到本文件描述的五区。
- 面板位置、尺寸、标签顺序、可见性、抽屉开合、效果控件与快捷属性的折叠都存进布局树（`21`），由 `22` 的拖动/停靠交互修改，`23` 负责持久化与损坏恢复。
- 布局预设按工作流保存（默认 / 镜头 / 字幕 / 行为 / 规则等），切换预设不重建文档、不丢选区、不触发脚本历史。
- 主题在「视图 → 主题」切换深色/浅色/跟随系统；切换即时生效，不重建预览流、不改脚本、不改脏标记。

**换视图**：顶栏「项目」与「文档」两个位置切换；关系图不是 tab，不参与文档的脏标记与关闭流程。

### 3.2 边界

- 主轴只编辑「片段在轨道上的位置/长度/循环」与片段级选择，不改属性值，也不显示/编辑属性节点。
- 效果控件与快捷属性宿主只消费选区、提供上下文，不自己推断「当前应该编辑谁」；节点/值内容归 06。
- 抽屉只消费选区与宿主状态，不自己推断当前文档。
- 本轮不定义任何新的脚本字段；所有可写字段必须来自 `schema.get`（01 的 C01 快照）。
- 关系图不提供轨道/片段/属性节点编辑（`shared/product-and-layout.md` §3.1）。
- 布局、主题、偏好、窗口状态、草稿是**编辑器状态**，不写入脚本、不改变游戏画面、不参与脏标记（C03/C13）。

### 3.3 宿主范围（Fabric 措辞的准确边界）

| 路径 | 状态 | 本轮要求 |

| WebUI → 主模组 Forge | 完整目标 | 全部交互、主题、停靠、偏好、窗口、草稿按本文件验收 |

### 4.2 契约

- 创建/销毁：布局服务随应用存活，面板内容随文档挂载；Selection归02文档会话，关闭会话清空。布局不因关闭文档丢失。
- 状态归属：标准文档/历史/Selection由02持有；播放真值来自03，拖动意图由05提交；布局树归21、主题归20、持久化归23。面板不能另建layoutStore或选区所有者。
- **写入**：一切修改走 02 的 `EditorCommand`（原子提交 + 撤销 + 失败回滚）。本轮提供命令的**调用点**与禁用条件，不实现命令体。
- **失败**：命令失败时选区不变、播放头不变、界面回滚到提交前快照；错误进诊断抽屉，不用 `window.alert`。
- **异步**：抽屉与两个宿主的内容按 `panelId` 懒挂载；面板加载失败只影响该面板，宿主显示错误行 + 重试，不拖垮主轴与预览。
- **布局/偏好**：布局事务与脚本撤销历史分离；切换布局/主题/预设不得清选区、不得触发脏标记、不得重建预览流；坏布局只回退布局，不重置脚本与全部偏好。

### 4.3 数据形态

Selection的唯一形状、片段键、节点移动映射和失效处理见[02-SelectionIdentity](../02-model-contracts/02-SelectionIdentity.md)。本轮不定义SelectionRef/nodeId，也不把time当不可变身份。clipKey与运行时clip.id分离，匿名片段同样在重排/跨轨/撤销后稳定；节点以属性内time定位，移动命令同步old→new，删除清空节点选择而非猜邻居。

05只产生选择/拖动意图，02在同一文档事务中修复选择，06/07/11读取同一会话。多选批量片段使用02的clipKeys；06的批量节点选区也归该会话，不能在效果控件或快捷属性宿主自持第二份选区。02未交付时明确阻塞选择交互，不用下标或可能漂移的回退充数。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 保留左栏脚本列表 + JSON 列 | 只把时间轴换新 | 预览仍被压窄；两套入口（列表/图）长期并存 | 用户明确取消常驻栏，`shared/product-and-layout.md` §2 同口径 |
| 时间轴继续按整帧关键帧渲染 | 把 `objects` 拍平成旧 `keyframes` 再画 | 无法表达同时间多属性节点；一改就丢数据 | 与 C02/C08 冲突 |
| 主时间轴按片段展开对象行/属性节点 | 片段内再展开属性组、画菱形、拖节点 | 上百行属性压垮片段编排；用户截图与合同都要求属性集中在效果控件 | 属性/节点归 `clip.effects`，主轴只留片段 |
| 选中属性就切成单属性独占面板 | 一个面板只显示当前属性 | 其他处理消失，无法上下对照；旧窄检查器限制空间 | 效果控件多组同时展开，快捷属性只是补充 |
| 选区继续用数组下标 | 少改代码 | 插入/删除/排序后指错对象；跨面板不可靠 | 下标不是身份（C04） |
| 把曲线/行为/模板做成右面板 tab | 只留一个右侧区域 | 右面板挤到 8+ tab，效果控件与快捷属性的横向空间不足 | 效果控件/快捷属性各有独立停靠身份，其他工具进抽屉 |
| 把抽屉做成模态弹窗 | 全屏浮层 | 看不到时间轴，插入位置无法对照 | 模板/诊断都需要「看着时间轴操作」 |
| 关系图作为文档 tab | 少一次跳转 | 图是跨文档的，放进文档会让脏标记/关闭语义混乱 | 图是项目级视图（04） |
| 只做固定五区 | 布局简单、测试少 | 预览/字幕/行为任务的空间需求不同；用户明确要求正常桌面应用的面板移动 | 默认五区 + 自由停靠（21/22） |
| 主题做成可选皮肤 | 少做浅色验证 | 用户明确要求深/浅/跟随系统；浅色不是「以后再说」 | 05.20 必做 |

**本方案的缺点**：

- 抽屉会进一步压缩竖向空间；1366×768 一类窗口需要「抽屉与主轴二选一」的降级（见 `05-08`）。
- 效果控件在 CAMERA 上可达上百行，折叠、虚拟化与左右行对齐必须由 06 独立完成，实现成本明显高于把节点塞回主轴。
- 双宿主意味着同一值控件要在效果控件与快捷属性两处通过同一命令联动，还要处理输入草稿互不覆盖；这是两处 UI 共用一个合同的代价。
- 稳定片段身份需要02先完成；05消费同一合同并验证撤销/重排，不以身份退化作为可接受完成状态；属性节点的移动映射由06在同一会话上消费。
- 旧组件（`ScriptDock`/`ScriptList`/`TrackListPanel`/`PresetsPanel`）退役时，`App.vue` 的快捷键与 `TitleBar` 的菜单都要重写，属于破坏性改动，需要一次性切换。
- 自由停靠比固定分区难测：需要「未知 panelId / 布局环 / 零宽 / DPI 变化 / 多屏转单屏」的恢复用例；这也是把布局模型（21）与拖动交互（22）拆开的代价。

### 6.1 本轮出口（无遗留）

本轮完成的判定不是「界面画出来了」，而是下列 15 项全部落地，且没有一项被挪到后续轮次：

1. App按唯一布局树渲染默认区域（左上效果控件 / 中央预览 / 右侧快捷属性 / 下部主轴 / 按需抽屉），旧常驻脚本/源码列与重复轨道/旧预设入口本轮删除；12后续只按冻结接口注册真实新模板，不把旧格式生成器保留到12。
2. 主轴、双宿主与抽屉消费同一clipKey/Selection；匿名片段重排稳定；主轴只到片段级，对 100+ 属性片段保持轨道高度且无任何关键帧点；属性节点选择与移动映射由06在同一会话上消费，删除不跳到别的节点。
3. 显示范围由片段窗口派生，无限内容有显式标记；不再读写 `total_duration`。
4. 双宿主 + 选区契约冻结并写进 `05-07`，06 可直接按契约实现 `clip.effects` 与 `selection.properties` 的内容。
5. 抽屉 5 个面板容器可注册、可懒挂载、可报错重试。
6. 片段编辑命令的调用点与禁用条件齐备（命令体在 02）。
7. 标尺/播放头/标记/A-B 循环/缩放交互与旧版等价或更好，且区分「脚本 A-B 循环」与「纯 UI 预览范围」。
8. 关系图入口独立，从图打开脚本的路径唯一。
9. 快捷键表集中管理，冲突在开发期报错；所有操作有键盘路径。
10. 每份任务文件的验收表都能在 WebUI 上复现（本轮出口）；游戏内（Forge 1.20.1）承载差异逐条写明，作为 14 迁移输入，不构成本轮出口。
