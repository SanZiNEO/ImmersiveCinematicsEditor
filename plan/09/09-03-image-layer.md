# 图片层

> 状态：未实现
> 范围：`layer_type=image` 的静态图片与 GIF：素材路径、素材列表、取材、几何、透明度与层级
> 关联：09-01 字段面、09-04 视频层（同一 `layer_type`）、09-07 层级

## 一、摘要

图片层是 `OVERLAY` 里唯一能把外部素材搬上屏幕的层类型（视频也走这一条，单独在 09-04 处理）。本文定义作者怎么选素材、怎么在窗口里摆位置与缩放、怎么用取材框从素材里裁一块，以及素材缺失或加载失败时编辑器该说什么、不该说什么。核心约束是：编辑器只按资源列表判断"路径是否存在"，运行时的纹理加载、GIF 帧数、解码状态它一概不知道，也不假装知道。

## 二、为什么做

### 2.1 问题

图片层的参数彼此耦合得很紧：位置是中心还是左上角、缩放相对的是素材像素还是窗口、锚点到底改变什么、取材框和缩放谁先谁后。作者凭直觉调出来的结果经常和预期差一截，而运行时的失败又是完全静默的——文件不存在、加载失败、GIF 超限，全都表现为"层不绘制，也不占位"，画面上什么都没有，作者无法区分是自己没摆对还是素材根本没加载。

### 2.2 目标

- 作者选一个素材后，能立刻知道它是否在资源列表里，并看到素材原始像素与当前生效的显示尺寸之间的关系。
- 位置、锚点、缩放、取材四个参数的作用互相独立，改动其中一个不会意外改变另一个的含义。
- 素材失败时编辑器给出的是"资源列表里没找到"这类它确实知道的事实，而不是伪造的加载状态。
- 生成的几何与运行时完全一致，作者在示意里看到的位置就是游戏里的位置。

### 2.3 非目标

- 不做素材预览渲染，不采样素材像素，不在编辑器里合成最终画面；最终画面由游戏播放呈现。
- 只写既有字段：不新增任何图片层专属键。
- 不提供"适应/填充/拉伸"这类素材适配开关：运行时没有这些字段，素材恒按元素框铺满。
- 不提供 GIF 速度、循环次数、帧范围控制：运行时没有这些脚本字段。
- 不在图片层属性面板里重复造一个基准分辨率字段。

## 三、方案

图片层的属性面板按六段排列：层类型、素材路径、位置与锚点与缩放、取材、透明度、层级。颜色、遮罩、渐变、混合、字号、文本这些对图片层不生效的字段一概不出现，也不写盘。

素材选择走既有资源列表，只列图片格式。选中后路径写进 `path`，面板显示扩展名标记与"资源列表中存在 / 未找到"。路径是 value-only，没有时钟——不能在片段内切换素材；要做素材切换就做两个片段。

几何的直觉模型是：素材先按窗口与基准分辨率算出一个基准尺寸，`scale` 把这个基准尺寸放大或缩小，`anchor` 决定缩放围绕素材框里的哪个点，`x/y` 决定这个未缩放的基准框中心落在窗口的哪个位置。因此 `anchor` 取 0.5 时绕中心缩放，取 0 时绕左上角缩放；`x/y` 取 0.5 时居中，取 0 时基准框中心在左上角（不是框的左上角贴左上角）。

取材是一个归一化的矩形，从素材里裁一块出来参与后续几何。缺省是整幅，脚本里不必写。裁切后的素材尺寸会进入基准尺寸计算，所以取材和缩放是叠加的：先裁再缩。

几何示意用 16:9 画布画出基准框、缩放后的元素框、中心点、锚点位置和取材框。它不加载素材像素，只用数值画框；数值一改示意立即更新，不引入第二个时钟。

## 四、技术细节

### 4.1 核心模型

图片层的字段面是：素材路径、位置、锚点、缩放、取材、透明度、层级。视频层共用同一套，区别只在路径扩展名（09-04）。颜色、遮罩、渐变字段即使存在于同一片段，运行时也不读。

几何计算用单一缩放系数，宽高共用，不做分别拉伸：系数取"播放区宽 / 基准宽"与"播放区高 / 基准高"中较小的一个。基准分辨率来自脚本元数据，缺省 1920×1080，宽高必须同时为正整数，缺一即脚本解析错误。基准分辨率不是图片层字段，编辑器在脚本元数据里编辑它，图片层面板只显示只读摘要，方便作者理解 `scale` 对应的实际像素。

取材矩形先被钳制到素材范围内，再算裁切宽高，因此越界不会报错而是被裁剪。裁切结果宽或高小于等于 0 时运行时不绘制。

透明度初值在运行时是 0，由播放器在层创建后补成 1；脚本字段缺省仍是 1，编辑器不需要知道这个内部细节。

### 4.2 契约

- 素材列表只列图片格式；视频不走这个列表，避免把两类素材混在一起。
- 列表返回的相对路径直接写入 `path`，不做路径改写。
- 列表里没有的文件，编辑器标"未在资源列表中找到"，不阻止保存——资源列表可能不完整，作者也可能刚把文件放进去。
- 路径为空是合法状态：层可以存在，但没有纹理，运行时不绘制、不占位。
- 清除路径只删 `path`，不自动删除片段。
- 取材框是动画字段，可以打帧做"取材窗口移动"。
- `path` 与 `z_index` 不进效果面板。

### 4.3 数据形态

`path` 是资源根目录下的相对路径，扩展名决定加载方式：静态图按图加载，GIF 按动图加载。扩展名识别按小写，路径大小写按文件系统实际。图片格式之外的后缀不由图片层处理。

GIF 有明确上限：帧数与单边尺寸都受限，超限直接拒绝，层不绘制。GIF 帧延迟按文件自身数据，仍按取材裁切、按缩放缩放。这些上限是运行时行为，脚本里没有对应字段，编辑器不提供调整入口。

几何与取材字段都是归一化比例，不是像素：位置与锚点是窗口比例，缩放是相对素材像素的倍数，取材是素材比例。归一化坐标不钳制，越界元素按公式落到窗口外。

### 4.4 边界

写盘前拦截：路径非空但扩展名不在允许集合内；几何或取材字段非有限数；取材宽高为负；透明度超出 0–1；层级非整数；层类型不是 image 却存在图片层字段（由 09-01 清理）。

只提示不拦截：取材框超出素材范围（显示运行时钳制后的有效取材）；缩放小于等于 0（运行时该层不绘制）；路径不在资源列表里。

明确不做：不判断 ffmpeg、解码、GIF 帧数等运行状态；不显示假的加载成功；不因为路径缺失就删除片段或自动换素材。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 加素材适配模式 | 提供适应/填充/拉伸三选一 | 脚本没有这个字段，只能写进编辑器私有状态 | 会造出预览与游戏不一致的假象；现有字段已能表达全部布局 |
| 缩放相对窗口 | `scale` 表示占窗口宽高的比例 | 与运行时语义不符，同一脚本在不同窗口尺寸下含义漂移 | 相对素材像素更稳定，也与运行时公式一致 |
| 在图片面板放基准分辨率 | 让作者在片段里改基准分辨率 | 基准分辨率是脚本级元数据，写在片段里会造成多个真值 | 元数据只有一处，片段面板只显示只读摘要 |
| 显示素材缩略图 | 加载素材画预览 | 需要本地解码路径，等于把运行时搬进编辑器 | 与"编辑器不做画面处理"的边界冲突 |

**本方案的缺点**：

- 位置以基准框中心表达、锚点以缩放不动点表达，两个概念叠加后需要作者实际调几次才能形成直觉。
- 编辑器无法告诉作者"素材其实加载失败"，只能告诉"资源列表里没有"；列表不全时这个提示会误报。
- GIF 只在游戏里动，编辑器无法预览播放，作者要确认循环与节奏必须进游戏。

### 验收要点

- 选中静态图与 GIF 各一次：路径写入正确、扩展名标记正确、资源存在性提示正确。
- 空路径与不存在的路径：层保留、游戏不绘制、不占位，编辑器显示未选择素材或未找到。
- 位置取 0.5 居中、取 0 落在左上、取 1 落在右下，越界不自动夹。
- 锚点取 0.5 绕中心缩放、取 0 绕左上、取 1 绕右下，示意与实际一致。
- 缩放取 1 时素材按原始像素显示，取 2 时加倍，取 0 或负数只给提示不绘制。
- 取材缺省时不写多余字段；给定矩形时只画裁切区；越界被钳制；负宽高被拦截。
- 基准分辨率改变时实际显示尺寸随之改变，而图片层面板不出现新的可编辑字段。
- 打帧后位置、缩放、取材、透明度进入效果面板，路径与层级不进。
- 保存重开后路径、几何关键帧、取材、透明度、层级原样保留。
