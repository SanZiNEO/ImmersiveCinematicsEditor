# 09 验收

> 状态：未实现
> 范围：字段面、五种层的编辑面、层级与多轨、便利组件、数据 round-trip、消息面、模组零改动、真游戏冒烟
> 关联：09-01 至 09-08 全部任务文档

## 一、摘要

09 的验收口径只有一条：编辑器写固定格式脚本，通过现有通道推给游戏，游戏播放出真实结果。编辑器侧的检查只能证明"字段写对了"，画面是否正确一律以游戏为准。本文列出要验什么、每项的通过条件，以及为什么有些东西本轮明确不验。

## 二、为什么做

### 2.1 问题

这一轮的全部产出都是字段与面板，很容易出现"界面看起来对、游戏里什么都不发生"的情况：层类型切换留下了死字段，校验器报错但作者没看到；透明度落进了不可见区间；取材框越界被运行时静默钳制；视频缺工具链而作者以为素材坏了。这些问题在编辑器里全都不明显，只有把脚本推给游戏播放才暴露。

反过来，如果把无法自动验证的东西（拖动手感、观感是否好看）也写进验收，验收就变成了主观判断，每次都要重新争论一遍。

### 2.2 目标

- 每一项验收都能指向一个可观察的结果：要么是面板里的字段集合，要么是游戏里的画面，要么是仓库的 diff。
- 字段面与数据形态的检查可以完全自动完成，不需要人看画面。
- 画面相关的检查集中在一段固定的冒烟脚本里，跑一遍就能覆盖五种层。
- 不通过时能定位到具体是哪个字段面或哪条规则出了问题。

### 2.3 非目标

- 不验观感：黑边厚度是否好看、渐变过渡是否自然，不在验收范围。
- 不验性能：覆盖层只有个位数层，本轮不做帧率测量。
- 不验编辑器内部的像素级预览，因为编辑器本来就不做像素合成。
- 不验跨轮次的交互细节，只验 09 自己声明的边界。

## 三、方案

验收分三块。第一块是结构与字段：文档齐全、每份一个一级标题、面板归属不重叠、只写既有字段。第二块是行为：五种层的字段面、层类型切换、透明度与取材的边界、层级与多轨规则、便利组件的原子性。第三块是真游戏冒烟：一段包含画幅、颜色层、图片、渐变遮罩层、字幕、视频的脚本，按时间点逐步确认画面。

前两块可以逐条对照检查，第三块必须真的把脚本推给游戏播放。任何一步失败，按对应的字段面定位，不接受"编辑器示意里看着对"作为通过依据。

冒烟脚本要覆盖的时序：起始阶段黑边与黑色淡入；中段图片出现、径向渐变加圆形遮罩的层叠在图片之上、字幕在最上层；随后图片结束视频接上、视频音轨随画面播放、淡入淡出层重新压暗画面；最后脚本实例结束，颜色层与画幅层渐出、图片视频字幕直接清理，画面回到无覆盖层状态。此外还要验两种失败路径：不存在的图片路径不绘制不占位；不存在的视频路径在有工具链时显示错误纹理、移除工具链后不显示不占位。以及一条结构验证：在同一轨道插入重叠片段，编辑器标出重叠区并提示后一个不成层，游戏里也确实只显示第一个。

## 四、技术细节

### 4.1 核心模型

验收的判据分三类。结构判据看仓库与文档：文件数量、标题层级、链接有效性、面板职责划分。字段判据看脚本 JSON：哪些键存在、哪些不存在、切换后是否残留、round-trip 是否稳定。画面判据看游戏：黑边位置、层叠顺序、透明度、文字内容、视频播放与失败表现。

三类判据不能互相替代。字段对了不等于画面对，画面对了也不等于没有死字段。

### 4.2 契约

消息面必须完全复用现有通道：校验用既有校验消息且文档是对象；推送用既有推送消息且脚本是字符串；定位用既有 seek；播放控制用既有播放/暂停/停止；播放状态以既有状态消息为准，不自行推断；资源列举用既有资源消息，图片、视频、语言各用对应类别。不新增消息类型、不新增消息字段、不新增本地运行时。

模组侧必须零改动：模组仓库的状态里不应出现 09 引入的 Java 修改，覆盖层相关的播放器、运行时、管理器、各层实现、颜色遮罩规格与渲染器、轨道 schema、对象校验器全部保持原样。编辑器仓库只新增 09 的文档与模块，不改 08 已定的结论。

数据侧：全部字段写在片段对象内，不扩到顶层；不写默认值填充，清除覆盖时删除空对象；未知键保留供诊断、不静默删除；保存→重开→再保存的值、关键帧、结构、未知键一致；不写版本号、总时长、选中态、轨道或合成相关键；不写视频专属键、字幕颜色键、素材适配键、画幅方向键。

构建侧：构建通过且无类型错误；新组件不全部进首屏包；颜色与尺寸走主题 token，深浅色可读；输入、下拉、按钮有标签，键盘可操作，错误不只靠颜色表达。

### 4.3 数据形态

验收用的冒烟脚本固定一份，包含一段画幅轨与五段覆盖层轨：黑色淡入淡出、静态图片、径向渐变加圆形遮罩的混合层、`@lang:` 引用字幕、视频。时间上刻意安排重叠与交接，用来同时验层级顺序与单轨单活跃片段规则。资源侧需要准备一张可辨认的静态图、一个不超限的 GIF、一个短时长含音轨且不超 4K 的视频、语言文件里增加一个测试 key，以及游戏目录下具备解码工具链。

### 4.4 边界

不验的项要写清楚，避免下一轮被当成缺口重新提起：观感类（黑边厚度、渐变自然度）、手感类（拖动、缩放交互）、编辑器内部像素预览。这些要么无法自动验证，要么本来就不属于本轮范围。

有些检查只能做到"结构上确认"：例如同一层级的顺序来源，验收能确认编辑器给出了提示且脚本里没有伪造的排序字段，但无法断言两个不同播放时刻的绘制顺序一致——那本来就不是可承诺的行为。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 以编辑器预览为准 | 在编辑器里合成画面并与预期对比 | 等于要求编辑器实现一遍渲染管线 | 与"最终画面由游戏完成"的边界直接冲突 |
| 只验字段不验画面 | 检查脚本 JSON 就判定通过 | 无法发现"字段对但游戏不读"的组合 | 09 的失败模式恰恰大量出现在画面侧 |
| 引入截图比对 | 冒烟时截图做像素差异 | 窗口尺寸、显卡、字体都会导致误判 | 假阳性成本高于收益，且需要维护基准图 |
| 把观感也写进验收 | 人工判断黑边是否好看 | 每次结论不一致，无法复现 | 主观项不该出现在验收表里 |

**本方案的缺点**：

- 真游戏冒烟依赖人工逐步确认，跑一次需要准备资源与工具链，无法在 CI 里全自动执行。
- 结构判据只能证明"没有多写字段"，不能证明"该写的都写了"，后者仍要靠画面确认。
- 冒烟脚本固定，新增层类型或字段时需要同步维护这一段脚本。

### 验收要点

**结构与字段**

- 09 目录下九份任务文档加一份总览齐全，总览里的任务链接全部有效。
- 每份文档恰好一个一级标题，且都写明目的、字段面或数据合同、编辑面、验收要点。
- 属性面板、效果面板、层级预览三处职责不重叠，同一属性不会在两处同时有值控件。
- 全部可写字段都能在 schema 里找到；没有任何界面状态、宿主状态或版本字段。

**字段面与切换**

- 三种层各选中一次，面板只出现该类型字段组，其余零命中。
- 层类型缺失时显示有效类型为 fade、不报错，首次编辑写显式值。
- 三个方向的切换各做一次：保留项与移除项符合预期，一次撤销完全回退。
- 切换后对象校验器不再报"字段不适用于层类型"。
- 动画叶子打帧后从属性面板迁到效果面板，删掉最后一帧后回流；value-only 字段在效果面板零命中。
- 未知键保留、不进界面、推送前能被校验定位。

**各层行为**

- 颜色层：纯黑淡入与闪白可用；单通道打帧时其余通道回落基色；线性与径向渐变各写自己的几何；三种遮罩形状各自只写自己的几何；非普通混合不出现强度字段；位置与缩放对该层零命中。
- 图片层：静态图与 GIF 都能选、都能标出资源存在性；空路径与不存在路径都不绘制不占位；位置、锚点、缩放在边界取值下与运行时一致；取材越界被钳制、负宽高被拦截；基准分辨率改变时实际尺寸变化而面板不新增字段。
- 视频层：视频路径仍是图片层类型，无视频专属字段；大写扩展名同样识别；缺工具链不显示不占位，坏文件显示错误纹理且几何照常作用；解码上限生效且不放大；暂停停帧、大幅倒退与前跳重开解码；音轨自动播放且无音量控件。
- 字幕层：多行分行正确、末尾空行增加高度、不自动换行；字号与缩放叠加、锚点不偏；引用命中显示译文而保存仍是引用串，未命中两级回落，双 `@` 转义为字面文本，非法 key 原样显示；空文本与低透明度都不绘制且有提示；文本在效果面板零命中。
- 画幅层：宽银幕出上下黑边、竖屏出左右黑边、同比例无黑边、比例为 0 无黑边；底图不裁切；透明度可打帧；空档立即复位不走渐出；多轨叠加有提示；同轨重叠后者不成层。

**层级与多轨**

- 不同层级的覆盖层顺序稳定；同层级按加入顺序排列且编辑器给出提示与顺序来源。
- 覆盖层层级为正时在黑边之上、为零时同层有提示、为负时被黑边盖住有提示。
- 层级预览跟随播放头、只读、不写盘、不建第二时钟，不显示相机轨道。
- 同轨片段切换时旧层移除、新层创建，层级只在新层创建时读取。

**便利组件**

- 每个预设生成一次，字段都在 schema 内，且不写视图状态、轨道、相机、过渡、调色字段。
- 渐变与遮罩预设只写自己类型的几何；媒体预设不写路径；字幕预设无颜色字体字段；画幅预设无方向裁切字段。
- 应用前差异清单四类齐全；一次应用一个提交，一次撤销完全回退；应用不删除未知键。

**数据、消息与模组**

- round-trip 后值、关键帧、结构、未知键一致；无默认值填充；无新增顶层字段。
- 全部交互复用既有消息，未新增消息类型或字段。
- 模组仓库无 09 引入的 Java 修改，覆盖层相关类保持原样。

**真游戏冒烟**

- 按固定时序播放：黑边与黑色淡入 → 图片出现 → 径向渐变加圆形遮罩叠在图片上 → 字幕在最上层 → 图片结束视频接上且音轨随画面播放 → 淡入淡出重新压暗 → 实例结束后颜色层与画幅层渐出、其余层直接清理、画面无残留。
- 不存在的图片路径不绘制不占位；不存在的视频路径在有工具链时显示错误纹理、移除工具链后不显示不占位。
- 同轨插入重叠片段后，编辑器标出重叠区并提示后者不成层，游戏里也确实只显示第一个。
- 保存重开后全部字段与关键帧原样保留，JSON 中无界面或宿主字段。
- 构建通过，模组状态无 09 引入的改动。
