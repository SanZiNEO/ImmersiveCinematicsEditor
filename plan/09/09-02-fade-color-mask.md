# fade 颜色、遮罩、渐变与混合

> 状态：未实现
> 范围：`layer_type=fade` 全屏颜色层的基色、逐通道颜色、渐变、遮罩、混合模式与透明度编辑面
> 关联：09-01 字段面与层类型、09-07 层级；08 的 crossfade 是另一件事

## 一、摘要

`fade` 是全屏颜色覆盖层，也是三种 `OVERLAY` 层里唯一带颜色语义的一种。本文定义作者怎么编辑它的基色、逐通道颜色、渐变、遮罩和混合模式，以及这些编辑如何映射到既有字段。这里的"调色"始终指覆盖层自身的颜色：它不是 `ADJUST` 轨道的底图调色，没有 LUT、曲线、曝光、对比度，编辑器也不做任何像素合成。

## 二、为什么做

### 2.1 问题

`fade` 的字段数量是三种层里最多的，而且互相牵连：基色和三个颜色通道谁优先、渐变存在时基色还算不算、遮罩形状决定哪几个几何字段有意义、渐变类型决定另外几个几何字段有意义。如果面板把这些字段全部平铺出来，作者会不断制造"写了但运行时忽略"的组合——比如 `mask_shape=full` 却填了 `mask_width`，或者 `gradient.type=radial` 却给 `gradient_angle` 打了帧。

### 2.2 目标

- 作者能在同一个面板里完成从纯色到渐变、从整窗到矩形/圆形遮罩的全部颜色编辑。
- 面板只显示当前生效的字段：遮罩形状、渐变类型、纯色/渐变三种模式各自决定哪几个字段可用，其余不出现也不写盘。
- 生成的脚本能被运行时直接消费，纯色快路径与 shader 路径的区别不需要作者关心，但也不会被编辑器的错误组合破坏。

### 2.3 非目标

- 不做像素合成、不实现 shader、不预览最终画面。
- 不提供混合强度、渐变平滑度、噪点、暗角这类脚本里没有的字段。
- 不碰 `ADJUST` 轨道的调色字段，也不把 `fade` 当作调色工具介绍。
- 不创建 crossfade：片段之间的过渡属于 08，`layer_type=fade` 是覆盖层，不是转场。

## 三、方案

`fade` 的属性面板自上而下五组：基色与颜色通道、渐变定义与渐变几何、遮罩形状与遮罩几何、混合模式、透明度与层级。顺序固定，作者形成肌肉记忆后不必找。

三组互斥关系决定了面板长什么样。基色/通道与渐变互斥：有渐变时颜色由 stops 决定，基色与通道的编辑控件收起，改成一句"颜色由渐变 stops 决定"；删掉渐变就回到纯色编辑。渐变类型与渐变几何互斥：线性只看角度和中心，径向只看中心和半径。遮罩形状与遮罩几何互斥：整窗不显示任何遮罩几何，矩形显示中心和宽高，圆形显示中心和半径。

切换互斥状态时，编辑器不自动删除另一侧的既有值。从纯色切到渐变，原来的基色与通道保留作为回退值，只是不再显示；从渐变切回纯色，它们原样回来。但从遮罩形状或渐变类型切换走时，不适用的几何字段会随切换一并从 `objects` 删除，一次提交完成——因为那些字段在新形状下永远不被读取，留着只会被误认为生效。删除 `gradient` 时，全部 `gradient_*` 一并移除。

几何示意用 16:9 画布画出窗口边框、遮罩中心与范围、渐变中心与方向。它只表达几何，不加载素材、不合成颜色，界面上不出现任何"游戏画面预览"的措辞。

## 四、技术细节

### 4.1 核心模型

`fade` 只读六组字段：基色、三个颜色通道、渐变定义、渐变几何、遮罩形状与几何、混合模式，加上通用的透明度与层级。位置、锚点、缩放对它不生效，脚本写了运行时不读，09-01 已规定 fade 不显示也不写这些字段。

运行时有一条快路径：纯色 + 整窗遮罩 + 普通混合三者同时成立时，直接铺满窗口；任意一条不成立就走颜色遮罩渲染路径。这个区别对作者不可见，但解释了为什么"纯黑整窗"最便宜。

基色与颜色通道是回落关系，不是覆盖关系。三个通道各自独立，只有作者显式声明过的通道才参与采样，未声明的通道回落基色的对应分量。所以只给红通道打帧时，绿蓝仍然来自基色；这不是"整组替换"。

### 4.2 契约

- 基色只写 `color`，不写任何通道；色板与十六进制输入共用同一个值。
- 不提供 alpha 输入：透明度统一走 `opacity`，基色只表达 RGB。
- 选色不会自动创建通道关键帧，打帧是独立动作。
- 渐变定义是 value-only，没有时钟；渐变几何是动画字段，有帧就进效果面板。
- 渐变存在时，基色与通道不参与该层渲染，但脚本里可以同时存在——这个互斥只影响编辑面，不改变脚本结构。
- 遮罩只决定"颜色覆盖在窗口的哪块区域"，不改变底层画面像素，也不是抠图。
- 混合模式只有下拉，没有强度字段：脚本没有这个参数。

遮罩形状的语义：

| 形状 | 可用几何 | 含义 |
|---|---|---|
| `full` | 无 | 整窗；纯色 + 普通混合时走快路径 |
| `rect` | `mask_x`、`mask_y`、`mask_width`、`mask_height` | 中心加窗口宽高比例 |
| `circle` | `mask_x`、`mask_y`、`mask_radius` | 圆心加短边比例 |

渐变类型的语义：

| 类型 | 可用几何 | 含义 |
|---|---|---|
| `linear` | `gradient_angle`、`gradient_center_x`、`gradient_center_y` | 角度以度为单位，中心是窗口比例 |
| `radial` | `gradient_center_x`、`gradient_center_y`、`gradient_radius` | 中心是窗口比例，半径是短边比例 |

### 4.3 数据形态

基色是六位十六进制字符串，`#` 可省，大小写不限，不支持 ARGB 八位写法。

渐变定义只有两个键：类型与色标表。色标表至少两项，每项是偏移加颜色；偏移必须是有限数、落在 0–1、严格递增；颜色规则与基色相同。首尾偏移不必是 0 和 1，范围之外保持端点颜色，色标数量不设上限。定义里已有的未知键保留供 round-trip，但不出现在界面，也不参与运行时解析。

编辑色标时，新增的色标追加在末尾，偏移默认落在最后一段中间，颜色默认取当前末尾颜色；删除时至少保留两项，删中间项后重新检查严格递增。

遮罩与渐变几何都是归一化比例，不是像素：中心按窗口比例，宽高按窗口比例，圆半径与渐变半径按短边比例。中心可以落在窗口外，编辑器给提示但不自动夹值，运行时会按几何公式处理。

### 4.4 边界

写盘前拦住这些形态错误：基色非六位十六进制；通道非有限数或超出 0–1；渐变不是对象、缺类型、类型非法；色标少于两项、缺偏移或颜色、偏移越界或非严格递增、颜色非法；渐变半径小于 0；遮罩形状或混合模式不在枚举内；遮罩宽高与半径小于 0；`opacity` 超出 0–1；当前层类型不是 fade 却存在 fade 字段（由 09-01 的切换清理负责）。

宽高或半径取 0 不拦：运行时该层不绘制，这是作者的合法选择。中心超出窗口范围只给提示。

关于退场渐出，有一个容易被误写成字段的行为：脚本实例退场时，`fade` 与画幅层会叠加一段固定时长的线性渐出，图片、视频、字幕层没有这个实现，退场时直接被移除。同一轨道内的片段切换也不走这段渐出，旧层是直接移除的。这段时长是运行时内部常量，脚本里没有对应字段，编辑器不提供"渐出时长"输入。可见性判断以有效透明度为阈值，低于阈值不绘制。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 全字段平铺 | 遮罩与渐变的全部几何字段一起显示 | 大量"写了不读"的字段；作者以为填了就生效 | 形状与类型本来就是这些字段的开关 |
| 基色与通道整组替换 | 有通道就用通道，没通道用基色 | 只调一个通道时要重复填另外两个 | 逐通道回落更贴近"局部微调"的实际用法 |
| 切换形状时保留几何 | 切到整窗后保留原遮罩几何，切回来时恢复 | 脚本里长期留着不生效的字段；校验与阅读都变差 | 几何字段离开形状就没有意义 |
| 提供混合强度 | 在混合模式旁加一个强度滑杆 | 脚本没有这个字段，只能写进编辑器私有状态 | 会造出"预览与游戏不一致"的假象 |

**本方案的缺点**：

- 纯色与渐变的互斥只体现在界面，脚本里两者可以并存；作者若手工编辑 JSON 制造这种状态，界面会按渐变显示，容易困惑。
- 色标表的偏移必须严格递增，作者用拖动排序时会频繁碰到中间态非法，需要编辑器给出清晰提示。
- 几何示意只能表达框与圆，无法表达混合模式带来的实际观感，作者仍必须进游戏确认。

### 验收要点

- 纯黑整窗淡入、纯白闪烁两条最小脚本能生成，游戏表现为整屏渐入与闪白。
- 只给红通道打帧时，脚本只有该通道的关键帧，绿蓝来自基色。
- 线性与径向渐变各自只写自己那组几何，另一组零命中；删除渐变时定义与几何一并消失，一次撤销全回退。
- 色标边界：偏移落在 0.2/0.8 合法，超出 0–1 时保持端点，少于两项、非递增、ARGB 颜色被拦截。
- 矩形、圆形、整窗三种遮罩各写自己的几何；切到整窗时全部遮罩几何从 JSON 移除。
- 非普通混合模式可写，且不出现任何强度字段。
- fade 面板里位置、锚点、缩放零命中，脚本也不写这些字段。
- 保存重开后基色、通道关键帧、色标、渐变几何、遮罩几何、混合模式原样保留。
