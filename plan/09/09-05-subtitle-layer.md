# 字幕层

> 状态：未实现
> 范围：`layer_type=subtitle` 的文本、`@lang:` 引用语法、字号、位置与透明度
> 关联：09-01 字段面、09-07 层级

## 一、摘要

字幕层是 `OVERLAY` 里唯一渲染文字的层，用原版字体、固定白色，只有文本、字号、位置、锚点、缩放、透明度、层级这几个既有字段。本文定义作者怎么写字幕、怎么用 `@lang:` 引用语言文件里的译文、以及为什么字幕没有颜色、字体家族、描边和背景框——不是遗漏，是运行时根本没有这些参数。

## 二、为什么做

### 2.1 问题

字幕是最容易被按"通用文本组件"想象的层。作者会自然地去找颜色、字体、描边、背景框，而这些在脚本里一个都没有；找了半天找不到，就会以为是编辑器还没做。反过来，如果面板给出"看起来能用"的同类控件，写进去的字段运行时不读，问题只会更隐蔽。

另有两个容易踩空的行为。一是文字块尺寸由最长行与原版字体行高决定，不做自动换行，末尾多打一个换行就会多出一行高度。二是低透明度并不等于"很淡"，透明度换算成字节 alpha 后低于一个极小阈值时运行时会直接跳过绘制，画面上什么都没有。

### 2.2 目标

- 作者能一眼看出字幕只有文本与几何两类参数，不会去等一个不存在的颜色选择器。
- 多行文本的行数与文字块高度在编辑时可见，末尾空行带来的高度变化不会被当成 bug。
- `@lang:` 引用能写、能预览、能确认回退行为，且保存的始终是引用串而不是译文。
- 不可见的透明度区间有明确提示，作者不会把"什么都没画出来"当成渲染失败。

### 2.3 非目标

- 不提供颜色、字体家族、描边、阴影、背景框字段。
- 不新增字幕字段：只用文本、字号、位置、锚点、缩放、透明度、层级这几个既有键。
- 不做富文本、颜色标记、制表符、自动换行。
- 不做逐字或逐行的文本动画：文本是 value-only。
- 不把译文烘焙进 `text`。

## 三、方案

字幕层的属性面板按六段排列：层类型、文本、位置与锚点、字号与缩放、透明度、层级。素材路径、取材、颜色、遮罩、渐变、混合这些字段一概不出现。

文本区是多行输入，按换行符分行，作者写几行就是几行，编辑器不做自动换行。行数与文字块宽度（由最长行决定）随输入实时显示，方便作者预判会不会溢出窗口。文本支持 `@lang:` 前缀去查语言文件，也支持用双 `@` 转义成字面文本；除此之外一律原样渲染。

语言 key 有输入提示：从既有语言资源里列出 key，选一个就写入引用形式。预览可以在"原文"与"按回退语言解析"之间切换，切换只影响显示，不写盘——保存下来的仍然是引用串。这样同一个脚本在不同语言的客户端上会显示各自的译文。

几何上，`font_scale` 决定文字块的像素尺寸，`scale_x/y` 再乘在文字块上，两者叠加。位置是文字块中心，锚点是缩放不动点。示意只在 16:9 画布上画出文字块矩形、中心、锚点与窗口边框，不渲染真实文字像素，也不用游戏字体测量——编辑器侧的字宽行高只是近似值。

## 四、技术细节

### 4.1 核心模型

字幕层只读文本、位置、锚点、缩放、字号、透明度、层级。素材、颜色、遮罩、渐变、混合字段即使存在，运行时不读。

文字块尺寸由内容算出：宽取最长行的字体宽度，高取行数乘以字体行高；再乘字号与单一缩放系数得到最终尺寸。字号靠绘制矩阵缩放实现，不换字体，所以 `font_scale=1` 对应原版基准字号。文字颜色固定为不透明白色，实际透明度完全由 `opacity` 决定。

文本按换行符切分且保留末尾空串，因此末尾换行会真的产生一个空行并增加高度。空文本不绘制。

`text` 是 value-only：没有时钟，不进效果面板，不能在片段内切换文本。要做逐段字幕就做多个片段或多条轨道。文本解析发生在建层时，改了文本必须重新推送脚本才生效。

### 4.2 契约

`@lang:` 的解析规则：

- 以单 `@` 开头的引用在建层时查语言表；
- 以双 `@` 开头表示转义，渲染成字面的引用串，不查表；
- 其他字符串原样渲染。

key 由点分隔的若干段组成，段只允许字母数字下划线，段长与总长都有上限。非法 key 不报错，原样显示引用串。

回退链是三级：当前语言 → 英语 → 原样引用串。语言文件是资源目录下的扁平键值对象，值只接受字符串。编辑器可以列出语言文件与 key 做输入提示，但不把译文写进脚本。

低透明度有一条硬规则：`opacity` 换算成字节 alpha 后低于极小值时直接跳过绘制，避免原版字体把极低 alpha 补成不透明。换算下来，一个很窄的透明度区间实际不可见。编辑器在这个区间给提示，但不自动改值。

### 4.3 数据形态

`text` 是普通字符串，换行用换行符表达，不需要转义。引用串原样保存，包括双 `@` 转义形式。

几何字段都是归一化比例：位置是窗口比例，锚点是元素自身比例，缩放与字号是倍数。位置可以落在窗口外，运行时不钳制，超宽文字块按公式溢出，不做自动适配窗口。

### 4.4 边界

拦截：几何或字号字段非有限数；透明度超出 0–1；层级非整数；层类型不是 subtitle 却存在文本或字号字段（由 09-01 清理）。

提示不拦截：文本为空（合法，不绘制）；引用 key 非法（运行时原样显示，编辑器给强提示）；文本超长（schema 没有长度上限，不新增限制）；缩放或字号小于等于 0（不绘制）；透明度落在不可见区间（提示 alpha 过低）。

不做的事：不因为文本为空就报警，不自动把长文本折行，不自动调字号去适配窗口，不因为找不到语言 key 就改成普通文本。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 提供颜色与字体控件 | 面板加颜色选择、字体家族、描边 | 脚本没有这些字段，运行时固定白色原版字体 | 会造出永远不生效的控件，比不提供更误导 |
| 自动换行 | 按窗口宽度自动折行 | 运行时不做折行，编辑器折的行与游戏显示不一致 | 折行必须由作者用换行符控制才能保证一致 |
| 保存译文 | 预览时把解析结果写回 `text` | 脚本被锁死在一种语言；换语言客户端显示错误 | 引用串才能让同一脚本在多语言下都正确 |
| 提供文本关键帧 | 让 `text` 可以打帧做逐段字幕 | 文本是 value-only，运行时只在建层时解析一次 | 逐段字幕应当用多个片段表达 |

**本方案的缺点**：

- 编辑器无法预览真实字体渲染，示意里的字宽行高只是近似，实际排版以游戏为准。
- `@lang:` 的预览需要编辑器自己读语言文件，与运行时的解析逻辑是两套实现，可能细微不一致。
- 低透明度不可见区间的提示需要作者理解"alpha 小于阈值就跳过"，否则仍会觉得是渲染坏了。

### 验收要点

- 单行与多行文本各写一次：分行正确、行高正确、末尾空行确实增加高度、不自动换行。
- 中英混排时文字块宽度由最长行决定，短行不拉伸。
- 字号加倍时文字块与绘制字号同时放大，位置与锚点不偏；缩放在字号基础上再叠加。
- `@lang:` 命中时预览显示译文而保存仍是引用串；未命中时回落到英语再回落到引用串；双 `@` 转义显示字面文本；非法 key 原样显示并有提示。
- 空文本游戏不绘制、不占位、不报错。
- 透明度落在不可见区间时游戏不绘制，编辑器给提示且不自动改值。
- 文本在效果面板零命中，改动只能靠重新推送脚本生效。
- 保存重开后文本、换行、引用串、几何关键帧、透明度、层级原样保留。
