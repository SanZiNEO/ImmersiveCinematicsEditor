# 叠化与参数过渡模型

> 状态：未实现
> 范围：A→B 片段交界上的两类操作——画面叠化（crossfade）与相机六参数过渡（morph），以及二者共存时的执行顺序
> 关联：08-03 转场面板、08-04 lane 视图、08-08 回放检查、模组 `plans/0.3.6/D-transition` 与 `F-playback`

## 一、摘要

把"转场"重新定义成 **A→B 片段交界上的操作**，而不是某个片段的属性、也不是脚本里的独立对象。08 只处理三类交界：叠化、参数过渡、硬切。叠化靠"B 前移 + B 的不透明度从 0 到 1"表达，不新增任何字段；参数过渡靠既有的 `transition*` 一组字段表达，只影响相机六参数。两者可以在同一个交界上同时存在，运行时有明确的优先顺序。

## 二、为什么做

### 2.1 问题

"转场"这个词在编辑器里目前没有归属：它既像片段属性，又像时间轴上的东西，而模组里其实根本没有转场对象。作者能感知到的困惑是：想看两段镜头怎么过渡找不到入口；片段属性面板里那组 `transition*` 看起来像转场，实际只改相机参数不改画面；想做画面交叉淡化凭直觉去填 `transition_duration`，画面毫无变化；两段首尾相接的片段想变成"重叠并淡入"，只能手工改 `start_time` 再手工打不透明度帧，很容易漏掉其中一项；两者同时存在时无法知道回放里到底会看到哪一个。

### 2.2 目标

- 叠化能被一次操作完成：A 不动、B 前移 D 秒、两段真实重叠 D 秒、B 在重叠区从 0 淡入到 1。
- 叠化落盘只改两处且都可读：B 的落点，B 的不透明度两端帧。
- 参数过渡能按通道分别声明模式、时长、曲线，提交前能解释出窗口范围和每个通道的行为。
- 同一交界两者共存时，编辑器能说出"哪段区间 morph 优先、哪段区间叠化仍可见"。
- 结构不成立时（时长超限、片段无限、非全屏、顺序不对）在提交前拦住。

### 2.3 非目标

- 不新增 `crossfade` / `overlap` / `crossfade_duration` 之类的字段，不新增转场轨或转场数组。
- 不改运行时求值：`TransitionSpec`、`TransitionParams`、`CameraChannels`、`CameraTrackPlayer` 原样沿用。
- 不做本地渲染、不采样像素来判断过渡效果。
- 不把叠化与参数过渡合并成一种"统一转场"。

## 三、方案

### 3.1 交界是编辑对象

同一 CAMERA 轨道内，数组顺序上相邻的两个片段构成一个交界。N 个片段有 N-1 个交界，最后一个片段没有出场交界。作者选中的是"A→B 这个交界"，不是 A 或 B 单个片段。交界当前处于哪种状态由片段字段和落点推导：硬切、叠化、参数过渡、两者共存、结构不完整。结构不完整只做诊断，编辑器不猜作者想做什么、也不自动修。

### 3.2 叠化：靠落点和不透明度，不靠字段

叠化的定义只有一句话：**A 位置完全不动，B 前移到与 A 重叠 D 秒，B 在重叠区从 0 淡入到 1，A 全程保持不透明。**

- D 同时是三件事：B 的前移量、两段的重叠长度、B 淡入所用的片段内时长。
- A 的落点、时长、内容一律不裁切；B 的时长不变，只是整体前移，结束时刻也随之提前。
- 后续片段不跟着移动；B 之后可能留出空隙，这是允许的。
- 要求 `0 < D <= min(A.duration, B.duration)`，B 在数组里位于 A 之后（B 是上层），两段都有限、非片段内循环、全屏，A 的不透明度恒为 1。
- 曲线不另存字段：B 的两端帧之间怎么插值，由关键帧自身的插值决定。

叠化的画面语义是"下层不透明、上层淡入"，不是"两层同时变半透明"。如果 A 也降到 0.5，两层半透明叠在一起会漏出第三层底色，得到三种画面混在一起——所以 A 必须保持 1。这不是风格偏好，是正确性问题。重叠区外，A 正常播放到结束，B 保持不透明继续；A 结束的时刻正好是重叠结束的时刻。

### 3.3 叠化落盘与前提

落盘只有两项：B 的 `start_time`，以及 B 的 `composite.opacity` 在片段本地 0 为 0、本地 D 为 1 的两端关键帧。**不写 A 的 `transition`。**

B 在 `(0, D)` 内原有的不透明度帧在应用时替换为 0/1 两端，区间外的帧保留。A 若有帧必须恒为 1，出现非 1 帧就报错，编辑器不改写它。

硬错误：没有下一片段、A/B 不同轨或数组不相邻、B 在 A 之前、D 非有限或不为正、D 超过两段时长较小者、任一方无限或片段内循环、任一方非全屏、B 的遮罩不是 `full`。软提示两类：B 自己的参数过渡窗口伸进重叠区（回放可能先走 B 的 morph lane），以及同一交界同时存在 morph（允许，但要标出优先区间）。

移除叠化是应用的反向操作：B 落点回到 A 结束处，删掉那两端能识别为叠化帧的不透明度帧，区间外的帧保留，A 的 `transition*` 保持原样。两端帧已被作者改成别的值时，就不再认为这是叠化，移除按钮禁用而不是强行改数据。

### 3.4 参数过渡：属于出场片段

参数过渡写在**出场片段**的 `objects` 上，作用于它到下一片段的交界。只有 `transition=morph` 且片段有限时，运行时才会在交界附近打开窗口。

`transition_params` 是一个对象路径，内部按六个通道名存放 `mode / duration / curve`，**不拆成六个独立对象**。六通道名与位序固定：位置、偏航、俯仰、翻滚、视场、变焦。位序只用于运行时数组下标和诊断排序，脚本里始终是字符串键。

三个模式的行为差异是这套设计的核心：

- `cut`：不占窗口，即使写了时长也不计入窗口宽度。
- `hold`：占窗口，窗口内保持 A 侧的值，窗口结束后随片段切换为 B 侧。
- `blend`：按曲线权重在 A/B 之间混合。

窗口宽度由所有非 `cut` 通道里最长的有效时长决定，以交界为中心前后各取一半。全部 `cut` 或有效时长全为 0 等于没有窗口——此时即使 `transition=morph`，回放也是硬切。

`transition_interrupt` 决定被新过渡打断时怎么办：`blend` 以当前混合中间态作为新的 A 侧继续接，`snap` 立即完成并切到新目标。它只在 `morph` 时有意义；播放头跳转、脚本替换、宏循环折返都会复位过渡状态，不把上一轮的中间态带进新播放。

编辑器在 `cut` 下折叠通道表但不删数据：已写下的分通道声明全部保留并可审计，切回 `morph` 立刻恢复，只有显式"清除分通道声明"才删除。清除最后一个覆盖时删掉整个 `transition_params` 路径，不留空对象；`transition_curve` 清除后回到线性，不写一个显式的"线性"对象充当缺省。

### 3.5 共存：允许同时存在，但不是同时可见

同一交界允许同时有叠化和参数过渡。编辑器不强制二选一，也不自动删任何一方。

关键在于运行时先判 morph：命中 morph 窗口时只产出一条 morph lane 并直接返回，不再捕获下层 lane。所以"共存"的准确含义是**数据可以同时存在、运行时不崩、按区间分先后执行**，而不是"两种画面效果叠加"。

| 区间关系 | 回放结果 | 编辑器呈现 |
|---|---|---|
| 只有叠化 | 两条全屏 lane，A 不透明、B 淡入 | 正常叠化 |
| 只有 morph | 一条 morph lane，合成参数取进入片段 | 正常参数过渡 |
| 共存，morph 只覆盖部分重叠 | 窗口内一条 lane，窗口外仍是 A/B 两条 | 标"部分遮蔽" |
| 共存，morph 覆盖整个重叠 | 整个重叠区只有 morph lane，叠化不可见 | 标"叠化不可见" |
| morph 有效时长为 0 | 没有窗口，叠化照常两条 lane | 视为无 morph，不报遮蔽 |

解决共存只提供显式动作，每条都明确说明会改哪个字段：

- **仅保留叠化**：把 A 的 `transition` 写成 `cut`，分通道声明保留。
- **仅保留参数过渡**：只在 A 是 `morph` 时可用；把 B 移回 A 结束处、删掉两端不透明度帧，**不改** A 的 `transition`。
- **两者保留**：不写任何字段，只显示遮蔽提示。

## 四、技术细节

### 4.1 核心模型

- **交界**：由轨道内数组顺序派生，带出场片段、进入片段、交界时刻、当前效果、来源分类。编辑器对象，不进文档、不进撤销、不参与保存。
- **叠化布局与解析结果**：A/B 的起止、重叠区起止、时长；在布局之上补出 B 的不透明度两端帧、A 在重叠区起止处的不透明度、被 morph 遮蔽的区间、若干提示。识别一个已存在的叠化，就是看落点是否重叠、B 的两端帧是否是 0 和 1、A 是否恒为 1。
- **参数过渡文档与窗口**：出场片段的类型、片段级时长与曲线、逐通道覆盖、打断方式；把片段级缺省与通道覆盖合成出每通道最终的模式、时长、曲线，再由它们算出窗口起止与总宽。读取时保留未知键，写入时只写显式覆盖。

### 4.2 契约

所有派生函数都是纯函数：输入文档片段与时间，输出视图，不修改文档、不触发提交。写入分三个入口——应用叠化、移除叠化、写参数过渡——每个入口一次提交，一次撤销回退全部。

叠化应用只写 B 的落点与 B 的不透明度两端帧，绝不触碰 A 的落点、两段的时长、A 的不透明度、A 的 `transition*`。参数过渡写入只写显式覆盖，清空一个通道的最后一个键就删掉该通道键，通道对象为空时一并删掉。

校验分两级：结构级（不满足就不允许应用）和提示级（允许提交，但说明回放的视觉结果可能不是作者预期）。未知通道、未知键、非法类型不静默删除，保留原值并出诊断。

### 4.3 数据形态

参数过渡落在出场片段的 `objects` 下，共五个路径：过渡类型、时长、曲线、分通道覆盖、打断方式。分通道覆盖是单个对象，键只能是六个通道名之一；每个通道对象只允许模式、时长、曲线三个键；未知键由解析器拒绝。

片段级时长可以是 0（表示无窗口），分通道时长必须是有限正数——写 0 或负数会被拒绝，因为"某个通道不占窗口"应该用 `cut` 表达，而不是时长 0。

### 4.4 边界

交界、布局、解析结果、窗口都不写盘。叠化不使用任何 `transition*` 字段；参数过渡不产生画面层。窗口计算不采样相机状态，只用字段与落点。编辑器不改写运行时求值规则，也不为了让编辑器好实现去调整字段语义；未知数据保留优先于数据整洁。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 新增 `crossfade` 字段与专用求值 | 脚本里显式声明叠化时长与曲线 | 模组要改求值、旧脚本要迁移、两份真值 | 模组已用"落点重叠 + 不透明度"表达叠化，加字段等于造第二套真值 |
| 两层同时变半透明（互补 alpha） | A 降到 1-w，B 升到 w | 实现直觉、数学对称 | 会漏出第三层底色，得到三种画面混合，不是交叉淡化 |
| 叠化时把 A 的 `transition` 强制改成 `cut` | 保证交界"独占" | 抹掉作者已写的参数过渡声明 | 叠化与参数过渡本可共存，强制改写是丢数据 |
| 把参数过渡拆成六个独立对象 | 每通道一个 `objects` 路径 | 表格编辑更直接 | 与模组"单个 `transition_params` 对象"的合同冲突 |
| 共存时强制二选一 | 提交时自动删一方 | 面板逻辑简单 | 按区间执行本来就是运行时行为，删数据不可逆 |

**本方案的缺点**：

- 叠化没有自己的字段，"这个交界是叠化"必须靠结构推断；一旦作者手动改了两端帧或落点，叠化不再被识别，移除操作失效。这是无字段方案的固有代价。
- 共存语义对作者不直观：数据同时存在但画面不同时可见，需要面板持续解释，否则容易被当成 bug。
- 窗口以交界为中心前后各取一半，作者想"只往后延"做不到；这是运行时规则，编辑器不能改。
- 分通道覆盖的"继承"有三层（通道 → 片段级 → 内置缺省），排查"为什么这个通道是这个时长"需要逐层看。
- 结构推断依赖数组顺序而非开始时间，片段被拖动到别处时，交界归属可能与视觉直觉不符。
