# lane 视图模型

> 状态：已实现
> 范围：编辑器对"当前播放头会产出哪些 lane"的只读解释，含顺序、来源、合成参数摘要、覆盖链与调色归属
> 关联：08-05 镜头检查面板、08-02 叠化与参数过渡、模组 `LaneCompositor` / `ScriptLaneDriver` / `CameraTrackPlayer`

## 一、摘要

定义编辑期的 lane 视图：lane 是运行时每帧从活跃 CAMERA 片段算出的画面快照，不是脚本里的持久轨道。本模块只在编辑器里按片段区间、叠化重叠区和参数过渡窗口列出"当前播放头会产出哪些 lane、顺序如何、来自哪个片段、合成参数长什么样"，不计算相机状态、不采样画面、不写运行时快照。

## 二、为什么做

### 2.1 问题

多片段重叠时，作者看到的画面是"好几层叠在一起"，但没有任何界面能说明这几层是谁、谁在上面、每层的合成参数是什么。具体后果：

- 叠化两段重叠时，作者无法确认"到底是不是 A 在下、B 在上"，只能靠反复 seek 观察画面亮度变化猜。
- 参数过渡窗口内只产出一条 lane，但作者会以为"两段都在播所以应该有两层"。
- 三个片段重叠时，层级由数组顺序决定而不是开始时间，凭直觉判断经常反。
- 调色和覆盖链作用在哪一层，从画面上完全看不出来。
- 一旦有人把 lane 当成可以编辑、可以保存的东西，就会去尝试"调整 lane 顺序"，而它根本不是脚本结构。

### 2.2 目标

- 给定播放头，能列出该时刻的 lane 序列，标出顺序、上下层、来源片段、角色。
- 能区分单片段、叠化双 lane、morph 单 lane 三种形态，并在共存时按当前区间只显示其中一种。
- 每行给出合成参数摘要：静态值显示数值，有动画显示帧数，不显示"当前帧采样值"。
- 能说明调色归属哪个片段、覆盖链有哪些档位、修饰符为什么不进 lane 快照。
- 保存的 JSON 里绝不出现任何 lane 相关键。

### 2.3 非目标

- 不计算相机状态，不求值曲线，不采样画面。
- 不读运行时 `CameraLane` / `CameraLaneComposite` 快照，不调用运行时求值器。
- 不把 lane 变成可选对象、可编辑对象、可保存对象。
- 不提供"置顶/置底"按钮：层级由片段顺序决定，调整顺序走主时间轴的片段移动。
- 不模拟目标可用性：实体是否存在、点源能否解析属于运行时，编辑器只给提示。

## 三、方案

### 3.1 三种形态

**单片段**：播放头落在某个片段的区间内，该片段产出一条 lane，最下层也是最上层。

**重叠多片段**：多个片段同时活跃，各产出一条 lane，顺序完全按轨道数组顺序，不按开始时间、不按 z-index、不按不透明度。数组里靠后的片段是上层。三个片段重叠就是三条。

**叠化**：是重叠多片段的一个特例，不是独立形态。A、B 两个全屏片段各一条 lane，A 在下且不透明度恒为 1，B 在上且不透明度从本地 0 的 0 到本地 D 的 1。编辑器给上层 B 标一个"叠化"角色，让作者能认出来——但运行时没有这个角色名，它只是编辑器对"这段重叠符合叠化结构"的标注。

**morph 窗口**：前后两个片段合成一条 lane，来源标为进入的那个片段，合成参数也取进入片段。窗口内不再捕获其他下层 lane，即使还有第三个片段重叠也只有这一条。

### 3.2 判定顺序

先判 morph，再判普通活跃片段。这个顺序照抄运行时：运行时在 morph 命中时直接返回，不再往下找。

判 morph 的条件是：某片段 `transition=morph`、不是无限、有下一片段、播放头落在窗口内。从后往前找第一个满足的，后开始的优先。

没命中 morph 时，取所有"开始 ≤ 播放头 < 结束"的片段各出一条。然后在这些活跃片段里识别叠化：A 在下、B 在上、B 是 A 的数组后继、B 的开始早于 A 的结束、A 的不透明度恒为 1、B 的两端帧是 0 和 1、两段都有限且全屏、B 的遮罩是 full。全部满足才给 B 标"叠化"角色，两条 lane 都保留、不合并；重叠区结束后 B 回到普通角色。

**识别叠化不要求 A 的 `transition=cut`。** A 的 `transition=morph` 只影响它自己的窗口。同一条交界上 A 有 morph、又有叠化时，窗口内只列 morph 单 lane，窗口外仍按叠化两条 lane 列出。

### 3.3 结构不成立时怎么办

不成立就退化成普通重叠，不伪造：

- 播放头落在片段间隙：零条 lane，标记为间隙，不保留上一帧结果。
- 末尾片段是 morph 但没有下一片段：按单片段列出，提示"末尾片段不产生参数过渡 lane"，不产生空 lane。
- 叠化结构不完整（A 非 1、B 两端不是 0/1、顺序不对）：仍按普通重叠列出多条，给"叠化不成立"提示，不给任何一行标叠化角色。
- 同一交界声明了 morph 但播放头在窗口外：如果叠化有效，正常列出两条，并提示"该交界也声明了 morph"。

### 3.4 合成参数摘要

每行给五项摘要：不透明度、目标矩形、源矩形、遮罩、维度。

- 静态值直接显示数值；有动画只显示"动画 N 帧"，并给一个跳去效果面板对应行的入口。
- 不给"当前帧采样值"——那需要求值曲线，与"不采样"的边界冲突。
- 矩形和遮罩都保持归一化，不换算成像素，不计算窗口裁剪。
- 叠化行额外显示重叠区起止和 B 的两端不透明度摘要，但不显示"当前混合值"。

摘要与属性面板同源，面板不缓存第二份值。

### 3.5 顺序、覆盖链与调色

顺序只由轨道数组决定。最下层序号从 0 开始，最后一个是最上层。上层不删除下层，合成阶段逐层处理。

覆盖链在 lane 之上工作：Base 先选一个整帧六参数来源，Modifier 再按自己的优先级域作用在覆盖链输出上。**Modifier 不进入 lane 快照**，所以 lane 行里不会出现"第 N 层修饰符"。面板固定显示四个档位（外部接管、飞行取景、编辑器直控、脚本导演）并说明脚本导演是默认来源，但不显示"当前谁赢了"——那只有运行时知道。lane 行只显示"该片段是否声明了抑制修饰符"，不推断最终是否生效。

调色属于片段，随片段产出 lane。lane 行只显示调色归属哪个片段，不复制 57 个通道的值。叠化两行各归属自己的片段，不把 B 的调色算到 A 上；morph 行的归属是进入片段，出场片段在窗口内不单独成行。调色编辑仍在属性面板和效果面板，lane 页只提供定位入口。

## 四、技术细节

### 4.1 核心模型

核心是一个纯函数：输入一条 CAMERA 轨道和播放头时间，输出一组 lane 视图加若干提示。lane 视图带来源片段、角色、序号、是否最上层、区间、交界时刻、morph 窗口起止、叠化重叠区起止、合成参数摘要、调色归属片段、是否声明抑制修饰符。提示是一组带代号和文案的说明，用来表达间隙、无下一片段、叠化不成立、被 morph 遮蔽、只在运行时可用等情况。

### 4.2 契约

纯函数：不改文档、不触发提交、不进撤销栈。lane 视图的身份只在"当前播放头 + 当前修订号"下稳定，播放头一变就重建，不作为选区身份。

播放头变化只重建视图，不产生文档修订号；修订号变化才重建全部派生数据。

### 4.3 数据形态

lane 视图、提示、序号、角色、窗口区间全部是界面派生层，不进入文档，不写 `authoring`，不序列化运行时快照。保存 JSON 的 CAMERA 片段只含片段字段与 `objects`。

### 4.4 边界

- 不读运行时求值器、不读相机管理器、不读预览画面。
- 摘要只读对象路径的声明值和关键帧数量，不采样曲线。
- 共存提示只算区间重叠，不删除任何 lane 行——遮蔽是说明，不是过滤。
- 点击行只选中片段，不创建 lane 选区。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 直接展示运行时 lane 快照 | 从游戏侧拉当前帧的 lane 列表 | 完全真实 | 需要新增消息与运行时快照通道，且编辑器与游戏必须同时在线 |
| 按开始时间排序 | 谁先开始谁在下 | 直觉上"先来后到" | 运行时按注册顺序叠放，与开始时间无关，按时间排会显示错误层级 |
| 叠化显示成一条"crossfade lane" | 合并 A/B 为一行 | 行数少、易读 | 运行时确实是两条 lane，合并会隐藏 A 保持不透明这一关键事实 |
| 采样曲线显示当前不透明度 | 显示 0.43 这样的实时值 | 信息更丰富 | 需要本地求值，与"不采样、以游戏为准"的边界冲突 |
| 允许调整 lane 顺序 | 提供置顶置底按钮 | 作者可"微调" | lane 顺序是数组顺序的后果，改它必须改片段顺序；提供按钮会误导成有独立层级 |
| 让 lane 成为可保存结构 | 存一份快照便于对比 | 可复现 | 会引入第二份真值，脚本与快照必然漂移 |

**本方案的缺点**：

- 摘要只到"动画 N 帧"，作者想知道"这一帧到底多透明"必须去效果面板看曲线，中间有一次认知跳跃。
- 角色名"叠化"是编辑器造的，运行时没有这个概念；一旦作者把它当成脚本字段去找，会找不到。
- 覆盖链只列档位不列赢家，作者可能觉得"这面板什么也没告诉我"。
- 判定顺序照抄运行时意味着编辑器必须精确复刻规则；运行时规则一变，这里就要同步，属于隐性耦合。

## 六、实现结果

状态：已实现

实现落在 `src/features/camera/lanes/model.ts`：`collectLaneClips` 按轨道数组顺序建立层序（后者在上，不按开始时间排序）；`buildLaneView` 产出 lane 表（`role: single|morph|crossfade`、`top` 徽标、morph 窗口与叠化重叠区、`compositeSummary` 摘要、`COVER_CHAIN_TIERS` 覆盖链）；空态分类 `none|no-camera|gap|morph-tail|crossfade-invalid|no-active`；不产出运行时快照、不写盘。

验证：`verify-08.ts` —— 播放头 1.8s 两条 lane（A 在下、B 在上且 role=叠化、最上层徽标只在 B、重叠区 = B 起点→A 结束、opacity 摘要 0→1）；2.6s 只剩 B；3.4s 为单条 morph lane 且给出出场片段；3.8s 窗口外回到普通 lane。

| 原设计 | 实际实现 | 偏离原因 |
|---|---|---|
| 叠化在 lane 里是 A/B 两条全屏 lane 各带 role | 同左，不额外产出 crossfade lane | 与运行时一致：叠化不是 lane 类型，只是上层不透明度 |
