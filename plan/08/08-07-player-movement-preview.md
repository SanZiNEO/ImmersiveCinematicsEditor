# 玩家移动预演

> 状态：已实现
> 范围：`camera.inspect` 的玩家移动 tab，只读呈现 EVENT 轨的 `Position` 目标点、折线、到达阈值与循环复位
> 关联：08-05 镜头检查面板、06-07 事件记录编辑、模组 `PlayerMoveController`

## 一、摘要

在镜头检查面板里用一页把 EVENT 轨的 `Position` 目标画出来：XZ 俯视平面上的目标点与折线、当前播放头所在的段、相对基准与绝对坐标的对照表、到达阈值和宏循环复位规则。整页只读，事件记录的编辑仍归事件面板。

## 二、为什么做

### 2.1 问题

玩家移动是一串藏在事件记录里的坐标，作者写完只能靠进游戏跑一遍才知道走成什么样：

- 事件记录里只有数字，看不出这是一条折线还是几个散点，也看不出相对坐标和绝对坐标混用时落点在哪。
- 相对坐标的基准是脚本启动时的玩家位置，不是事件触发点；作者常把它当成"从上一个目标继续走"。
- 第一个目标是起始锚点而不是传送点，从表里完全看不出来。
- 到达阈值是 0.05 格，太小，作者无法从坐标数字判断"这两个目标会不会被当成同一个"。
- 超出片段时长的记录会被运行时在编译期丢弃，编辑器里却还在，作者会以为它生效。
- 宏循环折返会把目标指针复位到第一个目标，这一点从字段上看不出来。

### 2.2 目标

- 一张 XZ 俯视图，画出所有目标点、按时间连成的折线、当前播放头所在的段。
- 一张目标表，同时给出片段局部时间、全局时间、写入坐标、预览世界坐标、相对/绝对、角色。
- 明确区分"运行时基准"和"预览原点"：前者编辑器读不到，后者只是画图用。
- 对超界记录、单目标、MOD_EVENT、编辑器预览态这些情况给出提示，不伪造目标。
- 点击目标能定位到来源片段并跳到对应时间，但不改事件记录。

### 2.3 非目标

- 不写事件记录，不改 `objects.event`。
- 不模拟碰撞、跳跃、寻路、地形：预演只画直线段。
- 不画高度：目标只有 X 和 Z。
- 不显示预计到达时间：速度、碰撞、地形都未知。
- 不把编辑器预览当成真实位移：编辑器预览态下运行时根本不驱动玩家移动。

## 三、方案

### 3.1 读取口径

只读 EVENT 类型轨道的记录，MOD_EVENT 跳过并给提示。逐片段读事件记录数组，只取带 `Position` 的记录。

目标时间等于片段开始时间加上记录内的局部时间。超出片段时长的记录在运行时编译期就被丢弃，预演同样丢弃，并显示丢弃条数。

片段循环不复制目标：目标只按片段在主时间轴上的区间出现一次，不因片段内部循环而重复。

相对坐标按"预览原点 + 偏移"换算，绝对坐标直接用写入值。所有相对目标共用同一个基准，不是各段各自的起点。

排序按全局时间升序；同一时刻按轨道数组顺序、片段数组顺序、记录下标排列，保证稳定不抖动。

第一个目标是起始锚点，其余是目标；目标数达到 2 才认为会产生移动。

### 3.2 预览原点

页面上有一个可填的原点 X/Z 和"复位到 0,0"，按文档存会话，不写盘、不进撤销。

这个原点只影响画图和表里的世界坐标显示，**不声称等于运行时基准**。运行时基准是脚本启动时捕获的玩家位置，编辑器读不到。有相对目标且作者没设原点时，用 0,0 画图并明确提示"运行时以脚本启动位置为准"。

绝对目标不依赖预览原点。切换文档清空预览原点，同一文档内切 tab 保留。

### 3.3 画布

俯视 XZ 平面，X 向右、Z 向上，坐标轴标注世界方向。视野自动取所有目标加原点的包围盒并留边距；单点或零跨度时给一个最小视野，避免退化成一条线。

首个目标画空心圆并标"锚点"，其余实心圆并标序号，按顺序连线。不画曲线、不画插值。

到达阈值在图上画成圈，但屏幕上至少保留可点击的最小尺寸，图例注明"示意放大"——它表示"这个阈值真实存在"，不表示真实比例。

播放头所在段高亮；播放头早于锚点时不高亮；晚于最后一个目标时显示"已到末目标"。

悬停显示片段名、局部时间、全局时间、相对或绝对、写入坐标、预览世界坐标。点击选中来源片段并跳到该目标的全局时间，不改事件记录。

画布不渲染地图、不读资源包、不采样画面。

### 3.4 目标表

列：序号、片段、局部时间、全局时间、模式、写入坐标、预览世界坐标、角色。

相对行显示带正负号的偏移量，绝对行显示坐标本身。数值保留三位小数，表头明确标注"预览世界坐标"，避免被误读成运行时真实落点。

少于两个目标时显示"只有锚点，不驱动移动"，不画折线。没有 EVENT 轨道或没有 Position 记录时显示空态，不伪造目标。

### 3.5 时间与循环

播放头在锚点与第二个目标之间时，画布标"首段未开始"或"进行中"，按时间判断而不是按是否已播放过。

播放头落在第 i 段区间时高亮该段。超过最后目标显示"已到末目标"，不再画移动。

宏循环存在时显示"折返复位到第一段"的提示，不模拟第二圈的位置——那需要知道折返后的实际起点，预演给不出。

### 3.6 提示

七类提示：没有 EVENT 轨道、有 EVENT 但没有 Position、只有一个目标、使用了预览原点而运行时基准未知、有记录超出片段时长被丢弃、存在 MOD_EVENT 的 Position、以及编辑器预览态下不驱动移动。

提示不阻止保存和推送——玩家移动是运行时行为，预演只是解释。按警告、信息排序，零条时显示"没有玩家移动提示"。

## 四、技术细节

### 4.1 核心模型

一个纯函数：输入文档和预览原点，输出一条路由视图，含原点来源、目标列表、段列表、起始锚点、是否会产生移动、到达阈值和提示。

目标视图带来源片段、记录下标、局部时间、全局时间、是否相对、写入坐标、预览世界坐标、角色。

### 4.2 契约

纯函数，不改文档、不发命令、不进撤销。预览原点只改会话状态，不调用文档命令。目标点击调用主时间轴的 seek 加选区命令，不写事件记录。

### 4.3 数据形态

路由视图、目标、段、提示都是派生层，不写盘。预览原点按文档键存会话，切换文档即丢弃。

### 4.4 边界

- 不读运行时的玩家移动控制器，不声称当前实际位置。
- 不写 `objects.event`；事件编辑仍在事件面板。
- 不画高度、不模拟碰撞、不给到达时间。
- 不把 MOD_EVENT 的目标算进来。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 只做目标表，不做图 | 纯表格，省一块画布 | 实现简单 | 坐标表看不出折线形状，而这正是作者最需要判断的 |
| 画在真实地图上 | 叠一层地图纹理 | 直观 | 需要资源包与坐标投影，且地图版本会变 |
| 从游戏侧拉真实玩家位置 | 显示运行时当前位置 | 完全真实 | 需要新消息通道；且预演的价值在"不连游戏也能看" |
| 模拟碰撞与寻路 | 本地跑一遍移动 | 结果接近真实 | 需要地形数据与移动规则，等于在编辑器里重建运行时 |
| 用运行时基准作为画图基准 | 直接读 `originPos` | 坐标准确 | 编辑器读不到该值；只能读到时才是真实基准 |

**本方案的缺点**：

- 相对目标的预览世界坐标以作者手填原点为基准，与实际运行时落点必然有偏差；表头再清楚也仍可能被误读。
- 不模拟碰撞，画出来的直线在实际游戏里可能走不通，预演给的是"意图"不是"结果"。
- 到达阈值只能示意放大，作者无法从图上判断两个近邻目标是否会被合并。
- 目标只有 XZ，遇到需要高度判断的场景（跳跃、上下层）完全帮不上。

## 六、实现结果

状态：已实现

实现落在 `src/features/camera/player/model.ts`：`buildPlayerRoute` 读 EVENT 轨 `objects.event` 的关键帧（`recordFrames` 读 `{keyframes:[{time,value}]}`，`value.position` 为 `{x,z}` 或 `{dx,dz}`）；`time > duration` 的记录在读取期丢弃并计数；`ARRIVE_EPSILON = 0.05`；预览原点支持「文档存值」与「编辑器本地预览原点」两种来源；产出目标表、段表、包围盒与诊断（`player.*` 九个代号）；`projectPoint` 做 XZ 归一化供画布使用。MOD_EVENT 只检测 `position` 是否存在并给提示，不解析坐标。

验证：`verify-08.ts` —— 2 个目标、全局时间 = 片段起点 + 局部时间、绝对坐标原样、相对坐标叠加预览原点、段数 = 目标数 - 1、`player.mod-event-position` 提示、无 EVENT 轨空态。

| 原设计 | 实际实现 | 偏离原因 |
|---|---|---|
| 事件记录行直接是记录数组 | 按 `{ keyframes: [...] }` 读取 | 文档模型里 `objects.*` 一律是 `{value?/keyframes?}` 包装，与解析器、模组 `EventClipRuntime` 的落盘形态一致；文档未写死行形态，以代码事实为准 |
