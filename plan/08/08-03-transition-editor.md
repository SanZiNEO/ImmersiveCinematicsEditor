# 转场面板

> 状态：已实现
> 范围：以 A→B 片段交界为编辑对象的独立面板，承载叠化、参数过渡与共存处理
> 关联：08-02 叠化与参数过渡模型、08-01 字段归属、06 属性/效果面板、04 面板宿主

## 一、摘要

新增一个独立的**转场面板**，用"A→B 交界"作为编辑对象，把叠化、参数过渡、共存处理三件事收在一处。片段属性面板不再出现任何转场组，主时间轴不画转场节点或交界手柄。面板只做编辑器操作和本地校验，落盘仍只写既有字段，推送由 08-08 负责。

## 二、为什么做

### 2.1 问题

转场在编辑器里没有归属，具体表现是：

- 片段属性面板里那组 `transition*` 字段看起来像"转场设置"，作者会以为调它就是做画面过渡，实际只影响相机六参数。
- 叠化在脚本里没有字段，作者没有地方能看到"这两个片段之间当前是什么关系"。
- 想做叠化要手工改 B 的落点、再手工打不透明度两端帧，两个动作分开做，漏一个就得到"片段跳了一下"或"画面闪了一下"。
- 叠化和参数过渡同时存在时，没有任何界面能说明回放里哪段区间是哪个效果。

### 2.2 目标

- 打开面板能按轨道列出所有相邻交界，一眼看到每个交界当前是硬切、叠化、参数过渡、共存还是结构不完整。
- 选中一个交界，能完成叠化：A 不动、B 前移 D、重叠 D、B 不透明度 0→1，一次应用一次提交，一次撤销回退。
- 选中同一个交界，能编辑六通道参数过渡，提交前能看到窗口范围与每个通道的模式。
- 共存时能显示 morph 优先区间与叠化仍可见区间，并能用三个显式动作解决。
- 面板里没有的东西：片段属性面板的转场组、时间轴上的转场节点、效果面板的转场行。

### 2.3 非目标

- 不新建页面，不新建第二个时间轴，不新增 lane 轨。
- 不新增脚本字段、不新增消息类型。
- 不做批量叠化或批量参数过渡：一次只处理当前交界。
- 不在片段右键菜单、时间轴交界热区、效果面板菜单里加"添加转场"入口。
- 不在这里做回放：推送与真实画面归 08-08。

## 三、方案

### 3.1 面板形态

面板挂在文档页右侧，与属性面板同区、按标签或上下停靠共存，可以关闭，也能用命令重新打开或聚焦。默认可见。

上半是交界列表，下半是详情；窄宽度时列表在上、详情可折叠。列表顶部有一排过滤：全部、叠化、参数过渡、共存、无效果、异常，另有一行统计"多少条 CAMERA 轨道、多少个交界、其中多少共存"。

列表每行是"A 名 → B 名"，带轨道、交界时刻、叠化时长、参数过渡有效时长、状态徽标和提示。状态徽标只用文字，不靠颜色单独表达。行只读，点击只切换面板内的选中交界，不改文档、不自动选中 A 或 B 片段。行右侧另有一个"定位"按钮，可以显式选中 A 或 B 片段——这是导航，不是编辑。

详情按交界当前状态分发：叠化显示叠化卡，参数过渡显示参数过渡卡，共存两张卡加一段共存说明，硬切显示两段首尾相接，结构异常显示原因和定位入口。详情里的输入只改草稿，点应用才提交。面板底部固定显示本地校验条数，错误能滚动定位到对应输入。

### 3.2 叠化详情

上方是一条只读的布局条：横轴用主时间轴秒，A 在上 B 在下，重叠区是实色块。A 条全程不动；B 条左端是"A 结束减去 D"，右端是 B 自己的结束。拖布局条不改落点，改时长走数字输入。B 的时长不变，所以 B 条总宽不随 D 变化，只有整体平移。

时长输入有三个状态：当前已有重叠时以"A 结束减去 B 开始"为初值；没有重叠时初值为 0 并显示占位；输入合法时实时更新布局条。`D<=0`、超过两段时长较小者、非数字都报错并禁用应用。输入框旁边直接显示上限，不自动夹值。

下方是画面预览，只显示两个片段的不透明度摘要：A 恒为 1，B 从 0 到 1。它不采样游戏画面，也不画"两层同时半透明"那种错误模型。

点"应用叠化"一次写两项——B 的落点、B 的不透明度两端帧——作为一个提交。应用后按钮变成"重新应用"，布局条标注"已应用叠化"。如果 B 的重叠区内本来有帧，应用时提示"已替换重叠区内 N 个帧，区间外保留"。如果 A 原本是 `morph`，应用**不**把它改成 `cut`，面板直接转到共存态。

移除叠化只在"确实有重叠且 B 的两端帧能被识别为叠化帧"时启用：B 回到 A 结束处，删掉那两端帧，区间外帧保留，A 的 `transition*` 原样不动。两端帧已被作者改成别的值时按钮禁用，提示手动调整或重新应用。

### 3.3 参数过渡详情

上半是片段级缺省：过渡类型开关、时长、曲线、打断方式。类型开关立即提交（因为它控制通道表折叠），其余走表草稿。

时长只接受有限非负数，空表示未声明（运行时取 0.5），0 表示无窗口。曲线默认线性，点"编辑模型"打开 07 已有的曲线编辑器，值域为过渡。打断方式二选一，在 `cut` 下隐藏但保留原值。

下半是六行通道表：通道名（不可改）、模式（继承 / blend / hold / cut）、时长（空表示继承片段缺省）、曲线（继承 / 线性 / 模型摘要）、清除按钮。行状态只有三种：三格全空是"继承"，至少一个显式键是"覆盖"，覆盖且 `cut` 时时长与曲线格禁用但显示保留值。表底在无有效窗口时提示"当前无参数过渡窗口"。

模式选"继承"时行内提示"继承（blend）"，让作者知道运行时缺省是什么。`cut` 行的时长与曲线不写；已有值先保留为禁用值，清除整行才删。时长在通道覆盖里必须是有限正数——0 不允许，因为"不占窗口"应该用 `cut` 表达。

表底"应用参数过渡"一次写四项：片段级时长、片段级曲线、六行合成的完整分通道对象、打断方式。一次应用一个提交，一次撤销。放弃更改或按 Esc 回到应用前快照。

窗口示意画两条独立区间：以交界为中心的参数过渡窗口，和叠化重叠区。共存时在重叠区上叠一层"morph 优先"阴影，只覆盖部分标"部分遮蔽"，全覆盖标"叠化不可见"。

### 3.4 共存详情

同一交界两者同时存在时，详情显示两组区间和一句话结论：窗口内是 morph 单 lane，窗口外仍可能出 A/B 两条 lane。三个显式动作的文案都直接写明"会改哪个字段"：

- **仅保留叠化**：把 A 的 `transition` 写成 `cut`，分通道声明保留。
- **仅保留参数过渡**：只在 A 是 `morph` 时可用；把 B 移回 A 结束处、删除两端不透明度帧，不改 A 的 `transition`。
- **两者保留**：不写字段，只显示提示。

`morph` 有效时长为 0 时不显示遮蔽，按"无 morph 窗口"处理，叠化照常。

### 3.5 提交与草稿

每个操作都是一次提交：应用叠化、移除叠化、应用参数过渡、切类型开关、三个共存动作。有错误时对应按钮禁用，警告不阻止。

面板关闭不丢草稿：草稿按交界身份保存；文档修订号变化时清空并重建列表。切换交界时如果有未应用草稿，提示放弃或应用，不静默丢弃。

面板不读文档 store，不缓存第二份文档；交界列表随修订号重建。面板自己的选中交界和过滤器存会话，不写选区——片段选择和转场选择是两个不同的界面层。播放头不参与交界选择，面板只显示当前播放头是否落在该交界的重叠区或窗口内，不创建第二个播放头。

## 四、技术细节

### 4.1 核心模型

面板是一个独立插件，注册为文档页的右侧面板（`transition.panel`），单例、常驻、可关闭，有文档时可用。它需要一个已有的工作台宿主作为依赖，不新增宿主类型。

交界列表由文档派生：只遍历 CAMERA 轨道，按数组顺序取相邻对，每个相邻对生成一行，最后一个片段没有出场交界。不按开始时间重排。

### 4.2 契约

面板只依赖工作台 API、08-02 的交界与过渡模块、共享界面组件；不 import 文档 store，不 import 镜头检查面板的组件。片段属性面板、效果面板、镜头检查面板都不引用本面板的组件，四处职责不重叠。

面板的所有写入都通过命令通道，一次应用一次提交。应用前跑 08-02 的结构校验，错误路径定位到具体片段字段；应用后统一走 03 的校验桥，错误会阻止保存和推送。

### 4.3 数据形态

交界、草稿、选中态、过滤器、布局条、窗口示意、遮蔽阴影全部是界面派生层，不写盘。写入的只有两类：B 的落点与不透明度帧，以及出场片段的过渡字段。

### 4.4 边界

- 不渲染像素，不采样属性曲线，只显示结构与摘要。
- 不移动片段落点以外的任何片段；不批量操作。
- 不提供"添加转场"的右键入口或时间轴热区。
- 不接管回放，不发送任何消息。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 把转场组放进片段属性面板 | 选中片段后就地编辑 | 无需新面板 | 转场是两段之间的关系，不是单片段属性；且会与 `transition*` 的语义混淆 |
| 在主时间轴上画转场节点 | 交界处放一个可拖的手柄 | 直观、所见即所得 | 需要改时间轴的几何与命中测试，且转场不是时间轴对象；与"时间轴只编排轨道/片段/标记"的边界冲突 |
| 做成独立页面 | 单独一个转场工作区 | 空间大，可放更多信息 | 转场是片段级操作，脱离时间轴上下文后作者要来回跳 |
| 叠化与参数过渡分两个面板 | 各管一件事 | 每个面板更简单 | 共存是常态，分面板会让作者在两个窗口间对照区间 |
| 自动解决共存 | 应用叠化时自动把 A 改成 `cut` | 交界永远"独占"，逻辑简单 | 抹掉作者已写的声明，且不可预期 |

**本方案的缺点**：

- 面板与属性面板同区，窄屏时两侧都要空间，标签切换会频繁。
- 转场不是时间轴对象，作者在时间轴上看到两段重叠却必须切到侧栏才能改，空间上不连续。
- 列表行承载的信息多（轨道、时刻、两种时长、状态、提示），窄宽度下必须折叠，信息密度受限。
- 草稿机制带来额外状态：关闭面板保留草稿、修订号变化清空草稿，作者可能对"我刚才填的还在不在"产生疑问。

## 六、实现结果

状态：已实现

实现落在 `src/plugins/core.transition-panel/`：插件 `core.transition-panel`、面板 `transition.panel`、槽 `document.right`、order 30、`singleton` / `keepAlive` / `closable`，`available = pageId==='document' && documentOpen`。面板内含：统计行 + 六个过滤器（全部/叠化/参数过渡/共存/无效果/异常）、交界列表（A→B、轨道、交界时刻、叠化时长、参数有效时长、状态徽标、提示、定位 A/B）、布局条（A 上 B 下、重叠实色块）、叠化卡（时长三态输入 + 上限提示、不透明度摘要、应用/重新应用、移除叠化门禁）、参数过渡卡（类型开关立即提交、时长、曲线摘要、打断、六行通道表）、共存卡（三个显式动作）、底部校验条。写入全部走 `documents.commit` / `commitBatch`，一次应用一次提交；草稿按交界 id 保存，修订号变化时清空并重建。

验证：`verify-08.ts` 的真实 store 提交段验证了应用叠化后可撤销的单批命令结果；`vue-tsc` 对该插件无报错。

| 原设计 | 实际实现 | 偏离原因 |
|---|---|---|
| 插件 ID `core.transition-panel` | 同左（README 指定；此前误用 `core.camera-transition` 已改名） | 以 README 的插件清单为准 |
| 「编辑模型」打开 07 的曲线编辑器 | 已接入 `src/features/paths/CurveEditor.vue`（`value` / `change` 受控契约）：片段级与每个通道各有一个「编辑模型」，编辑结果只改草稿，随「应用参数过渡」一次提交 | 07 交付后按其 README 的接口约定接线，无遗留占位 |
| 面板打开/聚焦走命令 | `LAYOUT_SERVICE.showPanel('document', { pluginId, panelId })` | 工作台没有专门的 focus-panel 命令入口，按布局服务既有能力实现 |
