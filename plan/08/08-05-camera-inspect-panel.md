# 镜头检查面板

> 状态：未实现
> 范围：文档级只读面板，承载 lane 列表、连续性诊断、玩家移动预演、回放检查四个 tab
> 关联：08-04 lane 视图模型、08-06 连续性诊断、08-07 玩家移动预演、08-08 回放检查、04 面板宿主

## 一、摘要

新增文档级 `camera.inspect` 面板，把四件只读的事收进一个抽屉：当前播放头的 lane 列表、连续性诊断、玩家移动预演、回放检查。面板默认挂在文档抽屉区，不复制属性值、不写脚本、不造第二个播放头。它只解释"现在会得到什么"，编辑仍然回到属性面板、效果面板和转场面板。

## 二、为什么做

### 2.1 问题

08 的其余几块各自都需要一个"解释"的位置，而它们都不能塞进属性面板或时间轴：

- lane 列表是派生视图，不是字段，放属性面板会让人以为可以编辑。
- 连续性诊断读的是脚本级播放字段和片段循环字段，横跨整份脚本，不属于任何片段。
- 玩家移动预演要画一张 XZ 平面图，属性面板的行放不下。
- 回放检查要发消息、要显示连接状态和校验结果，属于全局操作。

如果每块单开一个面板，作者要在四个面板之间来回切；如果都塞进属性面板，属性面板会变成杂物间。

### 2.2 目标

- 文档页有一个统一的"镜头检查"入口，四个 tab 覆盖 lane、连续性、玩家移动、回放。
- 面板全程只读：没有值输入、没有关键帧控件、没有保存按钮。
- 播放头跟随主时间轴，不提供第二个时间输入。
- 每个 tab 有真实数量徽标，空态说清"为什么没有内容"，不显示伪造的行。
- 面板内的定位动作只做导航：选中片段、聚焦面板、定位到效果行，都不改字段。

### 2.3 非目标

- 不新建镜头页、合成页、连续性页、转场页。
- 不提供转场编辑 tab 或"应用叠化/参数过渡"按钮——那是转场面板的事。
- 不渲染画面，不做第二块画布。
- 不缓存文档，不复制字段值。
- 不新增播放头服务，不接管 seek。

## 三、方案

### 3.1 外壳

抽屉面板，标题旁显示当前文档名和 CAMERA 轨道数；没有 CAMERA 轨道时直接写"无 CAMERA 轨道"。标题下是一排 tab，每个 tab 右侧带一个计数徽标，为 0 时不显示。顶部固定一行"跟随主时间轴：4.20s"，没有独立时间输入。

tab 选择存会话，切页或重开面板恢复上次的 tab。内容区滚动，标题与 tab 固定。窄宽度下 lane 表折叠成卡片行，不横向滚动整页。

面板默认收起，用命令打开或聚焦，不自动抢占抽屉里当前的 tab。

### 3.2 Lane tab

一行播放头时间、lane 数量、"轨道顺序：下 → 上"的说明，下面是表。

列为：序号、来源片段、角色、区间、合成摘要、调色、标记。

- 序号从 0 开始，最下层是 0。
- 角色只有三种：单片段、morph、叠化。"最上层"是层级徽标，不是角色。morph 行显示"出场 → 进入"，叠化行显示"A → B 淡入"。
- 区间是 lane 的起止；morph 显示窗口，叠化额外显示重叠区。
- 合成列是摘要，点击"属性"定位到属性面板；有动画时点击"效果"定位到效果面板对应行。没有动画就不显示"效果"入口。
- 调色列显示归属片段名，点击选中该片段。
- 标记列显示"声明抑制修饰符""只在运行时可用""动画"等，悬停给说明。

叠化的两行：A 行角色是单片段、不透明度 1；B 行角色是叠化、不透明度 0→1、调色归属 B，并额外显示重叠区起止。

点击行只选中片段，不创建 lane 选区、不把 lane 变成文档对象。

空态分四种，各自说清原因：没有 CAMERA 轨道（提示去主时间轴添加）、播放头在间隙（"当前播放头无活跃镜头片段"）、末尾片段是 morph 但无下一片段（"末尾片段不产生参数过渡 lane"）、叠化结构不完整（"当前重叠不满足叠化，按普通多 lane 显示"）。

表底固定一条覆盖链脚注：四个档位加一句"修饰符不作用 lane 快照"，不显示"当前谁赢了"。

### 3.3 其余三个 tab

**连续性**：只读解释播放关系、队列、打断、末尾保持、宏循环、片段循环和交界。详见 08-06。

**玩家移动**：只读 EVENT 轨的 `Position` 目标，画 XZ 平面、折线、目标表。详见 08-07。

**回放**：校验、推送、跳转、播放控制与状态回执。详见 08-08。它只在打开时才订阅播放状态，切走即取消订阅，但不停止播放。

### 3.4 定位与选区

所有定位的目标都是片段，不是 lane、不是字段行。"属性"按钮选中片段并聚焦属性面板，不强行展开某个组；"效果"按钮只在有动画摘要时出现，定位到具体对象路径。定位只发单选，不碰剪贴板与批选。

面板内不提供"编辑 lane""添加 lane""保存 lane 快照"。

### 3.5 命令

三个命令：打开/聚焦面板（默认落 Lane tab）、在面板中定位片段（切到 Lane tab 并选中该片段行）、打开回放检查（切到回放 tab，不自动推送）。命令都出现在命令面板，禁用时能看到原因。不注册第二个"打开 lane 面板"命令，避免多个入口指向不同状态。

## 四、技术细节

### 4.1 核心模型

面板本身几乎没有模型，它是四个只读视图的容器。真正的模型在 08-04（lane 视图）、08-06（连续性诊断）、08-07（玩家路由）、08-08（回放状态机）里，本面板只负责取数、切换、计数和定位。

### 4.2 契约

面板只依赖工作台 API、08 的模块与共享界面组件；不 import 文档 store，不 import 其他面板的组件。

播放头由主时间轴提供只读接口：读当前时间、订阅变化。这两个接口由主时间轴实现，播放头所有权、写入路径和生命周期不变；08 不新增第二个播放头服务。`seek` 仍由主时间轴或回放检查发出。

文档轨道与片段从文档 API 取只读快照，不直接读 store。修订号变化时重建四个 tab 的派生数据，不缓存跨修订号的数组。

### 4.3 数据形态

面板的 tab 选择、过滤器、预览原点等界面状态全部存会话，不写盘。lane 视图、诊断、目标、回放状态都是派生数据，不进撤销栈。

### 4.4 边界

- 面板只读：没有值输入、没有关键帧控件、没有提交按钮。
- 不渲染像素、不采样属性曲线；动画摘要只显示帧数。
- 播放头变化只重建派生视图，不产生文档修订号。
- 不提供转场编辑控件；转场只在独立面板里编辑。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 四个面板各占一个槽位 | lane、连续性、玩家移动、回放各自独立 | 每个面板职责单一 | 四个面板挤占抽屉与右侧，作者要在四个入口间切换 |
| 全部塞进属性面板 | 加四个折叠组 | 零新增面板 | 属性面板按字段派生行，塞派生视图会破坏它的模型；且属性面板要可编辑 |
| 做成独立页面 | 一个"镜头检查"工作区 | 空间充足，可多栏 | 检查是伴随动作，脱离文档上下文后要来回跳页 |
| 面板内嵌一块预览画布 | 就地渲染 lane 结果 | 所见即所得 | 需要本地渲染器，与"真实画面以游戏为准"的边界冲突，且会引入第二套渲染路径 |
| 面板提供编辑入口 | 直接改 lane 参数 | 少切一次面板 | lane 是派生数据，可编辑会让人以为它能保存 |

**本方案的缺点**：

- 四个 tab 塞进一个面板，每个 tab 的可用高度有限；lane 表在窄宽度下要折叠成卡片，信息密度下降。
- 只读面板的回答是"结构上会怎样"，不是"画面上会怎样"，作者仍必须靠回放确认。
- 播放头驱动重建，拖动时四个 tab 都可能重算；虽然有节流，但快速拖动仍有卡顿风险。
- 定位按钮只到片段粒度，不到具体字段行，作者还要自己找。
