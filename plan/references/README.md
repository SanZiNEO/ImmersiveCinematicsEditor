# 本地开源剪辑软件：源码借鉴与任务接入索引

## 一、摘要

本目录研究主模组 `example/editor` 中 Olive 与 LosslessCut 的本地源码，把可用的交互思想接入已有类级任务。交付不是一份软件推荐清单，更不是复制剪辑器：每个专题给出实际文件、类/函数、行号、解决的问题、可借鉴与不能照搬部分、既有任务落点、适配步骤及人工操作检查。

这里只增加研究依据，不增加第15轮，不改0.3.6脚本格式，不将既有必做能力降为建议。实现状态仍是未实现。

## 二、为什么做

“参考剪辑软件”不足以让执行代理知道该读哪个函数，更容易连数据模型和播放链路一起照搬。目标是把参考限定到明确职责与消费者可见行为：拖动怎样取消、一次操作怎样撤销、属性怎样保持独立、面板怎样恢复、字幕怎样从文件变成标准脚本。

非目标：运行或修改参考软件、复制GPL代码/资源、引入素材剪辑或成片导出、替换主模组渲染、为研究新增测试工程。

## 四、技术细节与优先级

### 4.1 权威顺序

1. 用户明确要求与[产品分区](../shared/product-and-layout.md)。
2. 0.3.6实际schema/parser/运行消费者与[共享合同](../shared/contracts.md)。
3. 当前轮README和类级任务的输入输出/错误/完成定义。
4. 本目录的来源思想与适配建议。

参考结论不能反向覆盖标准字段、时间单位、身份、同属性冲突策略或游戏真值。若专题与类任务矛盾，主代理先按实际源码和共享合同裁决，再形成完整任务书，不能让子代理自行二选一。

### 4.2 必须保持的分离

- 运行时标准脚本、编辑器草稿/选择/布局、字幕来源sidecar、游戏播放状态、画面帧各有所有者。
- 全局秒、属性局部秒与参考软件帧网格不同；预览60fps不量化脚本时间。
- 主时间轴只编排轨道/片段/手柄与全局视口；属性节点、对象展开与关键帧汇总标记只存在于片段效果控件（06-ClipEffectControlsPanel / 06-EffectControlsRows）。效果控件局部视口与主时间轴全局视口是两份状态，不共用可变 scale/scroll。
- 关系图位置、真实文件夹路径、meta.id和requires条目各有身份；不同操作不暗中联动。
- 曲线/字幕排版示意只是辅助。真实预览仍是游戏画面经RGBA/H264传输；进程内GPU承载只在14轮落实。
- 01–12完成WebUI，13人工打磨和全验通过后才14迁移Forge+AUI；不提前同步开发，不因Fabric+AUI问题削减WebUI→Fabric。

### 4.3 派单与验收

按[派单规约](../shared/agent-dispatch.md)一次交付目标、实际源码、写集合、输入输出、禁止项和人工检查。只附本单有关的专题段与来源函数，不在同会话中途追加需求。参考页引用的效果控件任务名是 `06-ClipEffectControlsPanel` 与 `06-EffectControlsRows`；不得回退成旧单属性面板或主时间轴对象行。全部验收按[人工使用规约](../shared/manual-acceptance.md)：每单完成正常、取消、失败、撤销/恢复与保存重开；不新增自动化测试、单测、CI或测试脚本。

## 五、为什么不选别的

| 选择 | 不采用原因 |
|---|---|
| 直接移植完整剪辑器 | 数据/时间/播放/授权边界均不同，超出固定脚本生成器范围 |
| 只给仓库名或截图 | 无法定位真实职责、事务边界及错误行为 |
| 按参考再造一套类群 | 与已有132份类/模块任务重复，破坏共享合同 |
| 为每条思想新增产品功能 | 来源不是新需求；仅支持既有任务，不以“参考也有”扩范围 |

代价是每点都要说明如何适配而不是拿来即用；好处是不会为了接近剪辑软件而改变脚本语义或引入本地假预览。
