# 10-08 · 媒体资源抽屉

> 状态：已实现
> 范围：资源抽屉的浏览与分类、搜索与类型过滤、语言页签、把文件填入当前媒体字段、引用定位
> 关联：10-01 音源字段、10-07 LUT 字段、10-09 媒体检查

## 一、摘要

把资源抽屉填起来，让作者能看到脚本可用的本地资源，并把选中的文件填进当前的媒体字段。抽屉是只读的：不上传、不删除、不改名、不写文件，也不读文件内容。它展示的是资源目录的清单，不是运行时解码结果——这一点必须在界面里守住，否则作者会把「列表里有」当成「游戏里能播」。

## 二、为什么做

### 2.1 问题

没有资源抽屉时，作者要填音频路径或 LUT 路径只能靠记忆和文件管理器。路径写错的成本很高：拼错一个目录名、用反斜杠、多写一层 `resource/` 前缀，脚本都能保存，游戏里静默失败。另一类问题是引用关系不可见：一个文件到底被哪些片段用了、哪些文件从来没被引用过，作者只能全文搜索。还有一类是语言文件，键值分散在多个 JSON 里，看某个键在各语言有没有译文只能逐个打开。

### 2.2 目标

- 能看到资源根下的文件清单，按用途分成图片、视频、音频、LUT、语言、其他。
- 能按路径子串搜索、按类型过滤，能只看未引用文件。
- 选中文件后能把相对路径填入当前聚焦的媒体字段，类型不匹配时按钮禁用并说明原因。
- 能列出某个文件被哪些片段和字段引用，点击可定位到对应片段。
- 语言文件能按语言代码与键值矩阵只读查看。
- 资源列表不完整时（请求失败、达到条数上限、目录过深）明确说明，而不是假装完整。

### 2.3 非目标

- 不上传、删除、重命名、移动资源，不写资源目录下的任何文件。
- 不读取文件大小、分辨率、时长，不生成缩略图，不播放预览。
- 不扫描文件内容，不建立资源数据库，不把资源列表写进脚本。
- 不把语言键填进媒体字段。
- 不把资源列表的加载状态当成脚本问题写进文档。

## 三、方案

抽屉有两个页签：浏览与检查（检查页签的规则在 10-09）。浏览页签顶部是刷新、搜索框与类型过滤；中间是目录面包屑，从资源根开始可逐层回退；下面是文件列表，每行显示相对路径、类型和引用数；底部是选中文件的三个动作：复制路径、填入当前字段、定位引用。

类型由扩展名计算，不依赖服务端的窄过滤：图片是 `png`/`gif`，视频是 `mp4`/`webm`/`mkv`，音频是同步解码与外部解码的完整白名单，LUT 是 `cube`，语言是 `lang/` 下的 JSON，其余归入其他。语言分类只显示 JSON 路径；要按语言矩阵查看，切到语言页签。

「填入当前字段」有一个前提：焦点必须落在媒体字段上。`OVERLAY` 图片层的 `path`、`AUDIO` 在 `source=file` 下的 `sound`、`ADJUST` 的 `lut` 是三个目标。焦点在别处时按钮禁用——选中片段不代表要改它的媒体路径。填入写的是相对路径，不带资源根前缀，写完后字段进入未保存状态，走正常保存流程。

「定位引用」扫描当前文档里已登记的媒体字段，列出引用位置；点击某条引用会选中对应片段、打开属性面板并滚到该字段，但不修改文档、不移动播放头。未被引用的文件显示「未引用」，编辑器不因此删除它。

语言页签按语言代码列与键值行只读呈现，没有新增、编辑、删除入口——译文文件由作者直接维护。

## 四、技术细节

### 4.1 核心模型

资源清单来自 `resource.list` 的一次列举，可指定类型与子目录。返回的是相对资源根的路径，统一用正斜杠。服务端有路径安全约束（拒绝绝对路径、盘符、UNC 与上跳）、深度上限与条数上限，超过深度或条数的文件不会出现在结果里——这是「没列出来」，不是「不存在」。

### 4.2 契约

- 资源根是游戏目录下的 `immersive_cinematics/resource/`。
- 列举类型为 `lang` / `image` / `audio` / `all`，空等于 `all`；可带子目录，空表示整棵树。
- 深度上限 5，条数上限 2000；达到上限后停止列举，且不返回截断标记。
- 非语言类型返回文件路径列表；语言类型返回语言代码与键值矩阵。
- 服务不返回文件大小、缩略图、总条数，也不写文件。
- 引用扫描只认已登记的字段：`OVERLAY` 图片/视频层的 `path`、`AUDIO` 在 `source=file` 下的 `sound`、`ADJUST` 的 `lut`。
- 填入字段写相对路径，不带资源根前缀，不写绝对路径。

### 4.3 数据形态

| 分类 | 扩展名 | 可填入 |
|---|---|---|
| 图片 | `png` / `gif` | `OVERLAY` 图片层 `path` |
| 视频 | `mp4` / `webm` / `mkv` | `OVERLAY` 图片层 `path` |
| 音频 | `ogg` / `wav` / `mp3` / `aac` / `flac` / `m4a` / `opus` / `wma` / `oga` / `ogx` | `AUDIO` `sound`（仅 `source=file`） |
| LUT | `cube` | `ADJUST` `lut` |
| 语言 | `lang/*.json` | 不填媒体字段 |
| 其他 | 其余 | 只读，可复制路径 |

引用列表按片段与字段路径组织，同一文件被多处引用时全部列出。

### 4.4 边界

- `source=minecraft` 的 `sound` 是注册表 ID 不是文件，不参与文件引用扫描。
- 字幕的 `@lang:` 只引用语言键，不引用文件路径，不参与媒体引用扫描。
- `OVERLAY` 的 `path` 在图片层与视频层都可能出现，不按扩展名反推层类型。
- 未登记字段里的同名路径不算媒体引用。
- 列表达到上限时，浏览仍可用，但缺失检查必须暂停（详见 10-09），不能把没列出的文件判成不存在。
- 刷新不清空搜索与过滤；刷新后若当前选中文件仍存在则保持选中，否则清空并提示。
- 抽屉的加载、失败、空目录都是界面状态，不写成文档问题。

## 五、为什么不选别的

| 备选方案 | 做法 | 代价 | 为什么没选 |
|---|---|---|---|
| 抽屉可上传与删除 | 做成完整资源管理器 | 作者少切窗口 | 越出只读边界，会让编辑器承担资源目录的写入责任 |
| 选中文件即自动填入 | 单击就改字段 | 少一次点击 | 作者浏览时会误改脚本，且难以撤销理解 |
| 用服务端的窄类型过滤做分类 | 只请求图片或音频 | 请求更小 | 视频、LUT、语言都需要全量列表后在客户端分类 |
| 列表达到上限时把未列出的文件标为缺失 | 简单直接 | 实现简单 | 会把「没列全」误报成「文件没了」，误导作者删改脚本 |

**本方案的缺点**：

- 只读意味着作者发现文件放错位置时，得离开编辑器去文件管理器处理。
- 不读文件大小与时长，作者无法在抽屉里判断素材是否合适。
- 引用定位只覆盖已登记字段，作者自定义结构里的路径不会被识别。

## 六、实现结果

状态：已实现

`MediaResourcesDrawer` 注册为 `resources` 抽屉页签，提供“浏览/检查”双页签：浏览含刷新、搜索、目录面包屑、六分类（图片 png/gif、视频 mp4/webm/mkv、音频 10 种、LUT `.cube`、其他、语言）、路径与引用计数、底部“复制路径/填入当前字段/定位引用”；语言页只读并明确“不按媒体引用统计”。`MediaResourceServicePort` 扩展 `list('audio'|'all')` 与 `queryRegistry`，`ResourceServiceImpl` 走既有 `resource.list`/`registry.query`，`WorkbenchApp` provide `RESOURCE_SERVICE`；不新增消息、不读资源文件。填入使用 `shared/resourceTarget.ts`，`OverlayMediaField` 也接入；`ColorLutField`/`AudioSourceField` 打开抽屉时填入目标。资源清单不可达/截断/未完成时显示不可用或暂停缺失检查，不把空清单当“文件不存在”。当前选中文件刷新后消失会清空选择并显示状态，空目录、类型不匹配、当前目录外路径均不伪造文件。

| 原设计 | 实际实现 | 偏离原因 |
|---|---|---|
| 只读资源抽屉 + 分类筛选 + 填入与引用定位 | 全部落地；新增“语言”入口 | 10-08 §3.1 的“语言”检查依赖语言清单；只读展示，不纳入媒体引用扫描 |
| 图片 png/gif、视频 mp4/webm/mkv、音频 10 种 | 按 10-08 表格执行 | 模组 `ResourceFileService.IMAGE_EXT` 实际还含 `jpg/jpeg`；按 09 用户裁决和 10-08 表格不把 jpg/jpeg 当本轮图片组，已在 10-09 记为口径差异 |
| 只读边界：不上传/删除/写文件/缩略图 | 抽屉只有 list/query 和复制/填字段；没有写文件命令 | 无 |
| 非资源根/截断暂停缺失检查 | 当前 `resource.list` 始终从资源根列举；截断/不可达会让检查降级为 `unverified`，不判缺失 | 以现有协议为准；没有“子目录作为根”的第二套请求 |

验证：`verify-10` 覆盖资源分类/扩展名、语言清单不可参与媒体引用、资源清单不可达降级、类型不匹配拒绝填入；`summary ok=96 fail=0`。`npm run build` 通过；`e2e/r10.spec.ts` 的 `R10-3` 在真实 Electron 中通过：资源抽屉可打开、检查页签可切换、WebUI 断连时明确显示不可用并暂停缺失检查。

**验收要点**

- 打开抽屉时默认列出资源根下的文件，面包屑从资源根开始。
- 类型过滤在图片、音频、LUT 之间切换时，列表按扩展名正确收窄。
- 搜索按路径子串匹配，清空后恢复全量。
- 焦点在 `AUDIO` 的 `sound` 且 `source=file` 时，选中音频文件可填入相对路径。
- 焦点在 `OVERLAY` 的 `path` 时选 `.cube`，填入按钮禁用并说明类型不匹配。
- 焦点不在媒体字段时填入按钮禁用，不默认改 `path`。
- 定位引用列出引用该文件的片段与字段，点击后选中片段并滚到字段，不改文档。
- `source=minecraft` 的 `sound` 与 `@lang:` 键不出现在文件引用列表。
- 请求失败时出现错误条并保留旧列表，重试成功后恢复，选中不丢。
- 返回达到条数上限时显示「可能未列全」，不把未列出文件标为缺失。
- 语言页签显示语言代码与键值矩阵，没有编辑与删除入口。
- 抽屉的搜索、过滤、选中状态不写入脚本，保存重开后文档无变化。
