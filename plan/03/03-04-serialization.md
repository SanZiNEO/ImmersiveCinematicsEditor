# 03-04 无损序列化

## 目标

定义「无损」的精确含义：保存和预览推送用同一套写出规则，作者没改的字段一个都不能丢、一个都不能被偷改。

## 无损的定义

对任意输入 JSON `R`，`serialize(load(R))` 与 `R` 必须：

1. **保留**所有运行时字段：等于 02 目录默认值的显式值、空 `keyframes: []`、`null`（`nullable_float`）、STRUCT 嵌套对象原样、事件记录原样、四类集合的数组顺序与 `id`。
2. **只允许这些差异**：对象成员顺序、数字表示（`1` 与 `1.0`）、空白。
3. **必须剥离**：`authoring`、`clipKey`、UI 视图状态（轨道可见/锁定/静音、缩放、折叠、marker）。

## 三条铁律

1. **不剥离「等于默认值」的值**。作者显式写出的 `0` 和「没写」是两种语义——运行时 `SampledClip.present` / `ClipValueView.declared` 把「声明了」和「没声明」区分开，`yaw_lock: null`（不锁）和数值（锁）就是语义差异。整体剥离会把「显式 0」和「未写」混为一谈。
2. **不写时间线总时长、不写目录外键**。目录外键运行时直接拒绝。
3. **不写编辑器派生的 `clipKey`**。它只在内存里，重开文档重新派生。

## 要做的改动

1. 保存和 `pushScript` 共用同一个 `serializeDoc(doc)`（见 03-07），**两处都不烘焙、不剥离、不裁剪**。
2. 序列化按 `objects` 的叶子逐字段写；不做整帧默认值剥离。
3. 缓动烘焙只由显式「属性段缓动」命令做，不在每次保存时暗改全部轨道。
4. 预览专用的「静音 AUDIO 轨裁剪」只发生在推送副本上，`doc` 和保存文件不受污染。

## 验收标准

- 打开 → 无修改保存 → 重载：除 `authoring` 与内部 id 外，JSON 语义逐字段不变；没有自动加目录外键或总时长。
- 只改 `yaw` 一项后保存：`position.x` 和 `fov` 不被补帧、不被删值。
- `yaw_lock: null` 保存后仍是 `null`，不被写成省略。
- STRUCT（如 `rgb_curve: {value:{points:[[0,0],[1,1]]}}`）嵌套数组原样写回。
- 静音 AUDIO 轨后保存：文件里该轨 `clips` 仍在（预览才裁）。
