# 05-14 05 闭环验收

## 目标

给 05 一个可复现的验收矩阵：图数据、文件夹、布局、移动/重命名、依赖维护、主轴几何/视图/编辑/标尺、四个面板、键盘、性能、离线断连，最后跑通“图→文档→主轴→保存→图”的闭环。每一项都写清前置、步骤、期望；不写“看起来正常”。

## 验收环境

- Windows 本地编辑器（Electron）；模组侧 WebUI 已启动并连接；`scripts` 指向一个临时测试项目。
- 测试项目结构：

```text
scripts/
  chapter/
    intro.json          meta.id=intro；CAMERA/AUDIO/ADJUST 三轨；1 个 CAMERA 片段；requires=[]
  boss/
    fight.json          meta.id=fight；requires=["intro"]
  empty/                // 空目录
  broken.json           // 非法 JSON
  dup-a.json            meta.id=dup
  dup-b.json            meta.id=dup
```

- 备份测试项目；验收可反复重置；不拿真实创作项目做破坏性用例。
- 每个用例记录：时间、版本、结果（通过/失败/跳过+原因）、截图/日志路径。

## 出口标准

05 可交付必须同时满足：

1. A1–A12、B1–B20、C1–C8、D1–D14 全部通过，或有明确“跳过+原因+风险”的记录；不允许静默跳过。
2. 图能真实打开脚本；主轴能真实编辑片段并保存；保存后图更新；不是 demo 假数据。
3. 断连、坏文件、坏布局、重复 id、路径越界、事务崩溃六类异常都有可恢复路径，不白屏、不半写、不丢用户文件。
4. 工作区只有一个图入口和一个主轴入口；固定列、固定左右页签、`window.prompt` 均不可达。
5. 双宿主只注册空态与选区摘要；不伪造字段控件。
6. 所有新增/修改的行为有对应文档段落；验收发现的问题回写到对应 05 文档，不靠口头约定。

## 验收纪律

- 用真实图数据、真实片段；不用 demo 数据冒充。
- 验收中不改代码；发现问题回写对应文档。
- 一个用例失败就记录，不宣布整轮通过。
- 能用计数/哈希/日志的都用可复现证据；不写“人工目测即可”。
