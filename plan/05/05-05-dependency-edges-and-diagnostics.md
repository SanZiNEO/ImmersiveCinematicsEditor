# 05-05 前置边与关系诊断

## 目标

定义图上「边」的精确来源、异常怎么画、以及哪些东西能改。所有判断都来自 05-01 的索引数据，图组件不自己解析脚本、不猜关系。

## 边的来源与身份

一条边 = **一个节点的某个触发器里的一条内置前置**：

```text
edge.key = `${to.path} > ${from.path} | ${triggerIdentity} | ${requirementIndex}`
edge.from = 被依赖脚本 path（上游）
edge.to   = 依赖方脚本 path（下游）
```

- 只有 `role=builtin` 且 `resolved=true` 的前置产生边：`script_played` / `script_started` / `script_completed`。
- 同一 `(to, triggerIdentity, requirementIndex)` 唯一；同一对脚本的多条前置保留多条边，不合并、不当成重复。
- 边的视觉：实线 + 箭头（指向 `to`，即依赖方）；悬停边显示「`to.name` 需要 `from.name`（`type`）」。
- 多条边在同一对节点之间时，按 `requirementIndex` 做 6px 平行偏移，避免完全重叠；不聚合成一条粗线（会丢失「有几条前置」的信息）。

## 悬空（目标缺失）

目标 `scriptId` 不存在时：

- 不产生边（画到不存在的节点上没有意义），但**画一个悬空桩**：从依赖方节点朝布局层级的上游方向伸出一段 40px 虚线 + 端点小圆 + 「缺失」标签。
- 悬空桩参与布局的层级计算：目标缺失的节点仍按「有前置」处理（层级 +1），避免节点突然跳到第 0 层。
- 悬停该触发器时，缺失条目显示「缺失」并提供「换目标 / 删除」。
- 悬空不阻断打开、不阻断保存、不自动删除条目。

## 重复 `meta.id`

- 两个脚本同 `meta.id`：先扫到的节点占用该 id；另一个节点标 `duplicate_id`。
- 指向该 id 的前置全部视为**歧义**：`resolved=false`、`editable=false`、悬停显示「重复 id」；不画实线边，画悬空桩。
- 不自动改 id、不自动挑一个当目标；由作者在编辑器页（或 05-06 的重命名）解决。

## 自引用

- 前置目标等于当前脚本自己的 `meta.id`：标 `self_reference`，不画边、画悬空桩（短虚线 + 「自引用」）。
- 不阻断保存；悬停里可删除或改成别的目标。
- 新增/改成自引用时直接拒绝（05-07），所以自引用只可能来自外部编辑或历史数据。

## 边样式（实现口径）

- **默认是近似直线**：二次贝塞尔，中点沿法向偏移 = 弦长 × `tan(2°)`，只有约 2° 的微弯。
  目的仅是让完全重合的两条边能分开，不是画成大弧线。
- **同文件夹边**：`--border-strong` 细实线（1.2px），`stroke-linecap: round`。
- **跨文件夹边**：**虚线** `stroke-dasharray: 5 4`，`--text-muted` 色、0.75 透明度，与同文件夹实线明确区分。
- **同一对节点间的多条边**：按 lane 做 6px 步进的垂直偏移，避免重叠；不靠加大弯曲来分开。
- 端点锚定：dot 模式从圆边缩进 `12px`，card 模式缩进 `28px`。
- 高亮：上游 `--c1`、下游 `--c2`、环 `--error`，宽度 2~2.2px。

## 环

- 环是**合法数据**：A 需要 B、B 需要 A 能写进脚本，只是运行时永远不满足。
- 图上：环上的边用 `--error` 颜色 + 实线，并在边的中点显示小标签「环」；**节点不再加「环」徽标**（用户要求先不做结构标注）。
- 每个环产生一条 `cycle` warning（带成员 path），不在图上画第二个「环列表面板」。
- 不自动修环、不阻止保存、不阻止打开；只做标记。
- BFS 计算上下游时必须防重复访问，避免环导致死循环。

## 可维护性分级

| 情况 | 图上显示 | 能否改 | 原因文案 |
|---|---|---|---|
| 内置前置、目标存在且 id 唯一、当前脚本有 id | 实线边 | 能（换目标/删除） | — |
| 自定义前置（如 `weather=rain`） | 不画边；悬停里列出 | 不能 | 自定义前置，只读 |
| 内置前置、目标缺失 | 悬空桩 | 能（换目标/删除） | 目标缺失 |
| 内置前置、目标 id 重复 | 悬空桩 | 不能换目标（歧义），能删除 | 目标 id 重复 |
| 自引用 | 悬空桩 | 能删除/换目标 | 自引用 |
| 当前脚本无 `meta.id` | 边照常 | 不能加前置 | 当前脚本无 id |

- 「能改」的判定只来自 05-01 的 `editable`，图组件不自己推断。
- 不允许「看起来能点但其实不写」：不可改的条目，操作按钮不渲染（不是禁用后静默失败）。

## 诊断入口

- 图顶部统计条显示 `invalidCount` 与 `warningCount`；点击展开诊断列表（图内浮层，不是独立页面）。
- 诊断列表按 `kind` 分组：`invalid` / `duplicate_id` / `dangling` / `self_reference` / `unknown_trigger` / `cycle`；每条可点击定位到节点/触发器/前置条目。
- 节点级错误（`node.error`）在节点卡片与悬停里显示；项目级 warning 在诊断列表里；两者不互相替代。
- 诊断列表只读：不提供「一键修复」；作者自己决定删/改/忽略。
- 状态区同时显示「问题：N」，与诊断列表计数一致。

## 验收标准

- A 的 `requires` 有 `["b","c"]`：两条边 B→A、C→A；`requirementIndex` 0/1；不合并。
- 同一对 A/B 由两个触发器各引一次：两条边，平行偏移可见；悬停分别显示不同触发器。
- 前置目标不存在：无实线边，有悬空桩 + 「缺失」；悬停可换目标/删除。
- 同 `meta.id` 两脚本：第二个节点 `duplicate_id`；指向该 id 的前置全部悬空、不可换目标、可删除。
- 自引用：悬空桩 + 「自引用」；可删除；改成别的目标后变实线边。
- A↔B 环：两条边用 `--error` + 「环」标签；两节点 `环` 徽标；`cycle` warning 两条成员路径正确。
- 环内选中任一节点：上下游高亮不重复、不死循环。
- 自定义前置：无实线边；悬停显示「自定义前置，只读」；没有可点的操作按钮。
- 当前脚本无 `meta.id`：所有「+ 加前置」不出现，提示「先设置脚本 id」。
- 诊断列表计数与状态区一致；点击一条 `dangling` 能定位到对应节点与前置行。
- 大图（800 节点/2000 边）：环与悬空桩渲染不拖垮画布；诊断列表仍可滚动。
- `grep 自动修复`：图组件 0 命中。

## 边界

- 图不解析脚本正文，只消费索引数据。
- 不生成第二套关系表；边是索引的投影。
- 不做「依赖健康度评分」「影响分析报告」这类分析功能。
- 环只标记不修复；缺失只提示不补。
- 诊断只读；所有修改走 05-07。
