# 13 — WebUI 完整打磨、验收与发布基线

> 状态：未实现。本轮只收口WebUI；通过本轮全部出口后，才启动14轮AUI迁移。顺序见[implementation-order](../shared/implementation-order.md)。

## 一、摘要

对01–12的WebUI真实实现完成全量格式/能力/界面/运行验证，形成稳定可用的脚本生成器和可供AUI复用的业务基线。不是边开发WebUI边验证AUI，也不以AUI接口或依赖可用为发布前提。

界面基线以[片段效果控件工作区](../shared/effect-controls-workspace.md)冻结的主时间轴、片段效果控件与快捷属性三职责为准；本轮必须按该合同实际验收，不得沿用主时间轴对象行或单属性独占页。

## 二、为什么做

面板齐全或构建成功不代表异步属性、真实预览、批量字幕和保存恢复正确。目标是用户全部点名功能在WebUI闭环，正常对接Forge/Fabric主模组。非目标：本轮实现游戏内UI、进程内GPU帧源、AUI输入或附属模组发布；这些明确归14，不视为WebUI遗留。

## 四、技术细节

前置01–12的WebUI出口全部通过。矩阵必须覆盖meta、七轨、异步value/keyframes/event、所有注册路径/数学模型、独立clips/rules/bindings/paths、触发/事实查询/规则/分支/出口、关系图文件夹/依赖维护、模板/纯数据、飞控、RGBA/H264真实画面、主题/停靠布局/恢复及SRT/VTT导入批量编译。

本轮界面验收必须按冻结合同实际完成以下场景，不能只在开头声明而保留旧步骤：

1. 主时间轴只编排轨道/片段：选中100+属性的片段时轨道高度不变，不出现属性节点、对象展开或关键帧汇总标记。
2. `clip.effects` 效果控件同时展开多个组和多个属性（如x/yaw有节点、y常量），切换选中行不隐藏其他组，左参数列与右节点列逐行对齐。
3. 效果控件共用片段局部标尺；选中属性不切走其他属性，局部seek经同一映射请求全局seek，局部与全局缩放互不重置。
4. `selection.properties` 快捷属性与效果控件可同时可见；两面板改同一目标值走同一Selection/值控件/命令并同步，快捷属性没有自己的关键帧时间轴。
5. 轴外帧在效果控件内定位、编辑、撤销并保存；主时间轴片段宽度、时长与全局视口不被拉宽或改写。
6. 小窗、停靠/换位、IME文本与数值输入、节点拖动、片段拖动、撤销与保存按真实游戏场景验证，互不抢输入。

读取实际package.json再执行真实构建/启动入口；当前只有dev/build/preview/electron:dev/electron:build，不能虚构npm test或新增测试工程。每个场景人工记录输入、操作、结果与证据，不靠mock/截图数量或源码字符串。必做失败项回原轮修复后按相同步骤复验，不缩功能、不放宽人工验收、不先禁用后补。

**本轮出口**：WebUI正常/边界/失败/保存重载/真实游戏均通过；上述六类界面场景全部通过；两种主模组加载器通路正常；发布说明准确；形成冻结标准脚本、schema消费/命令/生成语义与黄金场景供14迁移。AUI未实现不是阻塞，不要求AUI测试结果。任一新界面场景仍按旧对象行/单属性页运行，本轮即未出口。

## 五、为什么不选别的

不把AUI开发夹进WebUI验收，也不以接口设计完成替代WebUI可用。先完整打磨一个载体的代价是迁移阶段要再验证UI/输入，但业务语义与场景可复用，避免同时维护两套未稳定实现。
